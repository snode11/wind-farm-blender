# blade_recon v0.1 本机试跑报告

日期：2026-10-04（Asia/Shanghai）。输入为交付包自带的 `data/synth20`，没有重新生成或覆盖样例。

## 本轮结论

原版 Python 重建、评分、轮廓叠加和三维预览管线已跑通：三路输入均为 20 秒、200 帧、816×636、10 fps；输出包含完整的 200 帧状态，以及四个可完整解码的 200 帧视频。

这验证了交付样例的运行能力和同模型合成评分。尚未使用本平台 NREL 柔性回放视频验证，不能据此宣称真实叶片、真实翼型或缺陷几何的重建精度。

交付源文件和样例的 SHA-256 与运行前快照一致。本轮只新增 `.venv-trial/` 和当前试跑目录。

## 输入与输出检查

- 首帧已知状态对齐：C1/C3 轮廓距离中位数 0.0 px、P90 0.6 px；C2 首帧没有分割出叶片，未把空观测计为对齐通过。
- 附带相机外参与 `build_rig(back=6, down=3, pitch_down=45)` 的最大元素差为约 `1.4e-14`。由于模型包含 5° 轴倾，中路光轴相对世界水平的下俯为 40°；这与相对转轴的 45° 下俯一致。
- 输出 frame 编号连续，时间范围 `[0.0, 19.9]` 秒，state 形状为 `200×13`，observed_sections 形状为 `200×3×40`；state/std 都是有限数。
- 保存的 `nfev` 最大为 33，后续帧没有达到 60 次的迭代上限。原版未保存优化器的 success/status，因此这一项不能代替逐帧收敛验证。
- `overlay_C1.mp4`、`overlay_C2.mp4`、`overlay_C3.mp4` 均完整解码为 200 帧、816×636；`preview.mp4` 完整解码为 200 帧、960×720。
- 预览第 100 帧已肉眼检查：能显示三片叶片、绿色/橙色分区与真值边线。预览是算法自己的简化可视化。

## 方法与评分的适用范围

这版拟合 10 个量：方位角，以及每片叶片的桨距、一阶挥舞、一阶摆振。三维表面由固定近似 NREL 模板生成；弦长、翼型、扭角和模态形状没有从图像自由估计。它适合作为整体姿态和低阶变形的基线，本轮没有验证裂缝、凹坑或其他缺陷的三维恢复。

`recon.py` 不读取 `truth.json`。真值只在本轮对齐检查、评分和预览中使用。

需要保留以下口径：

1. `observed_sections` 是拟合后的轮廓自洽标签：任一路相机中两侧轮廓贴合到 3 个求解像素内，即可标记。它没有独立检查多视图深度约束、遮挡或表面面积覆盖；13.8% 是逐时刻的截面计数比例，不能称作完整表面面积覆盖率。
2. 原版网格评分比较同一模板生成的对应顶点，并对每个截面的周向顶点误差取平均；这不是独立 Blender 真值网格的双向面积加权表面距离。
3. 原版允许每帧按 120° 循环对齐叶片编号，不能用它证明长期叶片身份稳定。参数评分中的“叶片可见”只要求该片任一截面 observed。
4. `std` 是含先验的局部 Jacobian 近似，没有标定、同步、分割或模板误差的校准。二阶挥舞固定为 0、输出 std 也为 0，应视为固定假设。
5. 空掩码时程序仍可通过先验生成状态；指定的外部掩码文件缺失时会回退自动分割。使用真实数据时应单独检查分割和逐帧状态。
6. `coverage.py` 只统计一片叶片轴线点的入画比例、360 个候选方位角，不处理遮挡。这不能代替原平台实际时间线的全表面可观测性诊断。

## Blender 5.2.1 后台验证

在独立的 factory-startup 后台进程中运行原版 `blender_view.py`，没有操作已有前台 Blender 场景，也没有进行 Blender 渲染。

原版可以加载真实的 200 帧结果，并在帧 1、51、101、200 更新重建叶片、真值线框和顶点颜色；保存了独立验证 `.blend`。这属于后台对象和逐帧更新验证，未测量前台播放帧率。

发现相机导入错误：`blender_view.py:103` 将嵌套 Python 列表直接赋给 `matrix_world`。在本机 Blender 5.2.1 中，这会导致旋转转置、平移丢失；三路相机外参最大元素误差达 65.794。隔离复现中，两种写法都显式更新了 view layer，排除了未更新缓存这一原因。

使用 `mathutils.Matrix(M.tolist())` 后，外参最大元素误差约 `6.9e-6`，属于 Blender 浮点存储范围内的偏差。独立兼容脚本放在输出目录的 `blender/compat/` 中，交付源文件保持原样。兼容版已完成真实 200 帧的加载，以及帧 1、51、101、200 的网格、颜色、真值线框和相机核验；使用原版 `blender_export_cameras.py` 反导出后的外参误差也约 `6.9e-6`。

另外，原版相机导入只设置水平视角，没有还原完整 K、主点和场景分辨率。兼容版同时设置了样例的 816×636 场景输出分辨率，但保留原版 fx-only 内参近似；fy 的反导出误差约 1.261 像素。不能将查看场景的相机对象直接当作完整标定恢复。本轮没有据此改变重建输入。

保存 `.blend` 不会自动恢复此脚本的 Python `frame_change` 回调。需要按脚本方式重新加载才能继续逐帧播放，单独打开保存的 `.blend` 只能看到保存时刻的对象。
