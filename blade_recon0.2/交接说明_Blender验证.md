# Blade Recon v0.2：Blender 验证与证据合同

方法见[算法说明](docs/算法说明_三摄视频叶片三维重建_v0.2.md)，外部环境、动态输入和保存恢复见[运行与输入验证](docs/接入与正确性验证.md)。默认轮廓、冻结几何纹理融合、显式RGB辅助几何是不同功能，必须分别声明运行配置。

当前局部材料点候选独立Patch 2/8、Crack 7/8（87.5%<90%），跨相机RGB 0/264；真实同材料点三维误差和主增益为null，科学状态 `FAILED_GATE / NOT_ACCEPTED`。证据见[材料点对应实验报告](docs/材料点对应实验报告_2026-10-11.md)。显示、保存、软件回归和现场精度不能合并判断。

## 环境与已有样例

从仓库根目录使用 `python3 blade_recon0.2/run.py --check-env`；该入口调用已有外部算法环境，不安装依赖。Blender内置Python只负责显示。日常安装扩展、工作区源码、构建ZIP和独立原生文件须分别记录路径、版本和载荷身份。

打开纹理重建样例.command（本地文件：`scripts/blender/打开纹理重建样例.command`）通过日常安装扩展打开已有120帧合成纹理样例；该样例不等于内置601样本同源MAPPO纹理资源。自己的结果可由独立“叶片三维重建”面板导入，或运行：

```bash
/Applications/Blender.app/Contents/MacOS/Blender \
  --python scripts/blender/open_blade_recon_review.py -- \
  --recon outputs/my-v02-run/recon.json --texture outputs/my-v02-run/texture
```

当前安装reader对内嵌健康loft的支持范围见[纹理辅助几何合同](docs/纹理辅助几何_职责与合同.md)。健康模板候选的独立原生blend不能用解析模板reader结果替代。

## 视频、相机与时间

各路原图独立处理，不拼接后再求解。静态输入用 `cameras.json`；动态输入用 `input_bundle.json`，逐帧声明frame/t、W/H/K、MODEL系 `T_cv_from_model`、RGB和mask。相机或机舱有运动时，单时刻外参不能代替逐帧标定；`blender_export_cameras.py`只导出一个静态时刻。

记录相机布局、分辨率、曝光、画幅、输入帧率和源仿真时刻。共光心50°×40°扇形阵列与平台C1/C2/C3分区相机是不同布局；可观性和精度只能解释对应输入。三维状态共13维：方位角、逐叶桨距、一阶挥舞、一阶摆振、二阶挥舞；不可观方向须按质量信息解释，没有独立弹性扭转参数。

## 运行与可见验证

1. 核对输入身份、像素中心约定、转向、轴倾、预锥、轮毂高度、预弯及相机坐标系；已知状态叠图只用于对齐诊断，不能泄漏到拟合输入。
2. 使用新的输出目录运行重建和纹理融合，保留frame/t、观测数量、求解状态、可辨识性、未知域和源像素追溯。
3. 在确切结果的Blender窗口验证几何、纹理与时间。播放时左右源/估计对象使用同一时钟和旋转；暂停后缩放到三片叶片、继续播放，再从背面自由观察，确认用户调整的视角持续有效。
4. 保存并重开自己的blend，检查嵌入状态、packed纹理、动画和证据色；记录实际reader和模块来源。独立 `blender_view.py` 的原生动画与扩展恢复机制分别验证。
5. 将截图、源路径、结果身份、相机及时间与对应软件报告关联；原生窗口证据不能由静态源码检查替代。

绿色截面仅表示该帧轮廓支持，橙色表示推断。未知纹理使用透明度或证据色，不生成无来源缺陷。纹理有外观不等于真实同材料点位置已恢复。

## 评分与限制

评分真值由评价程序独立读取，不能进入tracker、初始化、solver或fusion。逐状态近似转换、最近表面距离、RGB边界误差和真实同材料点三维误差分开报告；未建立材料对应时三维材料误差保留null。训练、持出和锁定观察分母不能混用。

合成数据使用理想针孔、近似健康模板和声明的材质/相机，不证明真实风机几何、毫米裂纹、凹坑深度、鼓包高度或现场自动检出。原始性能与缺陷样例范围见[性能与缺陷验证](docs/性能与缺陷验收.md)。正式601样本资源未被局部材料点研究候选替换。
