## X100 雷达

公开0.3.42.6扩展、工作区源码与本机安装在独立侧栏标签 **N → X100** 提供 X100 入口（`WFRL_PT_X100` 及配置、显示、帧与数据流、记录子面板）；工作区还注册 `WFRL_PT_X100Blades` 和安装报告导入操作器。几何仿真的“原安装位置／机舱侧面”按钮通过 `runtime.apply_mount_preset()` 切换同一台传感器的安装标定，使用当前量化源时刻准备新观测；重复有效预设复用原帧，预算编辑仍在下一新样本生效；侧面位置由 `scene.nacelle_side_installation()` 按静态侧壁确定。已有会话时切换预先准备观测与 GPU 数据，成功后提交对象变换、配置与会话身份；无会话时写入安装参数后直接启动会话，由其采样首帧，失败回滚参数；必需GPU准备失败或提交失败回滚，可选分析失败独立标记不可用；复用有效的几何快照和安装对象，保留对象选择与可见性，失败保留旧观测与未应用参数。X100 支持 T1 同源只读几何采样、名义视场与点云、严格 PLY 读取、显式索引记录／回放及独立本地实时通道。规范实现位于 `wfrl/radar_x100/`，构建按清单复制到 `_vendor/radar_x100/` 并保存源码摘要；Blender 适配位于 `radar_x100/` 与 `panels/radar_x100.py`。来源身份、各流时钟与完整性独立于现有理想激光／双束净空。

工作区的 `sampling.py` 使用参考面积、随机平移Halton序列与固定重心坐标生成材料点，算法身份为 `shifted-halton.v1`；`SceneSampler.sampling_plan()` 缓存与来源绑定的计划，小预算保留大预算前缀。`installation.py` 和离线 `optimize_mount.py` 提供有限安装集合的完整过叶覆盖搜索；`WFRL_OT_X100SearchApply` 读取报告，由 `selected_installation()` 重算排序并核对来源、几何、采样算法、错误及有效推荐，沿用安装事务，保留当前采样预算。`tracking.py` 根据点云、同刻塔面、根部方向和名义叶尖径向坐标做叶片走廊关联、稳健局部拟合和因果平滑；Blender先验以轮毂为原点、局部Z末端取 `TipRad`，不读取材料标签或变形叶尖。估计拒绝状态、模型塔距与拟合段由独立面板／机舱XZ绘制，原始帧及侧壁诊断仍保留所有点。详细入口与限制见[观测研究](../docs/blender/X100观测研究.md)。

`Session.derive_blades()` 在主线程会话更新中按新配对上下文派生，不依赖观察窗口；关闭估计开关清除结果和因果历史。缺测、来源失效或不支持的来源撤回模型结果，派生异常保留合法原始帧。安装、采样和估计的规范模块分别由构建清单 `RADAR_MODULES` 纳入 `_vendor/radar_x100/`，0.3.42.6 公开扩展包含这三个模块。

工作区 `SideWallQuery` 在同一上下文、帧身份与点数组内共享成功的塔面最近点查询，供叶片跟踪和距离诊断复用。ROI 分别生成有效性与统计，扩大 ROI 只补算未查询点；失败点可重试，换帧或点数组变化使缓存失效，派生叶尖查询独立。离线安装搜索在同一源时刻和候选安装位只构造一份只读 `SceneSample`，供多个种子复用；采样计划、可见性和推荐规则不变。

`SceneSampler.material_sample()` 为速度差分只计算所选材料顶点，静态拓扑与同刻遮挡树按绑定复用；安装对象及父级存在约束或动画时撤回观测，记录失败终态保留在所属场景。

独立画布的辅助顶点统一使用C连续的 `float32` 数组提交GPU；拟合线和叶尖十字使用 `POLYLINE_UNIFORM_COLOR`，在原始点云之后按画布区域裁剪绘制。后台 `radar_x100_observations.py` 核对原始帧、来源绑定及推理输入边界；窗口 `radar_x100_estimation_window.py` 读回拟合线／叶尖区域像素，核对关闭、恢复及原帧和时刻保留。脚本控制不等于外部键鼠验收，实际保存证据见[研究验证](../docs/blender/发布状态与验证范围.md#x100-观测研究工作区验证)。

工作区源码通过 `radar_x100/core.py` 使用规范 `schema.PROFILE` 派生外壳、视场、角域和点数上限；`schema.DISPLAY_DEFAULTS` 单独定义示意长度和画布余量。`configuration.py` 比较会话应用时的来源配置与当前编辑值，显示未应用差异；显示设置、下一新样本预算与下一次记录目录不属于待应用配置。安装快捷按钮成功后同步实际应用配置，不自动热切换编辑值。

`Session.recording_health()` 把记录状态、失败原因、目录与已写帧数保存在所属场景；结束失败记录后，常规刷新保留该终态，新记录启动才清除上次错误。所属场景已删除时不写入失效 RNA，写盘线程仍须完成关闭，随后释放会话归属。

工作区源码的 `Session.stop_recording()` 和 `runtime.stop()` 返回布尔完成状态；`False` 表示已停止接收记录、写盘线程仍在收尾，不等待线程或释放归属。`runtime.tick()` 自动确认终态；写盘未退出时拒绝新记录及会话替换。`Fanout.request_close()` 仅发出停止请求，外部采集端的 `Fanout.close()` 则等待线程退出。加载／历史恢复按各自场景重绑；卸载时只保留必要的写盘收尾轮询，完成后停止计时器。

工作区源码的单帧 PLY 要求显式来源声明，并在显示与记录中保留该声明的性质；完整记录目录保留原始来源。几何采样在暂停和新帧前核对机舱外壳绑定、局部变换及网格数据，发生原生编辑时撤回旧观测，重新应用配置才能绑定修改后的静态几何。独立采集脚本的记录失败状态同时反映到非零进程退出码。源码行为与公开附件、日常安装分别核对。

工作区的 `radar_x100/output.py` 提供按场景绑定的独立点云窗口，使用 Image Editor 的专用 GPU 画布读取现有会话最新帧；`radar_x100/display.py` 与场景叠加共用只读属性着色，提供传感器角度投影及米制正交视图。窗口不创建相机或场景实体、不驱动观测或运动、不积累历史帧；导航状态与点云批次属于观察窗口。工作区与本机安装的窄窗通过控件换行保持字号，动静属性使用固定分类色，速度支持固定对称或逐帧色标；窗口色标选择只影响观察。关闭观察不关闭雷达会话，文件加载、撤销／重做与卸载释放窗口、绘制句柄和轮询资源。该窗口包含于 0.3.42.6 公开扩展；本机日常安装按其独立记录识别。

工作区源码的 `display.CanvasCache` 为每个观察窗口保留背景／按钮、网格／边框、色带和机舱参考四个当前辅助层。`output.OutputWindow` 按实际尺寸、UI scale、视图、bounds、缩放／平移和色带依赖重建，GPU 引用限于所属绘制上下文；上下文归属改变或绘制异常清除缓存，关闭及加载／历史／卸载生命周期释放引用。动态点云、未知状态和文字独立更新；点云裁剪缓存也包含实际画布矩形和 UI scale。该缓存和配置提示包含于公开扩展，本机安装使用 0.3.42.6。

几何采样、文件回放与本地通道基础能力包含于源码和本机日常安装，公开附件按其独立载荷核对。真实 PLY 对照、厂家 UDP／SDK 解码、实机标定、航迹与相机投影仍待外部资料及独立验证；不提供现场精度或安全保护结论。操作见 [X100 雷达](../docs/blender/X100雷达.md)，合同与采集入口见[规范数据核心](../wfrl/radar_x100/README.md)。

工作区源码的 `wfrl/radar_x100/analysis.py` 保持纯 NumPy 数学边界；`SceneSampler.analysis_context()` 只提取中心取样的塔面及允许的变换，`SideWallQuery` 使用共同锚点后的专用 BVH 选面，再以 float64 Voronoi 区域计算精化最近点。`Session` 以运行代、会话、来源、帧、时钟、回放索引及标定身份配对上下文；分析、原始帧、显示和记录分层失效。`output.tick()` 登记当前窗口需求并派生，`draw()/consume()` 不采样、不建立或查询 BVH。核心导入和构建 vendor 清单包含 analysis，不手改生成副本。在线接口不读取真实材料、叶片身份或变形叶尖。侧壁区域由 `tower_side_polygon_ids()` 核对构造语义，按 loop triangle 的 polygon_index 映射，排除封口；保持 tower_mesh 二元组和 FarmFlex 塔五元组，覆盖刚塔回退。原始／有限／投影／像素裁剪索引逐层保留，不按塔距删点。分析上下文和结果不进入原始记录，旧记录无上下文时不借当前Scene补历史。

`SceneSampler.sampling_transaction()` 仅在一次同步观测中复用绑定校验，finally 释放；tick 的原生编辑校验及独立 sample 调用保留；面拓扑经连续角点属性 `.corner_vert` 读取，属性缺失时退回 `loops.vertex_index`。窗口轮询继续接收状态、LIVE 过期和录制健康，按帧、样式及错误签名请求重绘；`runtime.tick()` 只在所属场景的观测帧、点云批次、显示有效性或视场开关按对象身份变化，以及会话关闭时请求该场景 3D 视口重绘。`RotorClock.configure()` 先校验整组参数再按旧 RPM 积分并提交。相机 `render_group`、状态摘要、snapshot/readback 及 PNG 写入提供默认关闭的 `performance` 聚合 CPU 计时，不改变画幅、RGB、取消或终态；嵌套计时不能相加或解释成 FPS。操作与覆盖报告见 [X100 雷达](../docs/blender/X100雷达.md#机舱局部分析工作区源码)。

工作区源码的新几何帧由采样事务执行一次完整来源校验；暂停帧和相机采集期间保留每次轮询的校验，独立零载荷参考仍单独校验来源。同帧距离分析只缓存成功结果，临时失败在同一冻结帧上每隔至少 0.25 秒重试；ROI 改变可立即重新计算。失败清除距离结果并保留原始帧，不重采样、不改写记录。

场景 X100 叠加的 GPU batch 构建／绘制失败保留合法原帧，以至少 0.25 秒间隔尝试重建显示；该操作不采样、不改变预算或时钟、不重复记录。来源失效仍撤回观测。机舱 XZ 的点色、色条、单位和说明统一采用连续塔筒侧壁距离，普通 MS 与速度视图保留各自语义。

独立零载荷参考在同一来源／绑定代内复用已完整验证的只读输入，只逐帧变换曲线；来源、参考内容或绑定变化重新验证，原始参考不进入观测求解。相机编辑预览的 fingerprint 保留逐次对象成员和 evaluated pose 核对，在几何字节未失效且状态相同时复用完整摘要；正式采集仍在绘制前后完整读取和哈希几何。手动 Down 的关系扫描保持实时校验，不缓存跨场景归属。

## 合成缺陷与默认补漆

`repair_marks.py` 管理 T1/B1 距叶根约 34 m 的 **1.4 × 0.7 m** 浅灰补漆。三角面索引和重心权重通过 Geometry Nodes 跟随旋转、变桨与柔性运动；仅原始 T1/B1 带此默认标记，重建叶片和 GW184 独立模型不受影响。

源码缺陷会话首次构造以独立临时所有者记录九片原 Mesh、柔性绑定、Scene 元数据和候选资源；全部激活、helper 与列表同步成功后才发布会话并释放原自有网格。失败恢复原身份，清理未确认时保留临时所有者供重新打开或关闭重试。

`nrel_defects/` 管理九片叶片的六类缺陷、预览确认／取消、撤销重做、健康对照和参考身份绑定的 JSON。`farm_flex.rebind_blade()` 与 `deform_points()` 使修改拓扑、支持区域和轮廓沿同一保存运动更新。保存只记录已提交配置。合成外观不改变气动、刚度、载荷或雷达源；G 的几何可见性不等于图片可辨识。叶片表面点选只接收发起视图绘制区内的事件，侧栏、标题栏和其他区域的事件交给界面，编辑器或其草稿关闭时点选结束；绘制区判断与相机选点共用 `viewport.in_window_region()`。操作和约束见[NREL 缺陷编辑器](../docs/blender/NREL缺陷编辑器.md)。

## 当前主要结构

- `panels/home.py` 与 `home_state.py`：WFRL 主入口、只读任务摘要、播放器归属、当前结果／时刻、已应用相机与草稿／观察／采集状态，以及独立后端状态；各模块 `status_for(scene)` 与 `can_start(action, scene)` 共享前台资源冲突判断，独立文件复制不使用全局 busy 锁。主页提供 X100／研究任务跳转和手动 Down／冻结试验视频入口；复用回放、相机、手动和导出面板的现有操作器，不管理运动时钟。导航保存在 WindowManager，进入／返回独立手动场景时保留所选页面；卸载移除导航属性。
- `manual_scene.py`、`manual_control.py`、`manual_operators.py`、`manual_rna.py`、`manual_motion.py`、`manual_pose.py` 与 `panels/manual_control.py`：独立刚性场景、墙钟积分、姿态预设、按机组当前值微调、三机概览及严格姿态 JSON。`manual_control.py` 管理场景状态、运动时钟、姿态同步与恢复回调；`manual_operators.py` 提供 Blender 命令及姿态文件操作；`manual_rna.py` 定义属性组并管理属性、操作器、定时器与处理器的注册和释放，入口为 `manual_control.register()`／`unregister()`。`manual_pose.py` 只使用标准库，定义 `wfrl.manual-pose.v1` 和角度边界；操作器先校验所选机组再写入参数、对象与时钟，导入后暂停。文件保存不暂停运行，运动相位以同一墙钟时刻采样；[操作说明](../docs/blender/风机手动控制.md)。
- `manual_down.py`：三机独立 Down、按稳定归属复用的叶片编号和便捷 MP4／JSON 导出。独立场景副本只驱动所选机组，并清除副本时间线标记的相机绑定，保留源场景标记。每帧及提交前核对实际相机、数据归属与声明光学参数；任一帧不匹配或未覆盖全部输出帧均保留 FAILED，不能发布 MP4／JSON。非阻塞原生渲染中的 `render_post` 相机校验失败会保留首个错误，等待渲染完成或用户取消后报告 FAILED、释放副本并保留临时文件；不会自动提前取消，剩余帧仍可能消耗渲染时间。该回调没有可依赖的安全提前取消接口，不通过关闭渲染窗口或模拟按键中断作业。真实帧数、尺寸、帧率、时间戳和完整解码通过后拒绝覆盖地提交。视口渲染依赖可见窗口，最终渲染使用原生渲染作业；工作区的可见窗口导出在渲染后异步验证与提交媒体，后台同步调用返回最终结果。此入口不接管冻结试验的后台监管和母版重试。
- `manual_geometry.py`：刚性叶片固定总览／标准／近景采样、配套叶根收口和同场景静态网格复用；构造归属、几何指纹、材质槽和消费者共同限制复用，绑定失败整体回滚。塔筒及柔性叶片不参与静态去重；用户编辑、链接、fake-user、shape-key 和跨场景资源受保护。Down 入口和视频副本使用近景，普通显示档位不影响回放与测量。
- `blade_root_display.py`：回放外形对应的叶根展示附件事务。叶片切换失败时恢复接头，保留原材质及用户数据；不改写运动、载荷或测量资源。
- `manual_scene_links.py`：原场景以稳定的手动归属标识查找其独立场景，手动场景以 Scene 指针保存返回目标，避免双向 Scene ID 引用形成依赖环。名称改变不影响查找；复制的原场景不能认领另一原场景的手动模型，归属不明确时不返回目标。加载和撤销恢复时规范存储关联；缺少标识的保存文件仅通过唯一返回关系恢复关联，显式解除的关联保持断开。
- `manual_video.py`、`manual_video_job.py`、`manual_video_render.py` 与仓库 `scripts/blender/render_manual_video.py`：保存已确认试验的场景副本，独立监管后台渲染 T1 Down，复用 `wfrl.camera_video.media` 编码与检查。`scripts/blender/manage_manual_video.py` 提供持久化作业的查询、等待、取消和完整母版重试。面板提供输出路径、保持时长、进度、取消和打开视频；安装入口通过偏好的 `project_dir` 定位完整工作区；注册阶段延迟到可访问场景后恢复作业。渲染后台使用该工作区源码，监管进程显式继承该项目的模块搜索目录。依赖支持 `flock` 和 `waitid(WNOWAIT)` 的独立 Python 3.11+（macOS 上 Python 3.13 起提供 `waitid`）及 FFmpeg／FFprobe。
- `panels/farm_replay.py`：共享播放、单步、复位及功能页；普通三机回放提供进度定位，统一重建对照隐藏进度滑块。View 页组织观察相机，切视角保留回放时刻。
- `split_reconstruction.py`、`split_reconstruction_timing.py`、`split_reconstruction_ui.py`：保存分屏生命周期、完整风机显示、独立视口、固定采样映射、统一入口、模式切换及左下角状态说明；底层样本步进工具保留，统一侧栏使用单帧步进。规范资源为 `assets/examples/mappo_reconstruction_split.blend`。
- `split_mappo_texture.py` 与 `assets/blade_recon_mappo_tex/`：同源纹理同步回放，使用原两相机实验的 601 个保存状态与动态标定生成固定 RGBA 图集，共用 MAPPO 的 60 Hz 时间轴。`split_texture_settings.py` 保存同源纹理的显示选择并在失败切换时回滚状态。来源、模型等价和安装边界见[发布状态与验证范围](../docs/blender/发布状态与验证范围.md)。
- `deflection.py`：T1 三叶片独立未受载参考、实际结构叶尖及根系 xyz 分量。参考随同刻塔顶与转子运动；源通道对照按实际可用性显示。
- `tower_motion.py`：读取并校验 v2 塔架截面与机舱变换，插值运动；`farm_flex.py` 同步塔筒网格、叶片、机舱及雷达挂载。
- `assets/mappo/`：包含默认预弯 v3 离线记录，无需求解器、Bridge 或项目路径；数据格式代次与扩展版本号分开管理。
- `assets/dual_beam/` 与 `assets/dual_beam_tls/`：两个结果层共享 `assets/mappo/` 的 40 Hz 源数据；默认 `hub-axis.v1`，显式选择 `hub-tls.v1`。
- `stacked_camera_rig.py` 与 `panels/stacked_camera_rig.py`：共盒三相机、支架安装端贴合、盒体末端转向、确认／取消／撤销及默认布局复位。
- `custom_cameras.py`：槽位、相机参数、布局及兼容处理；`native_camera_views.py`：独立原生单路／三路观察窗口。观察代理通过约束跟随位置和朝向，姿态、输出尺寸及记录焦距变化保留代理身份和手动视角；来源相机、FOV、裁剪距离或场景画幅比例变化时重建光学代理，保持相机／自由视角模式。文件加载后 `panels/custom_cameras.migrate_loaded()` 删除没有编辑会话持有的已保存草稿及其未使用的镜头数据，未确认的草稿不阻塞后续编辑、清除、启用切换、撤销和采集。观察会话释放后停止巡检计时器，未释放资源仍按间隔重试清理。
- `custom_camera_capture.py`：同刻或时间序列原图采集；`custom_camera_preview.py`：保留预览计算与质量恢复支持，普通原生观察不依赖逐帧 PNG 采集。
- `assets/cameras/t1-three-camera-default.json`：默认三相机取景配置，加载 MAPPO 时应用；显式重载与普通播放分开处理。
- `cameras.py`：观察相机与云台预设；Down 在各机舱底壳偏后缘侧求交定位，光心沿局部 −Z 外伸 0.2151 m，朝叶轮侧偏离正下 7.5°；采用独立 8 mm、16:9 垂直 60°光学预设，保留归属校验、失败清理与完整画框。[Down 参数与边界](../docs/blender/T1Down机舱下视.md)。
- `nacelle_camera.py`：单路机舱相机的机械转轴安装基准、8 mm 镜头及独立 59°/40°视场；`nacelle_visibility.py`：三角面与视锥裁剪、展向覆盖及有限首命中采样。[参数与当前模型限制](../docs/blender/NREL机舱相机.md)。

手动场景以 `wfrl_scene_kind=manual` 标识，使用独立命名空间的对象、网格、材质、World 与图片，复用 NREL 参考几何构造，不加载 demo 的柔性结果驱动。每台风机通过场景内对象指针绑定偏航、转子及叶片；控制前检查归属、装配层级和跨场景共享。RPM 按单调墙钟积分，改变速度保留相位；“全部”只传播正在编辑的字段，参数差异以“多值”提示，集体桨距统一覆盖三片叶片。批量设置分别变桨模式时，`_batch_update` 跳过已处于目标模式的机组；只在从关闭切换为开启时，以该机当前集体桨距初始化三片叶片。暂停时可设置叶轮角度；全部零 RPM 时禁用运行。参数和姿态随 `.blend` 保存，加载、撤销、重做、退出及失效绑定均暂停运动。首次创建与损坏重建分别形成撤销记录，重建保留返回视图。材质预览使用独立天空和轻量地形，退出恢复源场景预览设置。面板进入／返回保留源场景及播放位置，活动后端连接阻止进入；手动运动不写入后端或回放时钟，也不产生物理测量值。手动场景与三相机、缺陷编辑器的串联暂缓，不属于当前交付范围。

手动保护错误保存在场景的 `wfrl_manual_error`、`wfrl_manual_error_turbine` 和 `wfrl_manual_recovery`；异常暂停本场景全部机组并保留最近显示的姿态、实际桨距和试验时间。普通参数编辑不能解除保护。`recheck_feedback()` 检查绑定和受控旋转，通过后清除错误且保持暂停；`wfrl_manual_status` 分别表示主动暂停、隐藏场景暂停、载入／撤销恢复及检查通过，不代替旋转与变桨的运行标志。

工作区源码的手动场景默认使用 `rootkink` 叶根拐点改型，可选 NREL；`manual_scene._ensure_blade_model()` 以独立网格保留材质、UV、装配与参数，不改 demo 网格。普通手动变桨使用独立 `PitchClock`，目标、实际桨距与暂停状态分开；速度 0 立即到位，原生冲突和失效绑定停止在最近已显示的姿态。`manual_motion.PitchTrial.pose_at(t)` 从冻结起点计算累计方位及三片桨距；`interpolation` 为 `SMOOTH` 时使用起止速度为零的三次平滑插值，为 `LINEAR` 时按各片桨距差除以共同变桨时长匀速过渡，到达目标后保持。未指定该字段的配置按 `SMOOTH` 解析。`TrialClock` 是 T1 试验的唯一时钟，试验期间普通 `_CLOCKS` 不写入该 T1。`wfrl_manual_trial` 分开保存待确认输入、JSON 冻结配置、控制启用状态与已过时间；结束试验保留最近确认的冻结配置，下一次确认才替换。目标填写不应用，整体校验后按当前实际姿态确认。暂停／继续作用于旋转和变桨，复位恢复完整起点，结束试验后才能设置另一组或更改 T1 姿态与 RPM。模型身份、起点、目标、时长、变桨方式和试验时间随 `.blend` 保存，重开和撤销重做后暂停；姿态 JSON 仍只保存同刻姿态。

工作区源码的冻结试验复位／结束检查点按同一单调时刻采样 T1 试验、其他机组的转子与活动变桨，包括叶轮停止但桨距仍在变化、T1 已暂停而其他机组仍运动的情况。归属校验只查询受控对象在其他 Scene 中的实际成员关系；元数据引用不等于场景共享，实际跨场景共享仍在每次控制检查时拒绝。

手动 **T1 Down** 向 `cameras.ensure_gimbal()` 显式提供 T1 条目的 `yaw_object`、独立相机名与资源归属，复用 `_down_mount()`、`down_gimbal()` 和无遮罩视口适配。相机继承机舱，不随叶轮旋转或追踪叶片；切换 Down／整机保留试验时钟及状态，真实结构和自遮挡保留。这些手动试验能力包含于公开 0.3.42.6；视频后台仍需配套工作区源码，日常扩展按[安装身份](../publication/daily-installation.json)核对；手动工况的 RTSP 接入及识别算法不在实现范围。

手动面板的视频规格为 1920×1080、25 fps、H.264 MP4；变桨时长默认 8 s，目标保持默认 7 s，共 15 s、375 帧。`manual_video_render.frame_count()` 要求总时长对应整数帧。 监管解释器选择同时核对 Python 版本、`flock` 和 `waitid(WNOWAIT)` 接口；不兼容候选不会进入后台作业。每帧以 `PitchTrial.pose_at(k/fps)` 从冻结起点确定累计叶轮角和三片桨距，导出不依赖预览已过时间；后台停用墙钟，只驱动 T1，T2/T3 保持快照姿态。EEVEE 默认 16 个采样，关闭运动模糊，固定完整画幅和色彩设置，不模拟实体曝光。

`wfrl.manual-video-job.v2` 记录随机作业身份和监管凭据、场景副本、场景名、冻结试验、输出路径、画幅、帧率、保持时长及编码器路径。`<文件名>_data_<标识>/` 保留 `master_frames/`、`frames.csv`、`camera.json`、`experiment.json`、`scene.blend`、作业／状态／监管端点 JSON、运行日志和检查结果。`frames.csv` 使用连续 `frame_id`／`video_pts` 和 `time_s=k/fps`，另存同刻 RPM、累计方位、三片桨距及变桨／保持标记。固定的单叶片 20° 工况保持 rootkink、T1 Down、9 RPM、4 s 匀速变桨和 176 s 保持，共 4500 帧；B2/B3 全程 0°。

`manual_video_job` 的独立监管进程继承输出与作业锁，持有原始 `Popen` 身份；在停止进程组前用 `waitid(WNOWAIT)` 保留主进程身份，避免 PID／进程组编号复用。取消覆盖同组子进程并处理主进程先退出的情况；写入最终状态前完成进程收尾。查询和取消通过绑定作业、运行实例和随机请求的 HMAC 本机端点完成，磁盘 PID 仅用于诊断。`PREPARING`、`RENDERING`、`ENCODING`、`VERIFYING`、`PUBLISHING`、`FINALIZING`、`CANCELLING` 属于运行状态；仅带 `final=true` 的 `COMPLETE`／`FAILED`／`CANCELLED` 是最终结果。`LOST` 表示无法验证监管联系，不冒充退出或取消；输出锁仍被持有时继续拒绝重复启动。源 `.blend` 保存 `wfrl_manual_video_job` 后可在重开时恢复监管，作业路径也可独立查询。场景副本不认领源场景作业。

`manual_video.py` 在后台线程执行视频取消，同一作业的重复请求合并；主线程只提交请求、读取缓存并显示等待确认。取消响应按查询代际和作业路径匹配，不能用旧响应覆盖重载后的状态；超时或监管联系失败保留错误，有活动作业时继续跟踪；取消成功以已验证的终态为准。命令行管理入口继续等待监管结果。

工作区源码对失败、取消或失联的非活动视频记录，在界面读取超过两秒的缓存时异步重新查询当前 attempt；已完成交付不重新轮询。取消不把可重试的旧终态当成当前作业的权威状态，后台按作业凭据核对并取消当前 attempt；旧 attempt 或旧文件代际的迟到响应不能覆盖新的作业状态。

工作区源码的母版封存或全量校验结果只在同一 worker 的完成流程内传递，进入编码前仍检查作业与 `master.json` 身份。编码器独立读取实际 PNG 摘要并与该结果逐帧对照；独立重试入口和跨进程边界保持完整母版校验，不跨 attempt 复用校验结果。

`master.json` 只在全帧完成后封存，绑定 `job.json`、快照、相机、实验来源、姿态 CSV、逐帧 SHA-256 和编码配置。`retry --job <job.json>` 在同一作业和输出锁下核对完整母版，调用 `encode_video(..., resume=True)` 恢复受输入哈希和所有权限制的编码事务，再执行严格解码、尺寸、帧数、时间戳与时长验证。已完成编码通过其保存的 `encoding_intent` 和成片哈希复用；未知成片、符号链接、缺帧、内容或来源变化均拒绝，已成功作业不改写状态。此入口不启动 Blender，不实现逐帧渲染续传。

发布由 `wfrl.camera_video.publication` 在目标文件系统复制、刷新并提交完整文件。macOS `renamex_np(RENAME_EXCL)`、Linux `renameat2(RENAME_NOREPLACE)` 或可用的硬链接提交均拒绝替换已有目录项；原生接口不可用且目标不支持硬链接时，渲染前预检拒绝。跨文件系统复制使用目标侧暂存，发布凭据绑定暂存文件身份和成片哈希，支持提交完成但状态写入中断后的识别。普通失败及监管取消清理已记录的自有暂存，未知文件保留。输出侧锁名持久保留，只释放锁；按目标父目录身份和规范化文件名串行化同机作业。生成脚本默认等待最终结果，脱离运行须显式 `--detach`；命令和退出码见[手动视频操作说明](../docs/blender/手动场景研究接口.md#导出变桨视频)。

监管、恢复与发布有纯 Python 子进程及非媒体占位文件回归；真实 Blender 场景重开、编码、完整视频、Linux 及实际跨文件系统集成仍需单独验证。源码修改不表示安装版或公开附件已更新。

手动控制面板采用基本机组参数、姿态工具、运行／暂停／停转／复位及姿态文件入口；`panels/manual_control.py` 在 WFRL 手动页和风机控制页共用。普通静止默认桨距 90°、变桨速度 5°/s；运行命令 0°，暂停与停转命令 90°，复位立即到 90°。命令通过 `manual_operators.py` 调用 `_command_pitch()`，使用现有 `PitchClock` 保存连续实际桨距。冻结试验与 Down／视频保留独立[研究接口](../docs/blender/手动场景研究接口.md)，不在基本面板中绘制。

## 源码资源生命周期

扩展注册使用逆序资源账本，子模块取得资源前登记对应清理，部分注册失败仍执行所有逆操作并汇总错误；失败清理保留重试。卸载在释放播放器归属前只取消 WFRL 管理的实际播放场景，普通场景的原生播放不受影响。

已有 MP4 的复制任务区分 RUNNING、CANCELLING、SUCCEEDED、CANCELLED 和 FAILED。取消、加载与卸载只作有界等待；仍存活的线程、取消事件和私有暂存文件保留任务归属，退出前拒绝新复制。只有目标提交完成才成功；取消不会删除已提交目标。视频状态变化仅请求相关 UI 区域重绘，稳定状态不反复请求完整视口绘制。

Synthetic 撤销／重做清除 Python 数据绑定和样本缓存，按恢复后的 Object／Mesh／材质和 packed RGBA 重新绑定；独立样本游标、分屏导航和其他场景状态分别保留。

## 当前三相机维护要点

三台相机共同安装在 T1 机舱外伸支架末端，光心随整个盒体运动，各路保留独立方向与视场。贴合约束作用于支架安装端，不能把盒体背面贴住机舱当作默认安装；自由 XYZ 操作会解除贴合约束。

工作区源码的相机发布在任何退休、重绑或删除前核对 Object 归属。其他 Scene 的直接引用（包括时间线相机标记）、对象成员，以及外部或无当前场景归属的局部相机视口，会使编辑确认、布局替换或清除被拒绝；用户须先解除外部关联或创建独立相机对象。不同 Object 共享 Camera DATA 仍受支持，共享数据保留名称、身份与光学参数。当前场景的相机、局部视口与退出快照在同一事务中重绑，失败保持原布局。

精确预览的场景失效回调持久化并在加载后幂等注册；模块重载替换其自有旧回调，卸载清除自有回调并保留无关 handler。依赖图版本按所属场景区分，其他场景更新不使本场景的预览、采集摘要或相机历史缓存失效；文件加载使全部场景的预览失效。静止画面中的同帧几何变化也会使预览请求失效；回调与请求验证不等于 GPU 像素或实际 FPS 验收。

工作区的编辑预览按所属场景的播放归属选择画质。宽／高画幅在名义预览预算不足时提高长边，按正式输出相同的整数像素舍入规则保持短边至少 16 px、原视场角和完整画幅；仍执行 GPU 纹理上限校验，不修改正式输出分辨率或采集规则。

**恢复默认三相机** 复用已保存的默认 JSON，不改变回放帧、播放状态或用户自由视图。布局和原生状态都已默认时保持对象身份与历史；原生对象状态损坏时显式复位可修复。当前源码通过 `custom_cameras._publish()` 在同一事务中重绑定场景、当前场景的相机时间标记、局部视口及同场景未关闭控制器的 `snapshot`、`external_snapshot`、`session.snapshot` 相机引用，覆盖编辑确认、布局替换与默认复位；引用随相机对象一起提交或回滚。`_refresh_references()` 仅在 WATCH / LAYOUT 刷新当前观察相机。

当前目标是同一叶片的连续视场与相邻重叠，不要求三等分，不按目标叶长范围裁切图像。C2 可能因透视关系看到较远叶尖；不要求只有 C3 可见叶尖。默认参考时刻为 117 s，固定相机在旋转中允许叶片进出画面，不自动追踪叶片。

`panels/custom_cameras.py` 按参数、图像版本、错误、时钟、区域尺寸及拖动状态变化请求重绘，静止 WATCH／AIM 仍保留生命周期看护。操作器通过自身 Timer 的推进量过滤其他定时器事件，摇杆继续按时间积分；原生 Event 不提供定时器归属时也不把全部 TIMER 事件算作有效节拍。首次画面、加载／异常和交互结束仍触发必要刷新。

原生窗口用临时观察相机表达各路视场，共用场景和时钟。观察视口不显示画幅外遮罩和额外画幅边界；已保存的项目相机在加载或扩展注册时清除遮罩，切换视图不重新启用。周围场景保持可见，正式采集仍按相机真实 FOV 和画幅输出。重建、同源纹理和独立纹理相机的保存状态也遵守无遮罩显示。分屏侧栏初始化期间若暂不可编辑，保留当前页签并完成视图布局；原生属性异常会结束布局任务并显示错误。默认 GRID 为 2×2，第四格是 `installation_schematic.py` 生成的静态安装示意；STRIP 为三列对照。两种布局均有播放／暂停、单步及单路放大；镜头切换和预览画质操作只接受观察会话所属场景的上下文。独立 WATCH 和放大固定使用 SOLID 材质颜色显示，无单路画质切换；返回三路恢复其原画质。PNG 采集使用独立原始质量设置；完成、取消或异常退出时恢复仍由采集持有的回放状态。外部寻址、播放或暂停使采集失效，并保留用户当前时刻及播放状态，不用采集前的快照覆盖。

工作区的 PNG 采集调用 `render_group(..., create_texture=False)`，回读真实 RGBA 像素并完整核对求值几何，不建立显示纹理。非手动 FarmFlex 序列绑定窗口、场景、视图区域、View Layer 和冻结的时间映射；`frame_set()` 返回后按 RNA 子帧精度核对请求时刻，第三方回调改帧使采集失效并放弃时钟恢复。绘制前后、异步写入与提交前核对归属，外部上下文或映射变化使事务未完成，保留已提交组及用户修改。恢复期间发生变化时不恢复旧时间属性或自动重播。每次采集保护检查只生成一份新的布局，同时用于保存参数摘要和原生相机状态摘要；模型签名读取求值后的顶点与面，不构建碰撞查询需要的法线和 BVH。各次保护检查仍重新读取几何、修改器及镜头状态，不跨整段采集复用布局。相机编辑预览直接持有离屏目标的 GPU 纹理，显示不读回再上传像素；只有整组成功才替换上一组，最多保留两组目标，失败保留旧画面及其错误提示。两条路径共用颜色管理、相机参数、场景状态校验和资源清理；提取次数减少不等于已测得 FPS 或 GPU 性能提升。

GPU 取图和元数据冻结在 Blender 主线程完成；`ImageWriter` 只接收独立像素字节、尺寸和目标路径，在工作线程压缩并写入 PNG。每次最多处理一组图像，等待期间事件循环继续运行；写入成功且场景、相机与时钟保护检查通过后，主线程才提交该组元数据与完成计数。普通取消等待当前组结束，文件重载或会话失效立即保持未完成并撤销后续写入；正在编码的单张图像可以结束写入，但不能把事务改为完成。未结束的写入退出前不能开始另一采集，不积压图像队列。

采集操作器以最终事务的 `manifest.status` 判断结果：只有 `complete` 才报告导出成功；状态恢复失败、取消或会话失效均返回未完成，并保留清单中的原因与已写入图像。工作区逐组向 `frames.jsonl` 追加已提交元数据；活动 `manifest.json` 在完成组数为 2 的幂时保存检查点，最终清单记录准确组数。

预览的连续输入保持 250 ms 刷新预算，镜头输入停稳 50 ms 后可提前更新，实际间隔仍不小于上一组绘制耗时；首次画面无需等待已有图像的冷却。预览几何摘要按依赖图更新复用求值顶点，变换与对象成员每次读取；源／时钟／依赖图变化、几何修改或看护回调失效均清理缓存，采集不使用该字节缓存。持有离屏纹理的预览图在 `rgba()` 显式请求时才回读像素；采集的 `create_texture=False` 路径继续直接提供真实 `pixels`，现有采集调用不依赖预览缓存。

当前源码中，观察会话分别保留代理对象与镜头数据引用，分步释放绘制回调、代理和窗口，并独立恢复预览画质及主视口。已经删除的 RNA 不阻止其余清理；未释放的资源保留供再次关闭重试。布局事务提交后，释放失败的旧相机对象与镜头数据也分别进入重试队列；对象已删除仍可回收其镜头数据，数据仍有用户时等待后续清理。正常释放时仍被其他对象共享的数据不纳入失败重试队列。准备／观察失败保存在场景的 `wfrl_native_camera_error` 并显示于三相机主面板，成功完成重开后清除。

相机窗口的播放按钮和时间提示按实际场景播放归属显示。另一场景占用播放器或活跃播放器归属不明时，播放与单步按钮禁用；空格键请求和直接调用同样拒绝暂停或抢占该播放器。关闭及延迟恢复也保留另一场景的播放。源码同步不改变既有公开 ZIP 或日常安装的身份。

工作区的单路与三路播放按钮复用回放重播入口：位于终帧时从起点播放，播放期间采用 Blender 的 `STOP_END_FRAME` 模式停在片尾，丢帧不使片段意外循环。片尾停止请求绑定场景、读取器与播放代次；关闭后的延迟续播也校验播放代次，期间发生新的播放、暂停或加载就使旧请求失效。中途关闭保留当前时刻和同场景播放，不抢占其他场景。

[源码窗口验证](../outputs/camera-reopen-verification/final-native/result.json)记录 macOS Blender 5.2.1 独立窗口中的单路完整片段、终帧关闭重开三路、三路完整片段、重复切换、暂停、关闭续播及旧延迟恢复失效。三路均有推进与终帧绘制记录；脚本调用原生操作器，不等同于物理鼠标操作、稳定 FPS、安装载荷或跨平台验收。记录中的源码摘要界定证据范围。

相机视锥并集、射线可见性与拼接成功是不同检查。参考姿态的连续投影和重叠已有证据；根部连接件、机舱和叶片自身仍会遮挡局部表面，完整无遮挡尚未通过。不能隐藏真实结构制造几何通过结果，也不能将此仿真安装作为实体标定。

`playback_benchmark.py` 区分完成、超时、中止、错误与缺绘制。场景须从声明起点推进至终段；循环只接受末端到起点边界的已验证原生播放转换，寻址不能作为完成证据。每路须有声明激活时刻对应的起始绘制、持续推进、终段、有效最终状态和新鲜心跳；晚启用从实际激活时刻检查，只有场景静止的显式暂停区间可从推进间隔中扣除。FPS 或单个 PASS 字段不能替代这些证据。旧停止异常根因仍未定位，当前完整片段性能与跨平台稳定性继续单独验证。

## 启动与模式切换

在已配置完整后端环境的 macOS 上使用以下入口，先把示例路径替换为自己的路径：

```bash
cd "/path/to/wind farm RL"
scripts/blender/run_wfrl_macos.sh \
  --blender "/Applications/Blender.app/Contents/MacOS/Blender" \
  --python /path/to/wfrl-env/bin/python \
  --scene scenes/turb3_row.yaml \
  --mpi /path/to/mpiexec \
  --fastfarm /path/to/FAST.Farm
```

启动器预检环境并启动自己拥有的 Bridge；Blender 加载**已安装扩展**，停在 MAPPO 的 T1 侧前方首帧。默认状态为 **OFFLINE RESULTS**，Bridge 在 `127.0.0.1:8765` 待用，不自动连接或开始运行。这条入口需要完整后端环境；只看离线演示时直接打开扩展并点击“加载 MAPPO · 60 秒”，或用便携入口，无需 Python 后端、MPI、FAST.Farm 和网络。

`--python` 和 `WFRL_PYTHON` 选择的解释器入口保留符号链接路径，使虚拟环境的依赖与解释器配置在预检和 Bridge 子进程中生效。`WFRL_LAUNCHER_PYTHON` 单独指定启动器解释器，缺省为 `python3`；启动器与后端解释器都需要项目核心依赖 `psutil>=5.9,<8`，缺失时预检拒绝启动。可将两者设为同一个已安装项目依赖的环境。

0.3.42.6 安装版会同时建立推荐三相机配置，默认关闭叶尖轨迹和挠度辅助物。主视图仍先显示 T1 总览，进入 **View → 三相机 → 三路对照** 查看。仅更新仓库 README 不会改变已运行的 Blender 扩展。

需要后端时，进入 **Item → WFRL / CONNECTION → 后端连接（高级）**，选择 Replay 或 Interactive，再点 Connect / Reconnect。Item 不可见时先选中一片叶片。启动脚本在握手确认后发送 `scene.load`，自动加载命令指定的 YAML；确认 **CONNECTED / READY** 后，到 **WFRL / 后端运行** 设置参数并点击 Start Replay / Start Training。Replay 需兼容 checkpoint，例如项目中的 `results/checkpoints/mappo_fastfarm_Dec_Turb3_Row1_Fastfarm_mappo_s0_level_E128_none.pt`。

切换模式会断开前端，需要重新连接。运行结束先 Stop 并等待后端清理确认，再选择 MAPPO · 60 秒返回离线回放。工作区启动器使用固定运行标识、端点及 PID／创建时间记录进程归属；所属 Bridge 独立写入相邻的 `.bridge.json`，声明当前协议会话与递增代次。前端 bootstrap 不写这些凭据，界面连接到其他 Bridge 不改变启动器归属。启动前和请求停止前核对活进程、运行标识及端点；合法会话轮换只在同一 Bridge 实例内接受。

关闭该命令启动的 Blender 后，启动器使用所属 Bridge 发布的身份恢复会话并请求 `run.stop`。匹配的 Bridge 分别报告任务状态、`cleanup_confirmed` 和 `worker_alive`；只有明确确认清理完成且没有存活任务，才请求清理自己拥有的进程。`FAILED`、父进程退出或进程组变化均不证明全部后代已退出。监管覆盖已知后代与继承运行标识的本机孤儿进程；扫描用 POSIX UID 或 Windows 用户名排除其他用户，无关进程身份或环境不可读不构成运行归属。已记录身份仍无法核实时保留不确定状态，`alive()` 对 `LIVE` 和 `UNKNOWN` 均为真，只有 `EMPTY_CONFIRMED` 才删除两份恢复文件。启动器遇到 `UNKNOWN` 结束前台监管、保留记录并以非零退出；确认仍有所属活进程时，EOF、超时或无法校验的 Bridge 绑定继续重试，同一停止失败状态只提示一次。普通 Blender 窗口不运行此 bootstrap，连接已有 Bridge 后需手动 Load & Validate Scene。

监管未确认清空而退出时，终端打印保留的归属文件、端口和 `stop-session --session-file <路径> --port <端口>` 恢复命令。该命令核对结构化记录的固定端点和活进程身份，拒绝冲突端口或其他实例的凭据；只通过协议请求匹配会话停止，不按磁盘 PID 发信号。协议成功仅确认后端非运行，仍保留恢复文件。Bridge 已退出或无法确认协议停止时，恢复检查用 `known_processes` 和根进程的 PID／创建时间重新核对已观察身份，并扫描继承运行标识的孤儿进程；PID 已复用不认领新进程。全部确认清空时返回成功并删除两份记录，仍有活进程或归属不确定时分别报告 `LIVE`／`UNKNOWN`、保留记录并返回非零；记录中缺失或无效的身份不能证明清空。兼容的纯文本会话文件不提供上述结构化进程归属校验；空文本文件只允许空闲握手。启动器使用所选后端 Python 的 YAML 解析器识别场景后端，拒绝未知名称。

停止确认以握手的当前状态及其 `state_revision` 为边界，覆盖的历史终态不能触发进程清理；带版本握手后的新生命周期版本须有效且递增。清理结束时允许任务结果仍为 `FAILED`，但须发送更高版本的清理证明。没有清理字段的兼容服务仅接受当前握手、或高于握手版本且递增的当前生命周期中的 `READY`／`STOPPED` 作为非运行状态，不能把 `FAILED` 当作停止证明；无版本历史终态也不能代替当前握手。Bridge 接到退出请求后保留停止与同步协议，拒绝新任务，直到清理得到确认。

| 路径 | 前端显示与数据 | 是否启动求解／训练 |
| --- | --- | --- |
| MAPPO · 60 秒 | 随包随机阵风记录，九片独立形变、遥测与 B2 卡片 | 否 |
| 双束净空 / S1、TLS 候选 | 随包旧法或 TLS 结果层、外部可携带包，S2/S3 配对和独立 S1 状态 | 否 |

## 1. 场景如何搭建

前端采用 Python 程序化建模。默认几何输入来自扩展内的 [nrel5mw_geometry.json](wfrl_blender/assets/nrel5mw_geometry.json)，MAPPO 的可选合成叶片外形来自 [rootkink_geometry.json](wfrl_blender/assets/rootkink_geometry.json)。场景布局由 [scene_model.py](wfrl_blender/scene_model.py) 中的 `SceneDTO` 和 `TurbineDTO` 表达，包含机组编号、平面位置、风速、风向等信息。

scene_builder.py（本地文件：`blender_frontend/wfrl_blender/scene_builder.py`） 的 `build_scene()` 创建 `WFRL_Scene` 集合，按机组生成塔筒和上部装配，再加入基础、编号、地形、来流箭头、尾流与传感器示意，最后配置环境和渲染。当前构建器使用全局对象名；重建前检查集合及对象的场景归属，其他场景仍引用资源时拒绝重建，保留原场景及其回放。需要返回资源所属场景操作，或使用独立 Blender 进程。同场景重建会清除其同名集合及符合条件的无用户引用资源；普通切换镜头不重建场景。

几何计算集中在 [turbine_geometry.py](wfrl_blender/turbine_geometry.py)，它读取打包资源并返回顶点和面，不导入后端求解器。场景装配再使用 Blender 数据 API 创建网格、对象、父级关系和材质。日常打开已有 `.blend` 与重新构建场景是两条不同路径。

### 环境几何预算

工作区源码的 `landscape.build_landscape(collection, detail='balanced')` 使用固定空间预算：风机及生态覆盖区域保留地形采样，外围加大网格间距；远山使用较低采样，保留中心山脊和落地点。`detail='full'` 可构建完整细节供对照或特定输出使用。道路、平台和覆盖斑块继续通过 `terrain_sampler()` 贴合实际展示地面；`height()` 和 `terrain_shader()` 的调用接口保持独立手动场景兼容。

距最近风机 450 m 内的草簇保留完整几何，外围草簇保留原根部、叶尖、材质和位置，简化弯曲段；已有灌木、岩石实例继续复用原型。预算在创建时确定，不注册逐帧扫描或按活动相机隐藏背景，因此 Down、总览、三相机和离线渲染消费相同场景。保存重开保留已建几何；改变预算需要重新构建。地形和远山仅为展示环境，不进入后端地形、柔性运动或雷达测量。面数变化不等于实际视口 FPS 变化。

## 2. 风机如何建模与装配

### 2.1 主要部件

| 部件 | 实现方法 |
| --- | --- |
| 塔筒 | `tower_mesh()` 按高度—直径站点生成圆环并连接侧面，形成沿高度收缩的塔筒 |
| 叶片 | `blade_mesh()` 重采样翼型轮廓，按弦长、扭角、曲线和扫掠偏移生成截面，再沿展向插值连接 |
| 机舱 | `_rounded_nacelle_mesh()` 用纵向截面生成圆角外壳，保留配置中的长、宽、高包络 |
| 主轴与轮毂 | 主轴使用圆柱体并按轴倾角旋转；轮毂用缩放球体构造，整流罩通过环形截面收束到端点 |
| 机械细节 | [mechanical_details.py](wfrl_blender/mechanical_details.py) 补充叶根法兰、密封件、通风口、检修门与连接附件 |

叶片使用 19 个原始站点和配套翼型坐标；当前装配调用 `blade_mesh(subdiv=8, ring_points=96)`。普通截面之间采用保形 Hermite 插值，叶尖末段增加采样并收束到单点，以改善末端外观。这是展示用收尖，不能当作新的气动设计数据。

基础场景中的叶片对象复用名为 `WFRL.SharedBlade.SourceLoft` 的网格，但保留独立的对象变换与装配父级。基础场景因此可分别表达转子相位和变桨。进入 MAPPO 柔性回放后，`farm_flex.py` 改用 `subdiv=4, ring_points=48` 的展示网格，并为九片叶片分别复制 Mesh、逐帧写入独立形变；不能在这条路径继续共享可变网格。

`turbine_geometry.MODELS` 管理 `nrel5mw` 与 `rootkink` 的几何资产；两者共用 19 站径向位置、预弯、后掠和扭角。rootkink 使用较窄的叶根和靠近轮毂的宽肩部，最大弦长为 **4.85 m**，位于半径 **8.3333 m**。它只改变展示截面的弦长及翼型分配，继续由同一 NREL 保存截面变换驱动；载荷来源和雷达读数保留 NREL 身份，不重新求解，也不代表厂家 CAD 或经过重新验证的物理机型。

场景属性 `wfrl_blade_model` 保存外形选择。每次切换完整校验一次回放包，绑定和失败恢复复用该载荷。叶片、配套叶根展示附件及已验证的重建共享结构引用共同提交或回滚；共享引用完成重绑定后，只回收已无用户且属于相应模块的网格，保留共享、fake-user、shape-key 和无关网格。rootkink 的短颈、法兰和密封圈独立于 NREL 轴承尺寸，二者都只是展示装配。切换保留时刻、所选机组、可见机组、时间轴设置和相机设置。NREL 缺陷编辑或 NREL 重建对照启用时，切换 rootkink 会被拒绝；相机编辑、观察或采集会话也须先结束。相关模板位于 `projects/commercial-rootkink-reference/`，`scripts/blender/make_rootkink_blade.py` 生成叶片站表，`scripts/blender/export_geometry.py` 导出可审计几何资产。

### 2.2 运动层级

下图省略部分附件；对象全名均带 `WFRL.Turbine.<机组编号>` 前缀：

```text
机组根节点                         布局中的 x、y 平移
├── Tower                          固定塔筒
├── YawBearing                     塔顶连接件
└── YawRoot                        位于塔顶，绕局部 Z 轴偏航
    ├── Nacelle / MainShaft         机舱和主轴
    ├── ClearanceRadar...          雷达附件与光束
    └── Rotor                      主轴倾角与转子方位
        ├── Hub / Spinner          轮毂和整流罩
        ├── Blade1.PitchRoot        初始相位与预锥角
        │   └── Blade1             绕叶片局部 Z 轴变桨
        ├── Blade2.PitchRoot
        │   └── Blade2
        └── Blade3.PitchRoot
            └── Blade3
```

`PitchRoot` 分别设置三片叶片的 120° 相位间隔和预锥角，实际 `BladeN` 对象再承担局部变桨。不要把相机的 Pan / Tilt 与这些风机运动量混为一谈，也不要把所有旋转直接堆在叶片网格上。

### 2.3 高度与坐标

长度单位为米。机组根节点位于塔筒地面中心，`YawRoot` 位于塔顶；机舱未偏航时，轮毂在负 X 方向，Z 轴向上。当前塔筒高 **87.6 m**，名义叶轮半径 **63 m**，机舱外壳长宽高为 **8.03 × 3.30 × 3.30 m**。

`hub_position()` 同时使用塔高 `TowerHt`、塔顶到主轴偏移 `Twr2Shft`、悬伸量 `OverHang` 和轴倾角 `ShftTilt`。当前数据计算出的轮毂中心约为 `(-5.00, 0, 90.00) m`，不能直接把塔筒高度当作轮毂高度。

装配时，机舱外壳和部分附件相对塔顶上移 `Twr2Shft`，主轴和转子使用完整的轮毂中心坐标，偏航轴仍保持在塔顶。尺寸和装配明细见 [用户手册附录 A](../docs/blender/用户使用手册.md#附录-a风机模型尺寸与部件装配位置)。机舱、轮毂和部分附件包含展示造型，不是完整工程 CAD。

## 3. 材质与灯光如何实现

[materials.py](wfrl_blender/materials.py) 用 `PALETTE` 定义基础色，`SURFACES` 定义粗糙度范围、凹凸强度、金属度和涂层参数。叶片涂层、机舱、塔筒、金属连接件、橡胶密封件、雷达壳体和镜窗分别使用不同配置。噪声纹理连接粗糙度映射与 Bump 节点，节点按名称复用，避免重复刷新不断堆积节点。

`refresh_turbine_surfaces()` 按 WFRL 对象名称给主轴、轴承、法兰等绑定金属材质，给密封件绑定橡胶材质；雷达自己的材质槽由 `ensure_radar()` 维护。

`_apply_surface_lighting()` 调整主光方向，将曝光设为 0.45，并启用 EEVEE 阴影和局部环境遮蔽。主体材质的自发光强度设为零，以保留机舱、轮毂与叶根之间的明暗层次。以上参数只影响展示，不进入雷达计算。

## 4. 雷达外观如何建模

### 4.1 安装坐标与零件

入口为 [clearance_visual.py](wfrl_blender/clearance_visual.py) 的 `ensure_radar(scene, turbine_id, origin, directions)`。函数找到对应机组的 `YawRoot`，用固定名称查找或创建零件，并把它们挂在这个父节点下，使雷达随机舱偏航。

`origin` 是雷达光束起点在装配局部坐标中的位置，未加载结果时预览默认值为 `(-2, 0, 0)`。每个零件的位置按“光束原点 + 零件偏移”设置。下表列的是代码中的展示几何，不是硬件规格：

| 对象后缀 | 几何与定位方法 |
| --- | --- |
| `ClearanceRadar` 壳体 | 单位立方体缩放，未倒角包络为 0.20 × 0.16 × 0.25 m；中心相对光束起点上移 0.125 m |
| `.Bracket / .MountPlate / .MountPad` | 立方体构造支架、安装板和橡胶垫，沿上方连接到机舱安装区域 |
| `.Bezel / .Window` | 薄立方体构造镜窗边框与深色窗口，围绕光束起点附近布置 |
| `.CoverSeal / .ServiceCover` | 壳体侧面的密封层和盖板 |
| `.CoverScrew0…3 / .CableGland` | 32 边圆柱体，旋转到盖板法向或侧向，分别表示螺钉与线缆接头 |
| `.Cable` | 5 个控制点的三维 Bézier 曲线，自动切线并设置圆形截面厚度 |
| `.Beam1…3` | 每条由两个点组成的三维 POLY 曲线，表示三束方向 |

立方体在局部网格中边长为 2，因此 `scale` 是半尺寸；圆柱体的原始半径为 1、深度为 2。修改零件尺寸时要按这一约定理解参数，不能把缩放值直接当作完整长宽高。方形零件使用命名的 Bevel 修改器柔化边缘，刷新时复用已有修改器。

### 4.2 光束如何显示

三束光线共用橙色带自发光材质，曲线起点为 `origin`，终点为：

```text
origin + 0.95 × TipRad × normalize(direction)
```

默认预览方向相对向下竖直朝负 X 偏转；加载结果时由包内标定提供原点和方向。上述长度只是视觉示意，既不是理想首交斜距，也不是测距量程；前端不把曲线终点当作真实命中点。

雷达窗口、螺钉、线缆以及 Blender 叶片网格都不参与射线求交。真正的测距计算使用后端 AeroDyn 原生变形表面，具体算法放在 [独立雷达 README](../wfrl/lidar/README.md)。

### 4.3 为什么使用独立 BMesh

`_radar_primitive()` 在独立 BMesh 中生成立方体或圆柱，再写入新 Mesh 并通过数据 API 链接对象。它不调用 `bpy.ops.mesh.primitive_*_add`，因此不会把几何加入用户当前正在编辑的网格，也不需要修改活动对象、选择或编辑模式。

旧场景样式更新由 `refresh_saved_surface_style()` 在加载时触发，以 `wfrl_surface_revision` 防止重复升级；旧三束曲线存在时，使用其原点和方向补建附件。维护这条路径时，应保留原网格、父级、变换、场景与选择状态。不是所有建模函数都适合直接在文件加载回调中调用。

## 5. MAPPO 回放、相机与后端如何连接

### 5.1 三机结果包与九片形变

[__init__.py](wfrl_blender/__init__.py) 的 `load_demo_scene()` 先通过 `farm_flex.preflight()` 完整校验候选包、遥测及挠度对照，再停止所属场景播放、创建基础场景并挂载同一已验证对象。候选预检失败保留原回放、reader、时刻、对象和相机；实际替换后的绑定失败撤回就绪状态。默认来源为 [assets/mappo](wfrl_blender/assets/mappo/manifest.json)。结果包包括：

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | 当前 `wfrl.farm-flex-review.v3`、REVIEW_ONLY、布局、片段范围、参考定义及文件 SHA-256 |
| `geometry.npz` | 时刻、三机姿态和九片叶片沿展向的形变变换 |
| `data.json` | 三台机组各自的运动记录、B2 测距、净空估计／真值与统计输入 |
| `telemetry.json` | 同次 OpenFAST 实际保存的功率与转矩通道，含单位、源通道与文件摘要；当前内置 v3 未保存 `load` 通道 |
| `tower-motion.npz` | 塔筒截面位置/朝向与机舱变换，共享时间轴；用于塔架及挂载运动 |
| `deflection-t1.json` | 同源 T1 结构叶尖分量输出、刚性姿态及来源身份；v3 按保存的结构叶根坐标系 xyz 比较，边界变换取自 `geometry.npz` 的首截面 |
| `source-run.json` | 对应运行的来源、控制器和原始输出摘要 |
| `source-surfaces.json` | 生成形变数据所用的原始表面证据索引 |
| `blade-reference.json`、`reference-surfaces.npz` | v3 独立零载荷静止求解参考及对应表面，用于参考几何与实际形变对照 |

`read_package()` 校验格式、机组列表、文件哈希、数组维度、有限值、时间轴和运动一致性；遥测还要与几何摘要及时间轴匹配。工作区的 `_load_package()` 每次加载均完整校验源和结果层文件，随后按解析后的源路径与源 manifest 摘要复用解析数据；缓存最多保留两个源。基础、双束和 TLS 入口可共享只读几何、运动及塔架数组，各次加载的读取器、结果层身份与输出样本保持独立。仅更换结果层不重解析同源几何，源身份变化则重新解析；文件大小或修改时间相同不能绕过哈希校验。构造器、挠度比较及三叶响应分析复用同次加载的已验证源身份，遥测由该次已校验字节解析；该身份不跨加载或跨源复用。分析结果文件保持独立校验，独立调用分析读取器仍完整检查其五个源文件。公开 `read_package()` 保持五元组接口。不能在校验失败时改用假数据。原始 VTP 不需要随播放器分发；生成新结果与日常播放是不同流程。

`FarmFlex` 为九片叶片分配独立 Mesh，根据相邻源时刻和相邻展向站点插值形变，并结合机组偏航与装配变换写回局部顶点。工作区源码按消费方所需的机组工作集计算和上传整叶网格：普通单机视图选择对应机组，全景选择全部九片；缺陷编辑的寻址和几何分析可在同一时刻请求全部机组。切视图保留时钟，并在当前时刻补齐所需网格，不能以时间未变为由复用另一工作集的结果。`deformed_at()` 缓存键包含源帧和机组工作集；`rebind_blade()` 清除缓存，更换结果包或模型按新来源重新绑定。

同刻重复 `update()` 复用一份纯几何计算结果，键包含场景、来源／读取器、仿真时间及相邻源数据、模型、可见／导出工作集和对象／网格绑定。复用写入前读取原生顶点，仅字节一致且非编辑模式时跳过 `foreach_set` 和 `Mesh.update`；原生编辑、重绑和同刻切工作集不能直接沿用旧写入结论。遥测、隐藏 T1 的测量对照、缺陷附件与共享结构仍按各自请求更新，`record_telemetry` 和 `update_comparison` 不因几何命中而被跳过。

隐藏 T1 整叶时，挠度比较仍按同一插值与坐标计算采样三个结构叶尖，保持与可见 T1 的读数一致。普通回放还更新所选机组与 T1 的塔筒及挂载结构，包含仅选择 T2/T3、暂停时首次创建重建共享结构的情况；共享结构在源姿态与塔筒更新后同步。单机视频导出显式限定所选机组，不强制保留 T1 比较或结构。隐藏整叶不等于停止这些数值与结构消费方。这里保留物理变形幅度，展示网格的采样密度不等于求解器网格密度。

本节描述当前工作区与公开 0.3.42.6 的实现。跨加载的源解析缓存、按消费方选择工作集、单次加载内遥测数组复用及计时入口包含于公开包；ZIP、隔离安装和日常安装分别按其摘要与记录使用。源码脚本窗口覆盖播放归属和资源生命周期；日常安装使用安装记录所列的 0.3.42.6 载荷，检查范围见[安装身份](../publication/daily-installation.json)。包验证工具只运行后台检查，当前安装与公开包均未运行独立点云窗口的 GPU／RGB 检查。工作量计数与数值一致性不证明视口 FPS。

[tip_tracking.py](wfrl_blender/tip_tracking.py) 从变形网格的叶尖位置记录轨迹，叶片 1／2／3 分别为红／绿／蓝，相邻两圈定格对比 2 个仿真秒后淡出。轨迹不是相机测量；同机切镜头保留轨迹，换机、寻址、重播时按生命周期重置。MAPPO 默认关闭轨迹，需要时主动打开。

轨迹显隐逐一作用于所属场景的 View Layer，允许原生删除的 RNA 在卸载时被跳过。环境预设仅在 World 被另一 Scene 引用时复制 World。合成纹理与独立表面导入失败时恢复显示和属性，释放本次导入拥有的资源；清理未确认的资源保留到重试，不删除共享或用户保留数据。

柔性更新先预检实际消费者工作集的对象、网格拓扑和支撑绑定，再写姿态与几何；几何及关联消费者成功后才提交时刻和遥测。隐藏 T1 测量、共享结构与导出消费者继续参与工作集。中途 Mesh／RNA 失败锁存 `wfrl_flex_frame_valid=False`，撤回该场景 reader，并只暂停所属播放器；已显示几何可能部分改变，必须重新加载结果后才能作为完整帧使用，不通过恢复损坏网格伪造成功。

### 5.1.1 塔架、叶片参考与净空

初始塔筒网格带回放归属标记，绑定提交时只释放无人引用且无保留条件的旧网格；三相机盒体网格使用自有命名空间供场景销毁识别。清理保护共享、fake-user、shape-key 和 linked 数据。装饰修补附件在塔筒和共享结构绑定成功后、逐帧形变开始前重建，结构绑定失败时保留原附件及采样引用。

当前包包含三机塔架同源运动；塔底保持固定，机舱、叶轮及雷达安装随塔顶平移和转动。展示保持真实尺度，未放大摇晃幅度。v3 叶片参考来自独立零载荷静止求解。工作区 `deflection.py` 用保存的首截面刚体变换运输该参考与叶根坐标系；匹配模型的首截面位于受约束叶根，气动中心偏移为零。实际点与参考点之差按这一随根部变桨的 xyz 表达，`BlPitch` 遥测不替代结构根边界姿态。参考插值同时处理旋转和已运输的轮毂位置；结构输出只用于比较。不能把已经变形的第一帧当作未受载参考。

工作区源码的保存帧 **0.2 mm**、插值帧 **5 mm** 显示门槛通过；完整时间轴、匹配原始输出和适用边界见[集成验收](../outputs/regression-repair/integration/result.json)。正式资产保持；受载 VTP 缺失使原始表面拟合无法重跑，安装载荷、求解器收敛与现场精度仍须独立验证。

`deflection-t1.json` 保留同源输出与参考所需信息。原仿真输出对照按可用通道和实际参考系解释，不能把历史面外／面内标签直接等同于当前根系 xyz；缺少通道时不制造对照值。保存帧和插值帧分别标记，缺少对照资源或摘要／时间轴损坏时必须明确提示。

v3 净空真值定义为叶片末截面表面到同一全局高度移动塔筒截面的最小距离，不是整片叶片到塔筒的最小距离，也不是仅取单个叶尖参考点。遮挡检查使用移动塔架几何；B2 固定标定估计没有补偿塔架弯曲。塔筒尚无专用虚影或位移卡片。

### 5.2 统一侧栏与固定时间轴

工作区的 [panels/home.py](wfrl_blender/panels/home.py) 在 **N → WFRL** 集中提供回放、相机、手动、导出和后端页面，保留 Item／MAPPO／View／风机控制入口；X100 使用独立的 **N → X100** 标签，通过 `home.busy_reason` 共用相机与录制占用判断。顶部按实际读取器与播放归属区分未加载、未就绪、加载失败、就绪和播放，单独显示采集／编辑占用、手动保护暂停及后端连接／确认状态。加载异常持续显示，成功加载清除；MAPPO 结果包预检或候选校验失败时不替换当前场景，已加载的回放与读数保持不变；数据、相机和后端错误不依赖高级区展开。`LOCAL DEMO / READY` 不作为空场景已就绪的显示依据。

普通回放的观察视角／分屏、外形／模型来源及离线后端状态默认折叠；合成外形与测量限制、错误及播放栏保持可见。相机页将单路、GRID、STRIP 与外部观察入口置于安装编辑之前，盒体安装设置默认折叠，活跃安装事务直接展开。盒体动作、草稿动作和采集取消校验所属场景；槽位切换只更新本场景观察会话。[panels/ui_helpers.py](wfrl_blender/panels/ui_helpers.py) 按侧栏宽度与 UI 缩放绘制消息，并通过既有诊断操作器保留完整报告；历史、MP4 和后台动画输出可打开对应目录。

[video_output.py](wfrl_blender/video_output.py) 在导出前记录源文件身份、大小及时间戳，打开文件后和复制完成时核对文件描述符、路径与实际字节数。工作区源码将完整视频先复制到目标文件系统的自有暂存文件，校验、刷新并排他提交后才发布完成路径；取消、冲突或源变化只清理身份匹配的暂存文件，保留外部程序创建的目标。视频面板分别展示 MP4 文件导出与 RTSP 生命周期，文件路径、进度和完整错误独立保留。 工作区导出在 `CANCELLING` 等待 I/O 与自有暂存清理，进入 `COMMITTING` 后等待排他提交结果。RTSP 在后台收尾两个自有进程，`STOPPING` 期间不释放占用；未退出时保留进程句柄及错误。

### 离线不平衡分析

[imbalance.py](wfrl_blender/imbalance.py) 读取独立的 `wfrl.blade-response-package.v1` 结果层。`manifest.json` 用 `source_hashes` 绑定原回放的 manifest、geometry、data、telemetry、deflection-t1；`files` 保存 `results.json` 的 SHA-256。原仿真包及其 manifest 不改写。优先读取源目录内的 `blade-response/`；未声明本地分析时，只有与内置来源完全匹配的包才使用 `assets/blade_response/`。B2、双束和 TLS 的同源回放复用该结果。分析加载失败只撤回分析读数，保留其他有效回放功能。

结果 schema 为 `wfrl.blade-response.v1`，方法为 `common-turn-phase-mean.v1`。逐叶实际方位角加 0/120/240°，取三叶都完整覆盖的共同转次，在 5° 中点网格线性插值，按转等权平均。`rms_spread` 为三叶均值曲线相对共同均值曲线的 RMS；`blade_offsets` 为各叶均值相对三叶均值的有符号差。叶尖单位 m，叶根原始弯矩 N m，界面换算为 kN·m。已完成转的读取按三叶所需时间窗口的最大结束时刻判断，向后寻址直接重新选择，不累计或保留未来转次。全片段汇总及均值曲线明确标注其离线范围。

`physical.mass` 与 `physical.aerodynamic` 分别使用 `available`／`unavailable`；不可用记录不携带数值。可用记录要求 `source_kind`（`simulation_reference` 或 `estimate`）和 `provenance`。质量记录使用 `magnitude_kg_m`、可选 `phase_deg` 及对应 `phase_reference`、`blades`；气动记录使用 `parameter`（`aerodynamic_twist_offset` 或 `pitch_zero_offset`）和三叶 `blade_offsets_deg`。当前内置记录均不可用；现有三叶响应差异没有分离风况、转速、变桨等影响，不识别两类物理故障或定义报警阈值。

面板优先显示三叶响应的全片段汇总与最近完整对齐转，两类时间范围直接标注。两类物理指标均不可用时，合并说明其数据状态，并将独立卡片放入默认折叠的物理指标区域；任何可用物理指标仍直接显示。

生产入口为 [export_blade_response.py](../scripts/analysis/export_blade_response.py)，需要 replay 遥测记录所绑定的原始 OpenFAST 输出：

```bash
python3 scripts/analysis/export_blade_response.py \
  --package blender_frontend/wfrl_blender/assets/mappo \
  --output /path/to/new/blade-response
```

导出拒绝覆盖已有目录，并核对原始输出哈希、单位、时间、方位角和 T1 挠度参考。结果可随扩展或放在对应源目录的 `blade-response/` 中携带，播放不依赖原始输出路径。宿主入口为 `blender_frontend/tests/test_imbalance.py`，原生入口为 `blender_frontend/tests/blender/imbalance_regression.py`；后者支持源码或 `WFRL_ADDON_MODULE` 与 `WFRL_EXPECTED_ADDON_ROOT` 指定的安装载荷。可选 `WFRL_TEST_OUTPUT` 必须是新目录。

播放按钮和编辑预览使用 `playback.is_playing(scene)` 判断所属场景，不用 Screen 的全局播放标志推定归属。工作区后端连接绑定明确场景，遥测、来流、姿态、尾流和重绘均使用该归属；重建使用对应场景上下文，显隐操作指定所属 View Layer。切换活动场景不转移数据；每次轮询前检查归属，即使没有新消息，归属被删除或失效时也会断开并保持后端状态未确认，不自动认领其他场景。显式重连可绑定当前选中的非手动场景，保留后端会话身份与协议序号，并等待同步后重建。后端场景只配置本场景的主视口，保留其他场景、独立相机观察与重建视口的显示设置。

`panels/presentation.py` 的窗口 PNG 录制绑定发起窗口和场景。场景失效、窗口关闭、切换源场景、文件重载、撤销／重做和功能卸载均结束录制；已生成帧保留，清单标明取消或失败。清理不依赖源 RNA 仍可访问，重复结束不重复移除计时器。采样截止时刻固定在录制起点加整数倍采样间隔的网格上，每次截图后取严格晚于当前事件的下一格点；计时器送达抖动不导致漏采，迟到事件跳过已错过的格点、不补拍，清单保存每帧的实际采样时间。

`animation_render.py` 管理当前进程拥有的后台动画渲染，`animation_render_ui.py` 管理所属场景的状态和取消，`animation_render_worker.py` 在独立 Blender 进程读取冻结场景。输出位于用户选择目录下的唯一子目录，包含 PNG、场景副本、作业配置、清单和诊断输出；源相机、时间轴及渲染设置不被后台任务改写。父进程确认子进程退出后重读最终清单，联合正常退出、匹配的作业身份、`COMPLETE` 状态和完整帧数判定完成；取消和失败保留已生成帧。 工作区对分文件多视图逐帧确认每个启用视图的文件；合成立体 PNG 要求左右眼均启用。文件重载、撤销／重做或扩展卸载取消当前任务，不提供跨进程恢复。此入口输出当前场景相机的 PNG，不代替冻结变桨试验的 MP4 导出和监管。

后台动画恢复任何 `clearance_replay` 场景后，均须取得该 Scene 的有效读取器；柔性回放还须恢复其场景运行时。独立净空包缺失、不可读或校验失败时，在写入动画帧之前失败，不能把未恢复的数据驱动画面认作完整输出。

快照与输出设置在 `native_camera_views.capture_quality(scene)` 内取得，包含原始阴影、GI 和采样设置，结束后恢复观察窗口的流畅预算。工作区源码的普通 PNG 快照（含手动场景经通用 operator 调用）保留 8 位来源的位深，较高位深来源使用 PNG 支持的 16 位；转换只作用于任务配置，不改写源场景。

受控相机 PNG 输出绕过源场景的 VSE 和合成器，结束或失败后恢复其设置；后台动画仍按 File Output 前置检查执行。手动 Down 与缺陷相机使用各自归属场景，不借用活动场景的后处理结果。子进程使用任务专属配置目录；UI 和后台均递归检查合成器节点组，拒绝含未静音 File Output 节点的作业，防止场景中的额外文件输出绕过任务目录和拒绝覆盖保护。

临时隐藏相机标注只操作目标 View Layer 中实际包含的对象；被排除集合中的对象保持原状。采集完成或异常后恢复各对象原有隐藏状态。

时间读取复用 [clearance_replay.py](wfrl_blender/clearance_replay.py) 与结果包的 ReplayReader：

```text
t = segment.start_s
    + (frame_current + frame_subframe - frame_start) / timebase_fps
```

默认 MAPPO 以 `timebase_fps=60` 初始化，仿真片段为 117–177 s：40 Hz 源数据的 2401 个时刻在该默认映射下对应显示帧 1–3601。输出 FPS 改变目标播放速度，同一帧对应的仿真时刻不变；不能把 60 Hz 时间轴写成稳定 60 FPS 性能结论。

停止保留当前记录；复位到起点并暂停；单步推进 1/60 仿真秒；从头重播与片尾重播恢复播放。片尾不会添加零转速或顺桨动画。镜头切换保留时间和播放状态，不改雷达标定。云台交互通过 [cameras.py](wfrl_blender/cameras.py) 实现；MAPPO 的 `farm_flex_view` 会结束活动云台控制并清除局部相机覆盖，避免全景被旧视图锁住。

`WFRL.Camera.<机组>.Gimbal` 是对应机组的 Down 机位。`_down_mount()` 从 YawRoot 坐标 `(−3.5, −1.15, −5)` 沿 +Z 与实际机舱外壳求交，加 `(0, 0, −0.2151)` m 得到光心。yaw/pitch/roll 为 181.2°/−82.5°/175.9°，焦距 8 mm、传感器宽约 16.4224 mm；16:9 下水平／垂直视场约 91.4928°／60°，镜头偏移为零。固定相机随机舱偏航和塔顶姿态运动，保留完整画框，不随叶轮自转或追踪叶片。

`ensure_gimbal()` 对挂载标记小于 5 的相机原位恢复预设，保持对象与镜头身份；有效保存挂载保留手动姿态和光学设置。显式 Down／相机复位恢复对应预设。独立机舱与 C1/C2/C3 的传感器和复位规则分别维护。Down 切换不改回放时刻或叶片外形；有限构图、射线及后台回归不证明全周期无遮挡或现场安装安全。参数与适用范围见 [Down 说明](../docs/blender/T1Down机舱下视.md)。

`frame_change_post` 驱动读取和网格更新。工作区源码保存重开 FarmFlex 时保留保存的帧与子帧、机组、有效仿真时间基准、输出 FPS/base、帧范围与步长、同步方式和预览范围；缺少显式时间基准时保持缺键，按保存的输出 FPS/base 映射。首次载入仍按 60 Hz 时间轴初始化。重开时清除旧对象／场景指针缓存，按保存路径恢复读取器；随包 MAPPO 支持恢复到扩展数据目录。`.blend` 不会自动嵌入外部包，缺失或校验失败必须显示未就绪并清除读数。

### 5.3 遥测与 B2 数据合同

工作区后端快照可携带实际订阅 `channel_table`；通过当前运行身份检查后才发布新表。表必须由完整五字段行组成，启用字段为布尔值；整表校验通过后才替换，畸形表沿无效后端数据路径断开。未携带该字段保留已有表，显式空表或 null 清空；请求意图与控制边界生效后的实际订阅分别处理。实时卡片与安全事件只在后端归属场景显示，不清空其他场景仍需使用的全局连接数据。

工作区 FarmFlex 载入基础 B2 数据时，按原始测量重算累计读数与统计并核对保存结果；样本身份、时序、有限值和无效状态同时校验。合法空观测保留空累计与未知统计，不套用客户 READY 包的科学验收要求；文件摘要正确不能替代派生结果的一致性。校验结果随已验证源的解析缓存复用，每次载入仍完整检查源与结果摘要，双束／TLS 保留各自结果层合同。

`farm_flex.record_telemetry()` 将三机姿态及实际保存的额外通道交给 [charts.py](wfrl_blender/charts.py)，提供每通道最多 600 点的历史、曲线与 JSON 导出。变桨显示运动记录中三叶片的平均值；当前内置 v3 没有保存 `load` 通道，保持未知，不补造 B1 叶根载荷。关闭采样会冻结读数，奖励未记录。导出保留来源和单位，不代表整个物理运行档案。历史 JSON 在目标目录的独立临时文件中完成序列化、写入与刷新后再原子替换目标；失败保留已有文件并清理自有临时文件，不发布不完整 JSON。导出状态绑定发起操作的场景和作业，切换场景不转移完成或失败提示；场景被删除或文件关闭后不向替代场景写状态。在同一 Blender 进程中重新启用插件会恢复未发布结果的状态轮询。

历史按所属 Scene 独立保存；实时后端写入连接时绑定的场景，回放写入自身场景，曲线、遥测卡片和 JSON 导出读取当前场景。其他普通场景没有本场景样本时保持空白；一个回放向后寻址只清空自身历史。关闭采样保留最后采样时刻，恢复采样时若已回退，曲线与原始导出历史一起清空。曲线消息在接收时已达到其源年龄阈值的样本保留为过期断点，原始观察记录不改写。文件加载、撤销／重做和卸载释放场景历史。独立 normal／close 净空回放保存重开时恢复帧与子帧。

工作区的曲线数据缓存与 GPU 绘制资源缓存各限制为 8 项。历史追加、同一步替换、清空和训练统计更新通过版本使该场景的数据缓存失效；通道与机组选择、窗口尺寸、界面缩放和显示设置参与绘制缓存键。GPU 资源只在所属窗口绘制回调中创建，窗口／区域／场景身份隔离；关窗、加载、撤销／重做及卸载清理。暂停且状态不变时复用范围、断线分段和批次；600 点上限、未知值、单位／来源／回合分段及导出接口保持。

工作区源码的 `_read_telemetry()` 在每次加载时校验 schema、几何摘要、时间轴、机组、数组形状与有限值，将通道值保留为 NumPy 浮点数组供逐帧插值复用；重新加载独立校验，不跨加载复用数组。插值仍使用原时间轴、数值、单位和源通道，不改变可见读数或缺失通道语义。

旧 B2 模式的雷达卡片必须使用**同一条 B2 有效测量**的斜距、净空真值、估计和误差，不能把不同时间、叶片或其他光束拼在一起。误差为估计减真值；无效或过期显示缺失，不补零。读数年龄按仿真时钟计算，暂停时不随墙钟增长。

有效率分母是评估网格内预期样本；误差统计截至当前位置，整次漏测在片尾汇总。T1 当前有效率偏低，不能只展示 MAE 而省略缺测情况。数据仍是 REVIEW_ONLY；真值为仿真几何参考值，B2 是理想测距与简化算法估计，不能宣称现场精度、控制收益或数值收敛。算法与合同见 [雷达算法 README](../wfrl/lidar/README.md)。

工作区离线功率汇总显式支持 W／kW／MW，按 `1e-6／1e-3／1` 转为 MW 后求和。机组通道和历史导出保留原值、原单位、源通道及摘要；风场总量保存全部输入来源。未知单位或任一机组缺失功率时总量保持缺失，不补零或只改标签。

### 5.3.1 双束与独立 S1 数据合同

0.3.42.6 安装包包含默认 `hub-axis.v1` 与显式可选 `hub-tls.v1` 两份双束结果层及读取器，共享原 `assets/mappo/` 40 Hz 源几何。`farm_flex.py` 按 `measurement_mode=dual_beam` 接入，`panels/farm_replay.py` 提供“双束净空 / S1”“TLS 候选 / S1”与旧 B2 切换；读取及可携带打包由规范源码 `wfrl/lidar/dual_beam_replay.py`、`dual_beam_package.py` 负责，构建时生成扩展内置副本。

S2/S3 按同一保存时刻、同一叶片的有效命中配对，S1 有效叶片命中独立报警，不能用双束无效来抑制 S1。读数、报警和累计历史共用仿真时钟，寻址不重复累计；无效值保持缺失。可携带包包含自身 `source/` 并校验完整源数据及结果摘要，移走后不依赖开发机绝对路径。损坏或缺包须清空旧状态。

固定 MAPPO 源的双束完整过叶统计：

| 机组 | 完整过叶次数 | 每次是否存在 S2/S3 配对 |
| --- | --- | --- |
| T1 | 33 | 全部存在 |
| T2 | 33 | 全部存在 |
| T3 | 28 | 全部存在 |

合计 **94/94 次完整过叶、400 个有效配对采样点**；每次完整过叶至少有连续 3 个保存采样点配对。该口径基于 40 Hz 保存几何，不要求每帧命中，不包含片段边界的不完整过叶，也不要求 S1 在正常片段保持静默。原包实际安装的双束后台回归通过，覆盖标定、配对、独立 S1、寻址、FPS 映射、换机、保存重开、缺包清除和旧 B2 重载；不是现场或完整片段性能验收。

10°/12°/14° 是当前仿真安装角。TLS 是轮毂约束直线候选，只改变方向估计：在同一开发片段 400 对上，旧法与 TLS 的 MAE 分别为 4.268685 / 0.776096 m；独立单机固定 9 rpm 工况、40/80 Hz 网格的 TLS MAE 约为 0.943/0.970 m。两种方法仍为 REVIEW_ONLY / PENDING_ACCEPTANCE，不据此切换默认，也不构成现场性能验收。诊断、独立工况与评分口径见[候选总报告](../docs/lidar/双束TLS候选实施与验证总报告.md)，0.3.13 当时的安装验证见[0.3.13 发布核对](../docs/blender/releases/0.3.13发布核对.md)。

### 5.4 独立 normal／close 雷达包

独立入口为 [open_clearance_demo.py](../scripts/blender/open_clearance_demo.py)，需要工作区的 `dist/lidar-delivery.json` 清单及其指定的 `normal-v1.1`、`close-v1.1` 两个完整外部包，输入分发见[分发说明](../docs/PUBLICATION.md)。清单或结果包缺失、损坏时清空读数并报错；已有演示 `.blend` 缺失时会重建场景。该入口使用工作区源码，不替换已安装扩展。

`clearance_replay.load(scene, path, demo)` 校验机组、尺寸、标定及片段身份，退出现有柔性回放并建立对应读取器。“正常测量／较小净空”切片后从起点播放；“测量区侧视／风场总览”仅切镜头。这两段画面是刚性姿态示意，后端数值包含柔性形变，不能把这句话套用到三机 MAPPO 网格动画。

此独立路径采用固定全局塔原点与刚性塔假设，现有生产脚本要求零偏航；不是任意父级旋转、缩放或浮式机组的通用坐标变换。三机 MAPPO 使用其独立的偏航与形变数据合同。修改相机方向不会改变任何一条路径的物理标定。

### 5.5 实时连接与控制生命周期

项目侧 [wfrl_launcher.py](../scripts/blender/wfrl_launcher.py) 负责环境预检、所属 Bridge 进程树与 Blender 生命周期；[launcher_state.py](../wfrl/blender_bridge/launcher_state.py) 隔离启动器归属记录与 Bridge 会话声明。[wfrl_blender_bootstrap.py](../scripts/blender/wfrl_blender_bootstrap.py) 导入 `bl_ext.user_default.wfrl_blender`，写入路径配置、加载默认 MAPPO，并在用户主动连接后加载 YAML，不改写进程归属或停止凭据。

扩展 [runtime.py](wfrl_blender/runtime.py) 和 [transport.py](wfrl_blender/transport.py) 维护连接、协议状态与回传。[panels/status.py](wfrl_blender/panels/status.py) 管连接与诊断，[panels/run.py](wfrl_blender/panels/run.py) 是唯一后端运行按钮入口。CONNECTED 表示握手；实际运行还需 READY 后显式 Start，并观察 RUNNING 与不断更新的真实快照。

工作区规范协议对 snapshot 和 curve 的 `rotor_speed`、`yaw`／`pitch`、`power` 分别要求 `rpm`、`deg`、`MW`，有效或无效记录的单位不匹配均直接拒绝，不原值换标签。尾流保留源年龄与单调接收时间，按协议的 5 秒阈值判定过期；无效、等待、过期、断连及任务切换撤销旧 DisXY 有效显示，携带不匹配 `run_id` 的迟到尾流不覆盖当前数据，无 run 标识的兼容消息不能据此区分旧运行。DisXY `shape` 的每一维须为正整数（接受整数值浮点数），小数、字符串与布尔值直接拒绝，不截断换算；各维乘积须等于 `values` 数量。新有效样本恢复显示时保留用户可见性设置，包括过期期间的 DisXY 显示开关选择及各 View Layer 的原有隐藏状态；切换其他图层开关不改写这些设置，场景侧栏也不能重新显示无效结果。首次创建 DisXY 网格时尾流材质加载失败不阻断显示：网格照常创建并随后续样本更新，错误写入运行状态的 `error`，连接与尾流有效性不变；同一异常类型与消息只打印一次 traceback。

同一 Blender 进程打开其他 `.blend` 时，已认领的后端会话保留客户端、会话身份及协议序号，连接标为断开且未确认；旧场景的姿态缓存和待确认命令清空。保存的离线回放可以独立恢复几何、读数和位置，不据此认定后端已停止。显式重连使用保留的会话恢复握手，确认前禁用后端运行和配置操作。这些恢复凭据只在当前 Blender 进程内保留，不写入 `.blend`，不保证退出 Blender 后恢复活动后端。

工作区源码的 **连接新后端身份…** 仅在已断开且保留旧身份时可用。用户须在确认框勾选放弃旧连接；此操作只清除本地恢复身份，不停止旧后端或将其状态标为已停止。最近的旧会话、作业与最后状态保存在诊断中，仍标为未确认。普通 Connect / Reconnect 继续恢复原身份；`UNKNOWN_SESSION`／`RESUME_REQUIRED` 握手拒绝不会自动认领新会话。

0.3.42.6 扩展包含前端连接、协议和运行状态处理；后端服务器、训练启动器和 MPI 环境不随扩展 ZIP 安装。后端 [backend_session.py](../wfrl/blender_bridge/backend_session.py) 只在新的控制步边界处理暂停和单步，预热或重复第 0 步的进度通知不能重复消耗单步许可。[server.py](../wfrl/blender_bridge/server.py) 在接收新连接前回收已有连接的 EOF，允许断开后立即重连，同时保留活动客户端独占。

当前后端源码的 `BridgeServer.poll()` 即使没有客户端也调用 `BackendSession.tick()`，继续读取训练进度、检测退出与失败并清理已结束会话的临时资源。快照保留最新状态，训练统计可以按类型合并；`lifecycle`、`safety_event` 和 `error` 使用独立有界可靠队列，不被统计挤出。可靠队列真实溢出时报告 `EVENT_OVERFLOW`、进入 `FAILED` 并停止会话，不静默丢弃。重连恢复当前状态、各类最新统计及仍保留的可靠事件，并计入等待期间的数据年龄；不承诺补回每个观察样本或完整观察历史。

工作区 `hello_ack` 与 `lifecycle` 使用可选的非负整数 `state_revision`。`BackendSession.synchronization_state()` 在生命周期锁内取得状态、版本、作业、场景与通道元数据；握手版本覆盖的历史生命周期只进入前端最近 256 条 `backend_events` 诊断，不回退当前状态、作业、场景或仪表盘。握手之后的新生命周期必须具有递增版本并遵守状态迁移约束，可靠的安全与错误事件继续单独处理。工作区 Bridge 在命令拒绝中携带原命令序号；前端只用匹配的拒绝结束待确认命令。待确认期间收到无命令序号的拒绝时，前端断开连接并要求重连同步。无版本生产端保持严格迁移校验，不能据此安全识别重连历史；完整恢复语义需要匹配的 Bridge 源码及前端构建，既有公开 ZIP 与日常安装不自动获得这些源码行为。

清理合同使用成对布尔字段 `cleanup_confirmed` 与 `worker_alive`。清理确认要求任务处于 `READY`／`STOPPED`／`FAILED`、没有存活任务且排空线程已结束；失败结果与清理状态分别保留。清理完成但任务结果不变时，仍发布递增的生命周期版本。前端在清理未确认时禁止重新启动、复位及重配，并允许对未清理的失败任务重试 Stop。Stop 可以抢占尚未确认的 Pause／Step；迟到的暂停生命周期与快照不解除停止等待。其他动作继续等待对应的后端确认与新控制边界。

工作区 `hello_ack.last_command_sequence` 报告后端已接受的命令序号，未收到命令时为 `-1`。启动器停止重试使用该水位的下一序号；前端恢复时取本地已发送序号与后端水位的较大者，保留序号空间及严格递增校验。无该字段的兼容服务无法提供跨控制器的命令水位同步。

Formal CLI 由 `formal_process.py` 跟踪本机进程身份，包括已观测的后代及继承独立运行标识的脱离父进程；停止按 PID 与创建时间对应的身份发信号，不按进程名清理。主启动器退出后仍有所属进程时，Bridge 在轮询中报告失败并执行收尾，所属进程存活时清理保持未确认。该本机监管路径仍须在目标 MPI／FAST.Farm 环境核验，不据普通 Python 反例宣称真实求解已验收。

实时全场功率要求同一步的全部预期机组都有有限标量读数，且合计有限；任一缺测或无效都使全场值保持 `null / invalid`，通道完全未返回时为 `unsupported`。有效机组自己的功率仍可显示，真实零功率仍有效，不能以部分合计或补零掩盖缺测。Interactive 在 POSIX 平台经 `IsolatedTrainer` 和 `trainer_worker` 进入 Studio Trainer 的共享 actor、集中式 critic 路径；Formal Training 使用独立训练入口。迭代统计完整性与目标定义见[训练入口与合同](../docs/training/MAPPO_SETUP.md)。

工作区源码要求场景控制步长为有限正数、机组坐标为有限数。`scene.load` 在替换会话场景、清空观察或发布 READY 之前，验证候选场景与规范协议的完整序列化；被拒绝的候选保留原场景、观察和连接。未发出首字节的观察消息仅在 socket 可写时更新累计年龄并编码；已部分发送的帧保持不变，可靠事件与观察的队列规则保持。模式切换对动画、隐藏状态和回放历史的清理限定于当前 Scene 及其受管集合，仍拒绝操作被其他 Scene 共享的规范资源。

项目侧 Replay 从 checkpoint 的动作合同读取控制顺序、变换与边界，并校验观测、机组及运行时兼容性。Studio / Interactive 的 `tanh_scale` 与 CLI 高斯 yaw 策略的 `clip` 分别保留；单控制量不作为选择变换的依据。可识别的无版本模型按保存格式校验，元数据缺失或冲突时明确失败。[动作合同与兼容范围](../docs/training/MAPPO_SETUP.md#策略动作与-checkpoint)属于项目 Python 后端，更新后须重启 Bridge，不表示扩展安装包或既有模型的物理控制效果已验收。

Interactive 的 **Episode steps** 对应 `episode_steps`：`0` 保持单长回合，正值指定每回合训练控制步数；每回合独立预热，预热不占 `iters * n_steps` 的训练预算。快照顶层的 `payload.episode` 区分从零编号的回合；全局 `step` 不倒退，但相邻回合的结束与预热记录可以共享同一步号。曲线保留两个回合的边界点，同一回合、同一步号的修正记录替换该点。兼容输入仅在顶层字段缺失时读取 `context.episode`；显式顶层值优先，包括 `0`。仿真时间允许回零，遥测曲线在回合或时间边界断线，训练统计继续保留。[回合与 GAE 规则](../docs/training/MAPPO_SETUP.md#interactive-的采样与更新)由后端实现；配置面板和曲线变更需匹配的扩展安装载荷。

[isolated_trainer.py](../wfrl/blender_bridge/isolated_trainer.py) 的 `launcher_environment()` 移除继承的 OMPI/PMI/PMIX/OPAL/PRTE 作业身份变量，只保留 `OMPI_MCA_btl`、`OMPI_MCA_pml` 及各自以下划线连接的传输配置子项。macOS 未显式设置 BTL 时默认 `self,tcp`；未设置 TCP 接口 include/exclude 时默认 `lo0`，保留调用方的显式传输选择。后端源码需在重启 Bridge 后生效，重新安装扩展 ZIP 不会更新服务器或 MPI 环境。

实时 `rotor_speed` 当前由功率／效率／转矩／齿轮比推算，保留 SYNTH 与 `FastFarmDriver._rotor_speed` 来源；yaw、pitch、power、torque 的 DIRECT 标签不能推广到所有通道。离线 MAPPO 使用保存的转速记录。真实后端场景与随包随机阵风记录属于不同运行。

工作区 G 描述符与正式 RGB 共同使用独立 HFOV／VFOV、整数画幅、K／P 和 evaluated pose；A 原生渲染按同一完整视场临时设置像素比例，并在成功或失败后恢复设置。冻结签名包含完整 `CameraParameters` 与槽位身份；输出记录 K／P、实际姿态和画幅。非自定义相机保留原生 `view_frame()` 分支。曝光子样本只在 render 返回 FINISHED 且本次新建 EXR 可读时累计，取消不会复用旧样本或写成功帧记录。

## 修改、安装与验证

`verify_frontend_completion.py` 在 `WFRL_ACCEPT_OUTPUT` 根目录下创建独立 `run-*` 子目录，并把该绝对路径传给验收脚本。成功只依据该次运行生成的 `report.json` 与前后端退出结果，已有目录中的其他报告与日志保留。POSIX 要求 Bridge 退出码为 0；Windows 停止 Bridge 时退出码可能非零，改为要求启动进程均已退出，且按本次输出路径认领的进程清理状态为 `EMPTY_CONFIRMED`。常规源码回归使用 `scripts/blender/run_regressions.py` 的新目录、源码身份、完成标记和最终结果校验。

测试或检查流程启动的工作区源码 Blender 子进程在加载工作区模块前设置 `sys.dont_write_bytecode = True`，由宿主守卫测试 [test_blender_subprocess_bytecode.py](tests/test_blender_subprocess_bytecode.py) 检查。

PYTHONDONTWRITEBYTECODE=1 python -m pytest blender_frontend/tests/test_static_names.py -q -p no:cacheprovider` 单独运行。

维护修改应作用于规范源；`protocol.py` 来自 `wfrl/blender_bridge/messages.py`，内置 `_vendor/lidar/` 读取器来自 `wfrl/lidar/`。不要手改生成副本或替换冻结模型及正式资产来消除校验失败。

扩展源码（`_vendor/` 与 `assets/` 除外）的文件系统文本读写显式使用 `encoding='utf-8'`，包括 `Path.read_text`、`Path.write_text` 和文本模式 `open`，不依赖平台默认编码；宿主测试 `test_text_io_encoding.py` 以 AST 扫描强制该约定，二进制读写及 `os.open` 不在范围内。JSON 结果与状态文件统一通过 [atomic_json.py](wfrl_blender/atomic_json.py) 的 `write_json(path, value, *, mkdir=False)` 写入：按 UTF-8、`ensure_ascii=False`、`indent=2`、`allow_nan=False` 和末尾换行写出。已编码的姿态 JSON 等文本使用同模块的 `write_text(path, text, *, mkdir=False)`，按 UTF-8 保留原字符串，不追加或转换换行；调用方可将其导入为 `write_atomic_text`，与文件系统文本 API 区分。两个接口共用目标目录内的随机临时文件、`flush`、`fsync`、`os.replace` 与失败清理逻辑；Windows 上目标文件被其他句柄占用而 `os.replace` 抛出 `PermissionError` 时，按 0.05／0.1／0.2／0.4 s 退避最多再试 4 次，仍失败则抛出原异常并删除临时文件，POSIX 不重试；临时文件以 `os.open(..., 0o666)` 创建，新文件权限按进程 umask 确定，与普通文本写入一致，覆盖已有普通文件时保留其权限位，不修改进程 umask；需要保密的作业文件由其所在的 0700 目录限制访问；仅需要创建父目录的调用方传 `mkdir=True`。`manual_video_job.py` 与 `manual_video_render.py` 作为独立脚本运行时按同目录文件加载该模块，不导入扩展包入口。

python3 scripts/blender/build_extension.py --output <新目录>
python3 scripts/blender/validate_frontend_package.py --output <新目录> --blender <Blender可执行文件>

构建生成 ZIP、SHA-256 与逐文件 inventory，默认拒绝任一同名产物已存在的输出，包括断符号链接。使用新目录保留各包身份；明确需要替换时使用 `build_extension.py --output <目录> --overwrite`。文件在同一文件系统的临时目录中完成后逐个发布，ZIP 最后发布；普通发布异常恢复原产物，恢复冲突保留备份并报告位置，不保证断电或进程强制终止时三文件整体原子性。验证工具默认构建、隔离安装并执行后台检查；`--build-only` 仍会构建 ZIP。包验证在所有平台拒绝 inventory 中的绝对路径、`..`、反斜杠、驱动器前缀、`<>:"|?*`、以空格或点结尾的路径分量及 Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`，不分大小写与扩展名），并按 `casefold()` 判定重名。纯文档任务仅检查格式、引用、身份与要求一致性。

`build_farm_flex_delivery.py` 的自定义风场交付按源 manifest 身份选择结果载荷：规范源保留匹配的叶片响应、同源纹理及默认双束／TLS；其他来源不继承这些固定源结果。显式提供的双束结果仍须与自定义源完整匹配。同源纹理入口只有在场景源身份匹配且载荷存在时可用，已经激活的纹理仍可退出到几何模式；省略结果不表示其精度通过。

同源纹理首次导入按事务登记新建对象、网格、镜头、材质、图像、动画和文本等资源。失败时恢复场景元数据并回收无外部用户的自有数据，保留预存数据、其他场景引用及用户保留的资源；回收失败保留显式登记供重试，不执行全局孤立数据清理。

ZIP 包括 MAPPO 源、旧法和 TLS 结果层、规范示例、NREL 缺陷编辑器及生成的协议／读取器。公开 0.3.18 源码的复建结论仅属于该版；本地载荷、公开附件和已安装文件必须分别匹配 inventory 与 build-info，不用 Git 提交或版本字符串替代。

按[维护与验证入口](../.agents/skills/windfarm-blender-dev/references/verification.md)选择宿主、后台、窗口与隔离安装检查。源码导入不证明安装版正确，后台通过不证明可见交互或物理精度。每项测试记录实际模块、输入、环境、输出和终止状态。

[自动检查](../docs/development/自动检查.md)说明 GitHub Actions 的触发条件、宿主依赖、后台回归选择及本地复用命令。README 的发布身份摘要由交付与安装记录生成；`scripts/ci/check_release_identity.py` 默认只检查，显式 `--write` 才同步标记内的摘要。

工作区源码的 [performance.py](wfrl_blender/performance.py) 默认关闭，仅在启用后汇总 CPU 回调耗时与工作量。`flex.deformation_cache` 计时位于 `deformed_at()`，包含缓存查询、命中返回及未命中计算；`flex.rebind_blade` 独立计时。`flex.cache_hit` / `flex.cache_miss` 记录源帧形变缓存，`flex.update_cache_hit` / `flex.update_cache_miss` 记录同刻几何缓存；`flex.mesh_writes_skipped` 记录已核对原生坐标而跳过的写入。`flex.participating_turbines`、`flex.blade_updates`、`flex.vertices_written`、`flex.tower_vertices_written` 和 `flex.measurement_points` 分别记录参与机组、实际整叶写入、实际塔筒写入及隐藏叶尖采样工作量。计时可嵌套，不能相加推算总帧耗时，也不能把计数或后台耗时换算成视口 FPS。

`performance` 的 X100／相机入口包括 `x100.validate`、`camera.render_group`、`camera.simulation_state_hash`、`camera.snapshot_readback` 和 `camera.write_png`。通过 `performance.configure(True)` 显式开启，`performance.snapshot()` 读取计数、总量、最大值和均值；不存逐帧历史或声称已有p95／p99。`snapshot_readback` 包含图像快照工作，不能当作GPU硬件专用计时。同步取样校验复用、窗口重绘、RotorClock参数原子性以及相机保留现有架构的依据见[独立优化与测量范围](../docs/blender/发布状态与验证范围.md#独立优化与测量范围)。

播放基准保留原始墙钟观察时长和帧率分母，另列主动暂停、扣暂停后的运行观察和停滞时长；场景与各路推进间隔均扣除经过验证的主动暂停，汇总保留暂停区间。`peak_rss_mib()` 将 Linux 的 KiB 和 Darwin 的 bytes 统一为 MiB。历史峰值之差不代表当前驻留内存增长，也不能证明无泄漏。

`runtime.py` 保持 50 ms 的后端轮询预算，在消息、姿态、连接／控制状态、遥测有效性或异步结果变化时请求刷新对应场景。训练数据年龄按整秒刷新，并保留各通道独立过期边界；过期不依赖新消息到达。原生播放和手动运动负责自身画面，空闲轮询不额外刷新全部视口。

完整播放需要每路推进与终段证据；超时、缺绘制、错误和意外回跳不能判为通过。`POST_PIXEL` 是视口绘制回调，不是显示器扫描输出。近两秒采样、GPU 事务复用、固定 60 Hz 时间轴和暂停时稳定刷新均不能替代完整片段 FPS。

### Windows 支持范围

- 冻结试验视频的新建、重试和监管只支持具备 `flock` 和 `waitid(WNOWAIT)` 的 POSIX 环境。见 [`launch()`](wfrl_blender/manual_video.py#L344)、[`start()`](wfrl_blender/manual_video_job.py#L232)、[`supervise()`](wfrl_blender/manual_video_job.py#L319) 和 [`require_supervision()`](wfrl_blender/manual_video_job.py#L35)。
- Down 的 MP4 与 JSON 成对发布、扩展构建产物发布均依赖硬链接，目标卷需支持硬链接。见 [`_publish_pair()`](wfrl_blender/manual_down.py#L481) 和 [`_publish_outputs()`](../scripts/blender/build_extension.py#L55)。
- `.command` 和 macOS shell 入口只适用于 macOS。见 [`.command` 入口示例](../scripts/blender/打开净空雷达演示.command#L4)、[`run_wfrl_macos.sh`](../scripts/blender/run_wfrl_macos.sh#L1) 和 [`verify_macos.sh`](../scripts/blender/verify_macos.sh#L1)。
- 非 POSIX 平台查询已有冻结作业时不检查本地监管租约；监管端点不可达且没有匹配终态时报告 `LOST`、`active=False`，不阻挡 Down 导出，也不改写磁盘记录。
- 已有 MP4 导出在 Windows 上按设备、inode、大小和 mtime 判定源文件身份，不比较 ctime；POSIX 另比较 ctime，以发现保留 mtime 的内容修改。
- Launcher 在 Windows 上以 `CREATE_NEW_PROCESS_GROUP` 启动并发送 `signal.CTRL_BREAK_EVENT` 请求停止，接收进程须与发送者共享控制台。
- [.gitattributes](../.gitattributes) 对 `wfrl_blender/assets/` 与 `wfrl_blender/_vendor/` 关闭换行转换，保证检出字节与完整性摘要一致。
- 宿主测试的 venv 路径、Python 工具夹具和符号链接辅助位于 [tests/_platform.py](tests/_platform.py)；无法创建符号链接时相关用例跳过并附原因。
- Windows 上的前端宿主测试在 `windows-host` 任务中非阻塞运行。见 [Windows 前端宿主检查](../docs/development/自动检查.md#windows-前端宿主检查)和[工作流任务](../.github/workflows/checks.yml#L165)。

## Blade Recon 与重建对照

外部 `blade_recon0.2` 提供研究算法，扩展只读取已保存结果，不在查看时拟合。材料点候选独立结果为 Patch **2/8**、Crack **7/8**（87.5% < 90%）、跨相机 RGB **0/264**，真实同材料点三维误差 `null`，保持 `FAILED_GATE / NOT_ACCEPTED`。数据与限制见[材料点对应研究](../blade_recon0.2/docs/材料点对应实验报告_2026-10-11.md)；该研究没有替换扩展正式 601 样本资产。

“叶片三维重建”标签与 MAPPO 页共用完整风机几何／同源纹理入口。扩展默认注册只启用共享显示属性和同源重建运行时；独立算法研究导入由显式脚本管理，不自动恢复单独叶片场景。`blade_recon_review.py`、`blade_recon_surface.py` 和 `blade_recon_inspection.py` 保留算法读取、网格、纹理与观察工具。打包仅交付同源重建资产，独立合成样例及其分屏适配器不进入扩展载荷。

统一入口 **MAPPO → 打开几何重建示例…** 使用 `assets/examples/mappo_reconstruction_split.blend`，在同一完整风机分屏切换几何／同源纹理。右侧塔筒、机舱、轮毂与机械细节共享源 T1 结构，只有三片叶片属于重建估计。`split_turbine_context.py` 独立管理共享结构的变换与可见性，T2/T3 选择不得隐藏右侧结构。

整机取景使用塔筒、机舱与三叶片的完整范围；退出右侧相机后，绕转枢轴位于对应显示坐标系中的源 T1 转子中心。两侧可用画布宽度计入侧栏占用，手动近景不因播放或侧栏展开而重新对准运动中的材料点。

`split_reconstruction.py` 管理布局生命周期，`split_reconstruction_timing.py` 定义固定映射，`split_reconstruction_ui.py` 提供统一控制与左下角 HUD。601 个保存状态来自 10 Hz 重建，使用固定 60 Hz 时间轴，每个样本保持 6 帧；MAPPO 源为 40 Hz。两侧共同播放、暂停、步进与循环。

当前源码的 `split_mappo_texture.refresh()` 复用已校验的对象与结构绑定；来源对象、网格、保存清单或摘要变化时完整校验，文件加载、撤销与重做清缓存。只在矩阵、网格或全局可见性变化时写入，不重复激活显示设置或扫描全部场景。研究用 `split_surface_texture.py` 只存在于工作区，不进入安装包；它已被导入时，`split_reconstruction` 的文件加载与撤销／重做处理同样清除其运行时会话，使其从恢复后的 ID 重新读取，未导入时不加载该模块。

中段／叶尖观察点只定位一次，手动缩放、平移、绕转后继续播放保留用户视图。右侧处于相机视图时，窗口或侧栏尺寸变化稳定后自动适配取景；播放期间暂缓，暂停后按最后一次布局执行一次，透视／正交自由视图不受自动适配影响，完整取景等显式操作照常执行。原始／增强显式切换回两侧整机；模式切换保留时刻、播放状态和有效视角。保存重开恢复当前模式、显示、时间与视角，不重放按钮取景动作。侧栏只提供完整风机几何与同源纹理。

便携场景保存 `__WFRL_BUNDLED_MAPPO__` 与 manifest SHA-256，依据实际安装目录匹配 `assets/mappo/`，含 packed 天空／地表图，无 linked libraries。失效路径只恢复相同来源；不匹配则清空并报错，不改成任意默认包。打开入口保留 Blender 原生未保存确认，验证使用副本，不覆盖规范场景。

同源纹理为 `SAME_SOURCE_SIMULATION`，绑定来源、模型、图集与全部样本绝对时钟。embedded 数据和 packed 图片用于保存恢复。未观测 texel 保持透明；增强和放大不增加分辨率，条带、接缝、叶尖错贴与拖影如实保留。人工观察点不构成自动检测或科学精度通过。
