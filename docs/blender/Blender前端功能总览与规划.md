## 1. 平台定位与阅读方式

WFRL Blender 前端是风电场仿真的三维观察与操作工作台。它把风机结构、运动、测量结果、相机画面和运行数据放在同一场景与时间轴中，支持观察、分析、采集、导出，以及连接后端开展策略推理和训练。

平台目前主要服务于四类工作：

1. **物理结果展示**：观察风机旋转、偏航、变桨、叶片柔性形变和塔架运动。
2. **测量方案研究**：检查叶尖挠度、叶尖—塔筒净空、雷达安装和报警逻辑。
3. **相机方案与数据制作**：调整三相机安装，观察叶片不同区域，输出同步图像和视频。
4. **仿真与训练操作**：连接后端、加载场景、运行策略、查看遥测和训练过程。

## 2. 系统组成与运行模式

### 2.1 前端、求解器与数据之间的关系

```text
场景配置、控制策略、风机结构和来流条件
                  │
                  ▼
        FAST.Farm / OpenFAST 后端
                  │
          ┌───────┴────────┐
          ▼                ▼
     保存的结果包       Bridge 运行回传
          │                │
          └───────┬────────┘
                  ▼
           Blender 三维前端
                  │
       ┌──────────┼───────────┐
       ▼          ▼           ▼
   结构与运动   测量和曲线   相机与图像视频
```

FAST.Farm/OpenFAST 路径承担物理仿真：依据模型中的结构参数、来流、气动、控制和结构动力学关系计算响应。Blender 负责将这些结果组织成可观察的场景、卡片和图像，不在视口中重新求解这些物理过程。

当前默认柔性回放采用 **NREL 5MW 预弯改型**，叶片结构模块为 **BeamDyn**，塔架采用 **ElastoDyn 柔性塔架**。它是有物理模型约束的仿真结果，但具体结论仍受模型、边界条件、离散采样和验证范围限制，不能直接称为实机测量。

GW184 独立项目使用另一条路径：由预设启停规律生成刚性运动，再由 Blender 成像。0.4.0 提供固定三相机与六类合成缺陷编辑；完整三路 MP4 是另行待完成的视频交付。该项目不依赖 FAST.Farm/OpenFAST，不应与默认柔性仿真混为一谈。

Bridge 后端 macOS/MPI 启动环境修复已随 0.4.0 发布同步到公开源码（`1c2b334b`）：清除继承的 MPI 作业身份，保留显式传输配置，macOS 默认回环 TCP。已配置后端需更新源码并重启 Bridge；NREL 扩展 ZIP 仅提供前端通信代码，不更新后端服务。离线 MAPPO 和 GW184 均不依赖 Bridge。

### 2.2 四种主要运行方式

| 模式 | 实际在做什么 | 是否重新求解物理 | 是否更新训练模型 | 前端主要用途 |
| --- | --- | --- | --- | --- |
| 离线 MAPPO 回放 | 读取已经保存的同一次仿真记录 | 否 | 否 | 展示结构运动、挠度、净空、遥测和三相机画面 |
| 后端 Replay | 加载已有模型，在 FAST.Farm 中重新运行策略推理 | 是 | 否 | 观察策略在指定场景中的运行响应 |
| Interactive | 连接后端开展交互训练与遥测 | 是 | 是 | 调整运行参数、查看训练及物理反馈 |
| Formal Training | 提交正式训练流程或恢复检查点 | 是 | 是 | 查看任务进度与指标；不提供逐步实时三维遥测 |

“Replay”在后端表示策略推理运行，不是默认 60 秒离线播放器。“实时回传”表示运行中的数据传输，也不保证求解速度等于现实时间。

### 2.3 整个项目的代码架构

项目包含训练研究、后端运行、Blender 展示、雷达研究和独立合成视频五部分。以下路径均相对于仓库根目录 `wind farm RL/`；文件名用于定位模块，不要求读者先打开文件才能理解职责。

| 层次 | 关键目录／文件 | 职责与相互关系 |
| --- | --- | --- |
| 风场环境与物理驱动 | `wfcrl-env/`、`wfrl/fastfarm_driver.py` | WFCRL 环境提供观测、动作和奖励接口；驱动连接 FLORIS 稳态模型或 FAST.Farm 动态仿真。两后端的时间尺度及支持的控制量需分别核对。 |
| 场景与运行约束 | `scenes/`、`wfrl/scene/schema.py`、`wfrl/scene/runtime.py`、`wfrl/safety.py` | YAML 定义机组、来流、控制和数据通道；运行层推进场景，安全层记录指令被拒绝或限制的原因。这里的规则不是实机保护认证。 |
| 强化学习 | `scripts/train/`、`wfrl/mappo_central.py`、`wfrl/mappo_sb3.py`、`wfrl/rewards.py` | 训练入口、采样与策略更新、观测归一化、奖励口径和检查点。集中式 critic 的 MAPPO 与参数共享 PPO 是不同实现路径，不能只看脚本中 MAPPO 的名称就混为同一种算法。 |
| 训练及推理执行 | `wfrl/studio/trainer.py`、`scripts/train/train_fastfarm.py` | 已有 Trainer 提供策略推理及交互训练执行逻辑；正式训练由 CLI 路径启动。复用名为 studio 的模块不表示 Blender 采用旧 Studio 界面。 |
| Bridge 通信与会话 | `wfrl/blender_bridge/server.py`、`backend_session.py`、`workflow.py`、`isolated_trainer.py`、`trainer_worker.py`、`snapshot_adapter.py` | 校验场景与运行参数，管理工作进程、状态和停止流程，将后端结果转换为前端遥测。正式训练使用进度通道，不能假定每个模式都有同样的逐步遥测和暂停能力。 |
| Blender 主扩展 | `blender_frontend/wfrl_blender/` | `runtime.py` 与 `transport.py` 处理状态及通信；`scene_builder.py` 建立场景；`farm_flex.py` 驱动离线柔性数据；`panels/` 提供操作入口；相机、原图采集、曲线及视频模块负责展示与输出。 |
| 雷达计算与交付 | `wfrl/lidar/`、`scripts/lidar/`、`configs/lidar/` | 理想首交测距、净空估计、独立评估、S1 事件、DP 字段语义处理、数据打包及校验。DP 字段解码器不是硬件总线驱动。 |
| 独立合成视频 | `projects/gw184-single/`、`scripts/blender/gw184_single.py` | GW184 尺寸目标的模型、缺陷、固定相机、预设启停和视频制作；复用部分几何工具，但不依赖 Bridge 或物理求解。 |
| 结果与验证 | `results/`、`outputs/`、`evidence/`、各模块测试目录 | 保存训练或仿真结果、检查点、安装包、测试日志及窗口截图；本地存在不等于已进入 GitHub 或安装 ZIP。 |

后端在线链路为：`Blender 操作 → Bridge → 场景/参数校验 → Trainer 或正式训练进程 → 运行层/物理驱动 → 遥测与状态回传 → Blender`。离线链路为：`已保存的数据包 → 完整性校验 → 同一仿真时刻的结构/测量/相机显示`；它不经过训练更新。默认启动脚本可以同时启动待用 Bridge 和离线播放器，连接状态为 READY 也不代表已有训练任务。

### 2.4 后端控制与算法语义

- **FLORIS 与 FAST.Farm 分开评价。** 当前规划将 FLORIS 用作稳态偏航参考，不能用它的路径证明集体变桨对动态功率和载荷的效果。FAST.Farm 路径才承担这里的动态响应研究。
- **指令不等于实际响应。** 现有场景与驱动资料中的 pitch 命令可能表示基线控制器 `PitchRef` 的下界；命令、实际桨距、来源和单位必须分别记录，前端旋转叶片不能代替物理生效验证。
- **算法名称需看实现。** `mappo_central.py` 使用本地 actor 与全局状态 critic，属于集中训练、分散执行的路径；`mappo_sb3.py` 使用共享参数 PPO。历史配置指南对后者也使用 MAPPO 名称，交接时保留这一区别。
- **训练生命周期按模式处理。** Replay 加载检查点后重新运行推理；Interactive 执行训练，当前运行校验不支持用 Replay 的检查点参数恢复交互训练；Formal Training 可从兼容检查点恢复，但不提供 Pause/Resume/Step 和逐步实时三维遥测。Stop 需要等待收尾，断开连接不能代替 Stop。
- **数据来源不可补造。** 未返回的载荷或奖励显示缺失；由功率和转矩推导的转速应保留其派生来源。实际施加动作与请求动作分开，避免把受到约束的命令当作已经执行。

以上为当前源码与项目资料的静态核对，不代表本次重新运行了在线后端、完整训练或控制响应实验。

### 2.5 研究进度与实验结论如何使用

正式研究的问题包括：动态气弹场景下的控制收益、策略记忆是否必要、以及 FLORIS 到 FAST.Farm 的迁移效果。Blender 展示、训练程序存在、已保存策略轨迹和正式研究结论应分别报告。

| 研究／工程方向 | 当前可确认的进度 | 尚不能据此得出的结论 |
| --- | --- | --- |
| 训练基础设施 | 已有 PPO/参数共享 PPO、集中式 critic MAPPO、FAST.Farm 训练入口、奖励模块、检查点与评估脚本 | 所有算法配置均已完成对照实验，或任何已有检查点都适用于新增控制量 |
| 历史偏航收益 | `docs/WAKE_STEERING_BREAKTHROUGH.md` 记录了 seed 0 确定性 rollout 的正收益案例，并标注 seed 1 当时仍在验证 | 该案例不自动成为多 seed、跨风况或跨机型的稳定收益结论。本次没有重新审计原始跑次；文中百分比与绝对功率增量也未在本次重新统一计算，故不纳入当前已确认数值指标 |
| 研究完成状态 | 2026-09-09 的 Prototype 计划仍将动态收益、记忆必要性、跨后端迁移列为待回答问题；这是该日期的规划判断 | 不能把旧规划直接当成之后所有实验的最新状态，也不能用单个历史正例宣布三个问题全部解决；需要逐项绑定最新独立评估报告 |
| 当前默认 MAPPO 片段 | 已有 117–177 s 的保存数据，可显示三机结构、偏航、功率和转矩，便于重复演示 | 该 60 秒片段不是重新开展的控制收益实验；播放、相机或雷达改进不会自动增加 RL 研究证据 |
| 4D／世界模型 | 已有三台风机、偏航与集体变桨、时序预测、有限候选和规则筛选的实施方案 | 新预测器、统一训练数据、动作条件预测与控制收益尚不能按方案文字记为已完成 |

后续研究验收应固定同一来流、初始化、预热和物理评估时长，区分训练探索曲线与评估运行，以独立 seed/工况的对照报告支持结论。预测模型按整段 episode 划分训练和评估数据，与 Persistence（沿用当前值的预测基线）比较；工程链路完成、预测有效和控制有效是三个独立验收项。现有四周计划是历史工作量估计，不是当前已执行的日程或效果承诺。

## 3. 当前模型与基础参数

### 3.1 默认三机柔性回放

| 项目 | 当前参数或口径 |

| 名义叶尖半径 | 63.0 m |

| 名义转子直径 | 126 m |
| 塔高参数 | 87.6 m |
| 轮毂中心静止高度 | 约 90 m；由塔高、塔顶至主轴距离、悬伸和轴倾共同计算 |

| 叶片／塔架结构模型 | BeamDyn／ElastoDyn 柔性塔架 |
| 默认片段 | 仿真时间 117–177 s，共 60 s |
| 原始保存采样率 | 40 Hz，包含首尾共 2401 个时刻 |
| 显示时间映射 | 60 Hz，包含首尾共 3601 帧；不是稳定 60 FPS 的性能承诺 |

### 3.2 默认三相机的分区目标

| 相机 | 观察重点 | 默认用于构图的展长范围 | 默认输出 |
| --- | --- | --- | --- |
| C1 | 叶根 | 0–18 m | 1920×1080 |
| C2 | 叶片中段 | 14–38 m | 1920×1080 |
| C3 | 叶尖 | 34–61.5 m | 1920×1080 |

三个范围有重叠，目的是为同一片叶片提供连续观察和后续算法输入。这些数字是构图目标，不是图像裁切线，也不是严格的叶片三等分。固定相机下，叶片会进入和离开视场，不能把参考姿态覆盖理解为全周期始终可见。

## 4. 已实现的主前端功能

### F01　三维风场与风机结构展示

**用途：** 建立整个风场、单台机组和局部结构之间的空间关系。

- 展示 T1、T2、T3，以及各自塔筒、机舱、轮毂、叶片和附属观察设备。
- 支持全场查看、单台机组观察及机组显隐。
- 几何来源与运动结果保持对应，观察相机切换不改变风机的物理状态。
- 地面、环境和机械细节帮助解释安装关系；装饰性细节不自动构成物理碰撞或结构求解对象。

**主要入口：** MAPPO 场景及“工具 → 机组、视角与云台”。

### F02　叶片与塔架柔性运动

**用途：** 观察风机结构随运行发生的变形，而不仅是刚性旋转。

- 九片叶片分别使用对应的柔性运动数据，不用一片叶片的形变复制所有叶片。
- 三台塔架分别显示弯曲和塔顶运动。
- 机舱、叶轮以及依附结构的雷达和相机随安装结构运动。
- 默认物理回放保留原始运动幅度，不以夸张放大代替真实数值。

**边界：** 当前已经有塔架弯曲展示，但不应据此宣称已有与叶尖挠度页同等完整的塔架专用虚影、位移箭头和数值分析页。

### F03　离线物理结果回放与统一时间轴

**用途：** 在无需运行求解器的情况下反复观察相同仿真结果。

- 加载默认 60 秒 MAPPO 片段。
- 播放、暂停、单步、进度定位、复位和从头重播。
- 结构姿态、测量卡片及累计统计按同一仿真时刻查询。
- 仅切换视角时保留进度和暂停状态；重新加载工况按对应入口重置。
- 区分源数据保存时刻和显示插值时刻。

**边界：** 播放不会更新训练模型，也不会因拖动时间轴重新求解物理。暂停不会使风机物理状态自动变为停机或顺桨。

### F04　叶尖挠度分析

**用途：** 解释叶片形变有多大、沿什么方向，以及前端恢复坐标与源仿真输出是否一致。

- 当前分析页针对 T1，可选择叶片 1、2、3。
- 显示同刻未受载参考、实际结构叶尖、总位移及当前 v3 根系 x/y/z 三分量；旧双分量数据才使用面外／面内标签。
- 当前 v3 参考来自独立零载荷静止求解，随塔顶整体运动及叶轮姿态更新；根系 xyz 随变桨表达，使叶片挠度与塔架整体位移分开解释。不能把已经变形的首帧当作未受载参考。
- 对照“源仿真输出”“坐标差重建”“两者残差”。位移使用 m，部分残差使用 mm。
- 源仿真没有对应输出的分量不伪造零误差对照。

**主要入口：** MAPPO → 挠度。

**边界：** 毫米级重建残差只说明同源数据与坐标恢复的数值一致性，不代表实体相机或雷达具备毫米级测量精度。

### F05　叶尖运动轨迹

**用途：** 观察叶尖经过的空间路径和相邻转动周期的运动差别。

- 各叶片轨迹分别显示，便于识别不同叶片。
- 轨迹跟随当前显示的变形叶尖采样，不是实体传感器观测。
- 暂停后停止新增轨迹点；寻址、重播或换机组按规则清空并重建历史。
- 轨迹辅助物可隐藏，避免遮挡相机原图和演示主体。

**边界：** 彩色轨迹使用的显示网格叶尖与挠度分析的结构参考点定义可能不同，不能直接要求两者完全重合。

### F06　虚拟雷达、单束估计与净空对照

**用途：** 把雷达斜距、叶尖位置和塔筒净空这几个不同概念放在同一场景中观察。

- 显示雷达本体、安装件和光束方向示意。
- 原有模式以 B2 光束的有效测量作为主卡片来源，展示斜距、净空估计、同口径仿真参考及偏差。
- 误差符号定义为“估计 − 参考”；正值意味着高估间隙。
- 提供雷达特写、测量区域侧视，以及独立正常／较小净空工况入口。
- B2 无效时不借用其他光束或真值补齐。

**边界：** 可见橙线用于解释不可见光束的方向，其长度和末端不是测距读数。不同结果包的净空参考点与表面定义必须按该包说明读取。

### F07　测量状态、阈值与统计

**用途：** 判断读数是否新鲜、是否有效，以及当前片段中的误差和漏测情况。

- 区分新测量、保留的历史读数、等待、过期、无效和数据未就绪。
- 按结果包的阈值、滞回和读数保持规则显示原有测量状态。
- 统计有效样本比例、误差、叶片经过情况和整次漏测。
- 暂停时仿真读数年龄不因现实等待而增长；后退和重播不能重复累计或展示未来事件。
- 缺失值不显示成零净空、零误差，也不自动代表发生危险。

**边界：** 原有 B2 数值阈值规则与新增 S1 命中即报警规则是两种机制，不能混用。统计窗口内的覆盖率也不是设备精度或保护安全通过率。

### F08　运行参数、历史曲线与数据导出

**用途：** 将三维运动与机组运行数据对应起来。

- 展示各机组偏航、平均桨距、转速及已有功率、转矩等通道。
- 查看单机或风场汇总数据，选择机组与曲线通道。
- 可暂停遥测采样；关闭采样后读数和曲线冻结，不填充虚假零值。
- 当前历史按每机每通道最多 600 点保留，可导出包含单位、来源的 JSON。

**当前数据核对：** 随包 `telemetry.json` 的独立通道为三台机组的功率 `GenPwr` 和转矩 `GenTq`；偏航、桨距和转速另由回放状态提供。界面支持某个载荷或奖励字段，不等于默认结果包实际记录了该字段。没有数据时必须显示缺失或不支持。

### F09　多种观察视角与左右分屏

**用途：** 同时理解总体运动和局部测量关系。

- 风场全景、T1/T2/T3 下视、机舱观察、T1 侧前方、顶部和侧面。
- 叶尖、叶轮、测量区侧视及雷达安装特写。
- 左右分屏支持“Down + 侧前方”和“机舱 + 侧前方”。
- 两侧共享场景和时间轴；可调整分隔宽度并恢复单屏。
- 切换视角不更改雷达标定、已保存运动或控制策略。

**验证状态：** 2026-09-28 的源码版和本机已安装扩展均已有窗口回归 PASS，覆盖 Down + 侧前方、机舱 + 侧前方、重复点击复用分屏、播放中切换、恢复单屏及暂停状态保留。证据为 `outputs/t1-split-20260928/source-final/result.json`、`installed/result.json` 和 `live-result.json`。这些是该轮 Blender 5.2.1 LTS 窗口与状态检查，不代表跨平台或后续所有版本均已重新执行同一回归。

### F10　机舱云台交互

**用途：** 用直观操作调整观察方向和视场。

- 视图内拖动改变朝向，滚轮调整视场，摇杆持续转动。
- 提供 Down、Front、Back、Reset 等方向或复位入口。
- 观察相机保持与机舱的安装关系，并随相应结构运动。

**边界：** 相机 Pan/Tilt/Roll 是观察姿态，不是风机偏航或桨距命令。云台交互不等于自动叶片追踪。

### F11　三相机与共用盒体安装

**用途：** 检查三个相机如何安装在同一机舱上，以及安装位置对观察效果的影响。

- 创建 C1、C2、C3 及共用盒体、支架。
- 通过点击机舱表面选择安装位置，调整贴面旋转和盒体转向。
- 三台相机随盒体一起刚性移动；可在高级设置中使用自由坐标。
- 进入调整时使用可确认或取消的预览；取消恢复原布局，整套变化支持撤销。
- 对当前模型中的安装约束和穿入情况进行检查。

**边界：** 表面贴合和几何避碰不等于实际支架强度、开孔、载荷、制造或安装认证。自由坐标调整可能解除贴面关系。

### F12　同一叶片的根部、中段、叶尖分区观察

**用途：** 用三个固定相机覆盖较长叶片，并给相邻画面保留公共内容。

- C1、C2、C3 分别以根部、中段、尖部为观察重点。
- 允许相邻区域重叠，不要求三等分，也不禁止 C2 画面出现叶尖。
- 调整取景时保留机舱、根部连接件、其他叶片和自身遮挡。
- 已有安装候选和多旋转相位的覆盖比较工具。

**边界：** 投影在画幅内不等于表面没有遮挡；相邻画面有重叠不等于拼接算法已经成功；固定相机不保证全周期始终看到整片叶片。

### F13　三路同步观看、2×2 布局与单路放大

**用途：** 在一个观察窗口中清楚比较三路同一时刻的画面。

- 独立三相机窗口，共用同一场景和仿真时间轴。
- 当前支持默认 2×2 布局，三列布局保留为备选。
- 2×2 的三格显示 C1/C2/C3，第四格是静态安装位置示意。
- 支持单路放大及返回三路，保持相机参数、进度和暂停状态。
- 单路观察和三路内放大固定使用轻量实体视图，保留材质颜色，不计算实时材质光照；返回三路恢复其原画质。
- 保留完整画幅及真实宽高比，允许留边，不通过裁掉原视场填满界面。

**边界：** 第四格不是第四路实时相机。同一仿真时间的数据同步不等于三个屏幕区域在显示器上绝对同时扫描呈现。

### F14　相机参数、布局保存与恢复

**用途：** 让相机方案可以修改、比较、保存和复现。

- 分别调整各路方向、视场和输出尺寸，并保留其他相机的参数。
- 记录布局备注及是否参与预览、采集。
- 导出布局 JSON；导入时查看当前布局与待导入布局的替换摘要。
- 校验模型和布局兼容性，支持撤销、取消和默认布局恢复。
- 盒体位置、完整方向、贴合关系和相机参数作为关联配置保存。

**边界：** 布局 JSON 保存相机安装方案，不包含一套新的物理仿真。完整布局导入会替换相应槽位，应以导入摘要为准。

### F15　三路相机原图与时间序列采集

**用途：** 为图像算法输出与仿真时刻一致的相机数据。

- 采集当前时刻，或指定时间序列。
- 每个时刻以同一场景状态生成各相机图像。
- 输出原始完整画面，不包含 Blender 操作界面和视锥辅助标记。
- 保存相机内参、外参、时间戳和数据来源信息。
- 支持取消和异常恢复，避免采集后遗留临时画质或时间设置。

**边界：** 这里的“同步”指同一仿真状态，三路可以依次离线渲染；不是对三个实体相机的硬件触发同步验证。

### F16　画面质量、环境与示意尾流

**用途：** 根据演示或检查需求调整可读性和显示成本。

- 三路提供流畅／高清材质预览；单路固定轻量实体显示，无画质切换或精确材质预览按钮。
- 三路观察时降低主窗口的重复显示负担，退出后恢复相关设置。
- 环境、光照、地形、天气和尾流示意的显示控制。
- 原图采集按自身设置恢复所需质量，不直接把低质量预览当作最终图像。

**边界：** 当前 MAPPO 中的尾流样式是视觉示意，不是 FAST.Farm 实际三维流场。修改天气、地形或尾流显示，不会改变既有仿真片段的输入条件。

### F17　演示模式、截图、窗口录制与渲染入口

**用途：** 制作说明材料，或记录当前操作过程。

- 演示／开发模式切换，可隐藏编辑工具栏和操作手柄。
- 保存可见窗口 PNG 截图，包含当时可见界面。
- 按设置频率和时长录制窗口 PNG 序列，记录实际采样时间，可取消。
- 提供 Blender 静帧渲染和动画渲染入口。

**边界：** 窗口 PNG 序列不是直接生成 MP4；性能不足时可能丢采样。窗口录制不主动推进物理求解，也不替代相机原图输出。

### F18　离线相机视频生成

**用途：** 从确定的数据和相机配置生成可重复的视频素材。

- 配套离线脚本支持指定相机、时间范围、分辨率、帧率及渲染设置。
- 生成 PNG 源帧和 MP4，并保留逐帧时间及相机信息。
- 按数据时刻生成画面，不依赖屏幕实时播放是否流畅。
- GW184 独立项目另有配置锁定、分批执行、断点续跑和完整性检查，详见 F29。

**边界：** 主面板、脚本入口和独立项目的能力不能互相替代。已有视频生成代码不等于某个完整长片已经生成。

### F19　MP4 导出与 RTSP 文件播放

**用途：** 把已有视频交给其他播放器或局域网接收端使用。

- 导出选定 MP4，保留已有文件内容。
- 通过 FFmpeg 和 MediaMTX 循环推送选定视频。
- 提供开始、停止、地址复制及相关端口、局域网配置。

**边界：** 当前 RTSP 是选定视频的循环播放，不是 Blender 视口实时捕获，也不是三路实时同步流。切换 Blender 视角或暂停场景不会改变正在循环播放的文件。将 60 秒内容重复到更长视频，也不会产生新的物理仿真时段。

### F20　状态保存、数据完整性与启动诊断

**用途：** 让结果、布局和环境问题可以追溯和恢复。

- 保存、重新打开场景，并按相应入口恢复回放所需状态。0.3.13 保存包清单 SHA-256；原安装路径失效时只允许恢复到清单完全一致的内置 MAPPO、旧法或 TLS 包，不更换方法或数据来源。原数据包目录仍可访问时继续严格校验，外部包缺失、损坏或哈希不匹配时清空旧读数并显示未就绪。
- 检查结果包版本、来源和文件摘要；缺包或不匹配时清除旧读数并显示原因。
- 提供启动脚本、扩展安装流程、路径检查和错误报告。
- 区分源码版、已安装扩展和独立项目，避免误以为改源码会自动更新安装版。

**边界：** `.blend` 不一定嵌入所有外部数据；普通动态回放应保留兼容扩展与数据并通过加载入口恢复。GW184 烘焙时间线是独立机制。Windows 等平台有入口和配置支持，但本机 macOS 证据不能代替其他平台的完整验证。

- 显示连接状态、错误信息和完整诊断，可复制报告。

- 避免把“连接成功”或“场景就绪”解释为已经开始训练。

**主要入口：** Item → CONNECTION。

### F22　仿真场景加载与参数校验

- 检查机组布局、来流、控制配置和运行需求。

**边界：** 地形显示不自动进入物理求解；FAST.Farm 请求风向的支持和湍流文件覆盖风速等情况必须看实际生效信息。

### F23　已有策略推理运行 Replay

### F24　交互训练 Interactive

**边界：** 前端按钮响应不等于物理步骤瞬间中断；断开连接也不等于停止任务。观察相机调整不是手动覆盖策略动作。

### F25　正式训练提交与恢复

- 提交正式训练流程，或从兼容检查点恢复。
- 查看任务进度和可用训练指标。
- 通过相应停止流程结束任务。

**边界：** Formal Training 不提供逐步实时三维遥测，不支持 Pause、Resume、Step。已有短时 Replay 验证不能证明完整长时训练已经验收。

世界模型计划的首版侧重三台风机、偏航与集体变桨、一个小型预测器和有限候选库。独立变桨 IPC、完整三维流场预测、大规模风场及实机部署不属于该首版已经完成的内容。前端最直接的新页面是预测叠加、命令与反馈对照、候选比较和失败原因显示。

### 8.3 更长期的平台扩展

- **QBlade 接入**：属于平台后端扩展方向，需要后端适配后再定义 Blender 的显示与操作合同。
- **更完整的风场数据传输**：当前协议预留过二进制尾流扩展，但现有 v1 JSON 实现明确未启用，不能把协议预留当成可用功能。
- **实机数据与硬件验证**：未来可以研究真实相机、雷达、运行数据的对接，但当前合成图像、几何采样和仿真回放不能代替实机数据链路。

## 9. 常见误解与当前明确边界

| 容易混淆的说法 | 准确表述 |
| --- | --- |
| “打开 MAPPO 就在训练” | 默认入口播放已保存结果；Interactive／Formal Training 才进行训练更新。 |
| “模型会变形，说明所有运动都是物理求解” | 默认 NREL 柔性回放使用物理结果；GW184 独立项目当前是预设刚性动画。 |
| “60 Hz 回放就是 60 FPS” | 60 Hz 是显示时间映射，实际窗口绘制速度取决于设备和负载。 |
| “毫米残差就是雷达毫米精度” | 挠度残差用于核对同源坐标恢复，不能转化为实体测量精度。 |
| “三路看到整片叶片了，拼接就完成了” | 视场、实际遮挡、公共表面、真实成像和拼接算法是不同验证对象。 |
| “2×2 的第四格是第四台相机” | 第四格是静态安装示意。当前标准观察为三路相机。 |
| “调天气和尾流就改变了物理工况” | 当前画面与环境设置主要影响显示；新物理工况需要后端输入和求解。 |
| “RTSP 推的是实时 Blender 画面” | 当前推送所选 MP4 文件。 |
| “没有读数就是零净空” | 缺失、过期和无效必须保留状态，不能转成零值。 |
| “S1 报警等于双束净空低于阈值” | S1 有效叶片首交独立报警，与 S2/S3 是否成功无关。 |

## 10. 常用入口与典型使用流程

### 10.1 展示默认物理回放

1. 加载“MAPPO · 60 秒”，确认数据来源和当前机组。
2. 在全场与单机视角之间切换，说明机组结构和柔性运动。
3. 播放、暂停和单步，按需要开启挠度辅助物或叶尖轨迹。
4. 查看净空卡片，确认是默认“双束净空 / S1”、显式“TLS 候选 / S1”还是原 B2，按界面方法身份解释结果。
5. 打开遥测与曲线，将姿态、测量和运行数据对应到同一仿真时刻。

### 10.2 检查三相机方案

1. 加载默认场景，打开 View → 三相机。
2. 在外部视图检查盒体和支架，再按需要整体调整安装。
3. 分别调整 C1/C2/C3 的方向与视场，检查同一叶片的公共区域和遮挡。
4. 打开三路对照，使用 2×2 或单路放大检查局部细节。
5. 检查多个时间点或转动相位，再保存布局并导出同刻原图。

### 10.3 连接后端运行

1. 检查环境，选择 Replay、Interactive 或 Formal Training。
2. 连接 Bridge，加载并校验场景，确认实际生效参数。
3. 设置检查点及运行参数，启动对应流程。
4. 查看可用遥测、训练指标、订阅和安全事件。
5. 结束时发送 Stop 并等待停止确认，再断开或返回离线回放。
