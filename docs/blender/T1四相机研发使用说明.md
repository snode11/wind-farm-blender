# T1 四相机研发使用说明

当前功能随 0.3.7 交付。入口始终位于 **3D 视图右侧 N 侧栏 → View → 自定义相机 · T1 · 研发**，不在 MAPPO 面板。已有 MAPPO 加载与回放入口保持不变。

## 观察目标（2026-09-23 明确）

最多四台相机分工观察**同一片叶片沿长度方向的不同区域**，类似分别观察同一个人的腿部、腹部、头部。四路可先按叶根、中内段、中外段、叶尖分工，具体边界和相机参数需验证；不预设必须使用四台或等长分段。

此前 `T1-four-cameras-v1.json` 按叶轮上、右、下、左布置，属于目标理解错误，不是符合这一需求的推荐布局。文件保留用于复现历史测试，详见 [旧布局状态说明](../../outputs/camera-layout-test-v1/README.md)。能导入、能播放或能导出四幅图，不等于同一片叶片的各段已经看清。

已提供 [同一叶片四段试用布局 v2](../../outputs/camera-layout-same-blade-v2/README.md) 和 [可导入 JSON](../../outputs/camera-layout-same-blade-v2/T1-same-blade-four-cameras-v2.json)，桌面有同名副本。相机在机舱同侧固定安装，参考对象为第 1 帧／117 s 的 T1.Blade1。先在 View → 采集设置导入，再回到该时刻暂停看四路；导入本身不跳转时间。播放时叶片进入、离开取景区域，其他叶片也会经过，不是持续跟踪或身份锁定。C4 为形变留出余量，允许与 C3 重叠；C1 最内侧叶根未完整呈现。

最终布局已做安装版播放与内存观测，仍有明显掉帧，详见 [播放报告](../../outputs/camera-layout-same-blade-v2/performance/REPORT.md)。四个原生视口共享场景和时间轴，但仍各自需要绘制，不能理解为四路只付出一路绘制成本。

## 启动与四个槽位

先加载包含 T1 的演示。源码测试可从仓库根目录启动独立窗口：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --factory-startup --python scripts/blender/open_custom_cameras.py
```

其他系统使用对应的 Blender 程序路径。源码入口保留普通风机视角，不自动打开四格，也不预装相机。需要时在 View 面板点击“四路对照”。若窗口默认打开 Item 或 MAPPO 标签，手动点击侧栏 **View**。可折叠原生 View 和 3D Cursor 小节，为相机操作留出空间。

C1–C4 是四台独立相机，默认机舱相机和 Down 不占槽。空槽不显示虚构参数。已安装相机通过“参与四路预览与采集”单独启用／禁用；四路看板与采集只绘制参与路，单路“查看画面”仍允许检查禁用相机。旧双槽配置首次接入时保留位置、姿态、HFOV，以当时场景有效画幅计算 VFOV；此后主场景分辨率变化不再改变这台相机的画幅。

## 安装和调整

- **为 C1–C4 选安装位置／更改安装位置**：先选对应槽位，再点击该按钮。安装在原编辑窗口完成，原生观察窗口只负责观看。回放暂停在当前帧，外部视图单击机舱主壳；可从顶部、底部、尾部和侧部选择实际表面。独立盖板仅在明确标记为安装面且属于 T1 机舱层级时可选；其他附件、叶片、塔筒不会因名称相似而获准。
- **输入 XYZ 位置 / 参数**：输入镜头中心 XYZ 和角度，选择“表面安装”或“研发坐标”，点击“校验并预览”。表面模式要求距外壳 0.02–0.50 m，存在多个锚点时需选择。研发模式不吸附坐标，拒绝确定处于实体壳体内部或距壳不足 0.02 m 的位置；超过普通距离或表面不闭合时，需勾选确认支架偏置／未验证安装，并保留警告。
- 进入方向阶段后，鼠标拖动和虚拟摇杆改变 Yaw/Pitch；Shift 拖动细调。XYZ 保持固定；已安装相机通过“更改安装位置”直接回到选点，通过“调整方向与视场”直接进入方向阶段。Roll、HFOV、VFOV 通过数值输入。
- 默认滚轮不改变视野；明确打开“联动视场调整”后，滚轮同时缩放两个半角的正切，保持理想画幅比例。
- **确认修改**提交当前场景中的草稿，恢复进入前播放／暂停状态；**取消修改或视口 Esc**恢复原配置，新建草稿被删除。从外部布局开始的安装，确认和取消后都会回到外部布局，并保留选中的槽位。修改一个槽位不改变另外三台相机。固定观看期间导航不会修改参数，进入调整后才可编辑。

编辑时视口顶部持续提供“确认修改／取消修改”，滚动参数区或收起侧栏后仍可点击。确认仅在有效的方向阶段可用；未就绪时显示原因。数字字段正在输入时，Esc 先取消字段输入；鼠标回到视口后按 Esc 才取消草稿。

确认后配置保留在当前场景；持久保存请显式导出布局或保存 Blender 文件。

输入无效时保留字段并显示原因，不静默改变 XYZ、姿态或 FOV。改变相机槽位和采集前必须先完成或取消草稿。实时后端尚在运行或未确认暂停时拒绝安装与采集，不代发 Bridge 控制命令。

## 坐标与光学参数

坐标为 `T1.YawRoot.local / v1`，单位米，原点是塔顶偏航参考点。+X 朝尾部、−X 朝叶轮、+Y 为面向叶轮时右侧、+Z 朝机舱局部上方。相机只随机舱运动一次，不跟随叶轮。

Yaw 从 +X 向 +Y 为正，0° 朝尾部、180° 朝叶轮；Pitch 向上为正（−90° 至 90°）；Roll 绕相机局部 +Z 轴，正值使静止景物在画面中顺时针转动。极点保留记录角度，不反解覆盖用户输入。

HFOV、VFOV 都是**完整视场角**，各自范围 1°–170°。可空的“记录焦距”仅存档，不影响投影或内参。XYZ 和光轴也不会随 FOV 变化。

输出默认长边为 **1920 px**，可在“调整方向与视场”中提高，例如 2560。比例按 `tan(HFOV/2) / tan(VFOV/2)` 计算；例如 90°/60°、长边 1920 时的图像是 1920×1109。每路独立，不强制 16:9。短边不足 16 px、超过 GPU 纹理上限或分配失败时明确报错；不会偷偷裁切。预览使用较小的独立像素预算，极端比例也可能超出预览预算。

近裁剪默认 0.005 m，须为正且不超过 0.01 m；远裁剪必须更大。此限制防止通过扩大近裁剪隐藏贴近镜头的壳体。实际机身和支架认证不在本工具内。

## 原生观看与精确预览

“查看单路画面”和“四路对照”现在打开独立的 Blender 原生观察窗口。单路一个视口，四路按左上 C1、右上 C2、左下 C3、右下 C4 排列。它们共享原场景和回放时间轴，不运行离屏预览刷新循环，不复制仿真数据。各视口标题栏有播放／暂停和退出按钮；退出关闭观察窗口，原编辑窗口和相机参数保留。再次打开不会累积临时相机。未安装或未参与的四路槽位显示空画面；单路可以查看未参与四路的已安装相机。

默认采用原生材质预览，保留草地纹理、环境光和颜色管理；不会在播放时自动切换为实体着色。用户仍可通过 Blender 原生着色控件手动切换。画面按当前窗口分辨率绘制，不再使用播放时 320 px 的预览图片。四路仍有四个视口的绘制开销，不承诺任何机器都能达到 60 FPS。

原生相机框共用主场景画幅，因此观察窗口使用临时观察相机和黑色取景遮罩显示每路实际 HFOV/VFOV。临时相机跟随原相机，锁定相机移动；不会修改原 C1–C4 的 XYZ、角度、FOV、主场景渲染尺寸或导出内参。极端视场超过 Blender 原生范围时拒绝显示，可回到精确预览检查。

- **外部布局**：在原编辑窗口检查安装位置、光轴和视锥。
- **原生单路／四路**：用于观看运动、比较观察区域；真实实体仍参与遮挡，原生着色与导出材质效果可能不同。
- **精确材质预览（暂停检查）／调整方向与视场**：继续使用独立投影和离屏画面，校核与导出相同的构图及材质；暂停后操作。

旧的离屏四格预览入口与四格卡片绘制已移除。单路精确检查和按需导出 C1–C4 原图仍保留；它们不参与原生四路的自动刷新。

安装与导出在原编辑窗口完成。导出仍保留设置的输出尺寸、同刻采集和独立双 FOV，不使用观察窗口截图作为原图。若要改变相机位置或方向，先退出观察窗口，再选槽位编辑并确认。

## 单路精确预览的来源与更新状态

顶部同时显示“当前回放”和“看板画面”。图像来源时间与图像一起提交；没有有效仿真时钟时，显示该图像生成时的帧／子帧和“无仿真时钟”。修改 HFOV、方向、参与相机、颜色或像素预算后，即使时间没变，也会显示等待更新。

单路绘制成功才替换旧图与来源信息。绘制失败时保留同一有效会话的旧图，并显示“更新失败，显示上次画面”和错误原因；跨场景／来源失效会清理旧缓存。草稿单路与已确认相机的缓存互不混用。GPU 绘制是主线程同步调用，更新期间不能保证界面及时重绘，缓存不等于无输入延迟。

## 采集设置与导出

在 **N 侧栏 → View → 采集设置** 展开折叠区，核对 C1–C4 的安装／参与状态、输出长边与实际宽高。“编辑 Cn 输出参数”进入同一相机草稿，需要确认后才生效，没有第二份长期独立的输出尺寸设置。

选择“当前时刻”或“时间序列”。当前时刻按 1 组计算，静态场景也可用；时间序列需要已加载的正式 FarmFlex 回放。开始、结束、采样间隔统一保存在当前场景中，目录选择器只选目录并显示同一份摘要，不重置范围。

采样清单为 `start + n × step ≤ end`，结束时间不落在采样网格时不硬加末点。设置区显示实际首末采样点，以及 `N 个采样点 × M 台参与相机 = N×M 张 PNG`。更换来源后范围失效会提示，不自动改成另一份任务。

核对预检查后点击“导出原图 → 选择目录”。草稿未确认、没有参与相机、序列越界／无正式来源、非 sRGB、非法尺寸或后端未暂停等条件会阻止导出；真正开始前再检查一次。GPU 显存分配仍可能在运行期失败。

选择已有父目录，工具创建唯一 `capture_日期_时间_标识/` 子目录。同组相机使用同一仿真姿态，输出不带面板、编号、摇杆或视锥。序列使用既有正式数据只读求值，不按屏幕刷新次数采样，不重算统计或记录遥测；完成、取消或失败后按有效会话恢复原时刻与播放状态。

```text
capture_.../
  layout.json
  manifest.json
  frames.jsonl
  C1/frame_000000.png
  C2/frame_000000.png
  ...
```

`manifest.json` 只有整次成功才标为 `complete`；取消或失败保留 `incomplete` 和原因。`frames.jsonl` 仅提交已完整绘制的一组；失败组的零散文件不应作为完整样本使用。进度区区分“已完成 N 组”和正在生成／下一组序号及目标时间。Esc 或“取消采集”发起取消；插件收到事件后才报告接受，停止后保留完整组与 incomplete 清单。响应边界在完整单组之间，组间收到取消不会再开始下一组；GPU 同步调用中无法即时响应。

每条图像记录含 capture ID、仿真时间（无仿真时钟的静态场景为 null）、帧／子帧、来源包与哈希、布局哈希、双 FOV、实际宽高、K/P、机舱姿态及有明确方向的相机矩阵。矩阵使用行存储、列向量和米。OpenCV 坐标为右／下／前，左上像素中心为 (0,0)。源数据的 REVIEW_ONLY 状态继续保留。

**导出布局 JSON**单独保存完整四槽布局，拒绝覆盖已有同名文件。**导入布局 JSON**依次执行选择文件、完整校验、显示四槽摘要、用户确认、一次提交。摘要逐槽列出创建／替换／清空／保持为空／配置不变，并显示主要参数变化。JSON 未列出的槽位会清空，此操作是完整布局替换。

选择文件或取消摘要不会修改布局。确认时若布局、模型或会话已变化，会拒绝旧摘要并要求重新读取；提交使用已经展示的内存内容，不在确认后偷偷重读变动文件。替换失败会恢复原布局和引用。成功且确有变化的整套导入只记一步撤销。

## 撤销相机修改

“自定义相机 · T1 · 研发”面板提供 **撤销上次相机修改**，并显示“撤销：清除 C3”等操作说明。确认安装／位置／方向／FOV／输出参数、改变参与状态、清槽与整套导入均按一次成功操作记一步；连续输入、查看、切换卡片、取消草稿和无变化确认不记历史。

最近 20 步只保留在本次会话内，不接管 Blender 全局 Ctrl+Z，也没有重做。草稿或采集期间需先处理当前操作，不能直接撤销。撤销只恢复相机完整配置，保留当前回放时刻、帧／子帧、播放与统计；恢复后图像重新更新。

加载文件、切场景、会话或模型变化，以及外部修改／全局撤销导致历史脱节时，会清理相机历史并显示原因。普通恢复失败保留当前布局与有效历史。关闭文件或重启后不能依靠这份会话历史恢复配置。

## 调整前后比较

1. 选定同一仿真时刻，导出所有启用相机，保留 PNG、布局和元数据。
2. 重新调整位置、角度或双 FOV，确认新布局。
3. 回到第一组记录的时刻，核对相同模型、数据包、工况、颜色和输出长边，再导出到新的唯一目录。
4. 在外部图片查看器人工比较对应槽位的可见区域、构图和明显遮挡；通过布局导入恢复选中的布局。

两次有独立 capture ID；核对 `time_s` 和来源，不凭相同文件名判断同刻。FOV 改变导致宽高变化是预期行为。工具不做拼接、不提供软件内前后快照，也不承诺完整叶片覆盖或毫米级可辨识性。

## 文件和运行边界

安装、确认、取消、观看和撤销不会主动保存 `.blend`、偏好或配置。只有点击导出才写指定文件；用户自行保存 Blender 文件仍会保存场景相机。

真实窗口 GPU 测试环境为本机 macOS／Blender 5.2.1 LTS。离屏需要有效图形上下文，不承诺后台无窗口采集、四路 30/60 FPS 或 Windows/Linux 已通过。0.3.7 包含扩展注册时机修复，安装包及本次验证见 [交付说明](../../dist/README-lidar.md)。v3 的实际检查、失败修复、延迟与未验证范围见 [v3 实施记录](T1四相机研发_v3实施记录.md)，历史证据继续按当时版本和环境解释。
