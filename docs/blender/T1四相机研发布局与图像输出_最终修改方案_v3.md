# T1 四相机研发布局与图像输出——最终修改方案 v3

日期：2026-09-22
本轮主题：**状态与可靠操作**
文档状态：**待实施方案。本次仅编写方案，不代表功能已实现、测试已通过或安装版已更新。**
适用范围：当前本地 Blender 前端中的 T1 自定义相机 C1–C4。

## 1. 本轮目标与规格关系

本轮目标是让用户随时知道自己在看什么、哪些修改尚未确认、图像是否对应当前参数，以及导出将产生什么；误操作后能够单独恢复相机布局。

以当前本地源码为开发基线，保留已有四槽、独立投影、单路编辑、图像缓存和同刻整组采集。在此基础上增量完善状态显示、确认／取消可达性、采集设置、导入摘要和相机专用撤销，并建立真实操作延迟基线。

相关依据：

- [v2 主规格](T1四相机研发布局与图像输出_最终修改方案_v2.md)：已实现的坐标、双 FOV、安装校验、输出和数据合同继续适用。
- [当前使用说明](T1四相机研发使用说明.md)：核对用户可见行为。
- [当前实施记录](T1四相机研发实施记录.md)：核对历史运行环境、证据和限制。

本轮新增要求及实施顺序以 v3 为准。旧增量任务中的“两槽扩展四槽”等阶段属于历史需求，不重新作为本轮待办；历史测试通过也不自动等于 v3 通过。现存其他演示、雷达和视频流计划不纳入本轮。

本轮只实施第一轮。第二轮的布置效率改进、第三轮的软件内 A/B 比较，仅在本文末尾保留边界，不同步开发。

## 2. 已有基础与待补能力

| 已有能力，必须复用 | 本轮要补的内容 |
|---|---|
| C1–C4 独立槽位、备注名、启用状态；空槽与停用槽保留位置 | 更准确的状态和参与范围文案，不改槽位身份 |
| 表面选点、XYZ 输入、草稿、确认／取消、暂停与恢复 | 滚动参数后仍可执行确认／取消；区分草稿、场景确认和磁盘保存 |
| 方向编辑只绘制单路；四格才绘制各启用相机 | 保留此分工，不能把“编辑一台仍绘制四台”当作已确认问题 |
| 缓存与刷新间隔；标题保存并显示完成绘制时的仿真时间 | 同时显示当前时间和图像来源时间；补缓存帧／子帧、参数过期和失败状态 |
| 整组绘制完成后替换；组内状态签名检查 | 保留整组保证；图像及来源元数据一起成功提交 |
| 每相机输出长边、目录选择器中的序列参数、正式回放只读求值 | 集中呈现同一份设置、尺寸、采样数量及导出前检查 |
| 全量布局导入和参数校验 | 展示每槽实际影响，再确认提交；补齐替换失败的恢复保障 |
| 未提交草稿可以取消 | 增加已提交相机操作的专用撤销 |

当前预览绘制为主线程同步执行，现有缓存不等于无输入延迟。实施记录中的四路长边 640 px 首次整组绘制约 0.68–1.57 秒，是历史首次绘制测量，不是持续 FPS，也不是输入到画面显示的完整延迟。

## 3. 第一轮功能要求

### 3.1 持续可达的状态与操作区

保留入口：**3D 视图右侧 N 侧栏 → View → 自定义相机 · T1 · 研发**。保留当前工作区和 2×2 看板，不再次迁移入口或拆分 Screen。

在当前视口提供持续可见的简洁状态区。允许采用视口操作条；验收不限定必须将原生 N 侧栏做成粘性布局。操作条需预留空间，避免遮住完整画幅、卡片标题、原生工具栏及已有关闭入口。

| 状态 | 用户可见信息示例 |
|---|---|
| 单路固定观看 | `C2 · 已锁定；拖动不会修改相机` |
| 四路观看 | `四路对照 · 已确认布局；当前选中 C2` |
| 外部布局观看 | `外部布局 · 当前选中 C2；观察视角不修改安装参数` |
| 表面选点／位置输入 | `正在修改 C2 安装位置 · 草稿未确认` |
| 方向与视场编辑 | `正在修改 C2 方向与视场 · XYZ 已锁定 · 草稿未确认` |
| 采集 | `已完成 2/20 组；正在生成第 3/20 组；目标仿真时间 …` |

编辑期间，用户滚动参数区、展开侧栏或收起侧栏后，仍能直接执行“确认修改”和“取消修改”，不必滚回顶部。原侧栏按钮可保留，但两处必须调用同一操作逻辑。

确认仅在既有安装阶段和校验条件允许时可用；位置尚未确定或校验失败时，不能为了让按钮可点击而绕过流程。不可用时说明原因。取消保持现有草稿恢复、返回视图与播放恢复规则。

操作区附近说明：**“确认后配置保留在当前场景；持久保存请导出布局或保存 Blender 文件。”** 不把确认显示为“已保存到磁盘”，也不新增自动保存 `.blend`、偏好或配置文件。

Esc 按焦点验证：数字输入框处于编辑状态时，首次 Esc 应处理当前字段输入，不应同一次按键又取消整个相机草稿。焦点在视口时继续遵循现有取消草稿／关闭画面的规则。先检查原生事件分发，再做局部修改，不全局接管 Esc。

### 3.2 卡片和侧栏的信息层级

- 卡片默认保留 C1–C4、备注名、安装／参与状态、必要警告和位置入口；固定编号不随备注名或重命名改变。
- 完整 XYZ、Yaw／Pitch／Roll、HFOV／VFOV 以选中相机侧栏为主。卡片完整工程参数可通过“显示工程参数”选项展开，避免默认占满画面。
- 已有启用开关明确命名为“参与四路预览与采集”。禁用后保持卡片槽位，显示“已安装，未参与四路预览与采集”；单路仍允许检查。
- 不在本轮拆成两套独立预览／采集开关，不改变现有参与语义。
- 卡片选择、侧栏选择和操作条中的 C 编号始终一致。当前输入值与缓存图像不一致时，明确标记，不能让用户把当前数值误认为旧图的成像参数。

### 3.3 图像来源、待更新与失败状态

同时显示两类信息：

```text
当前回放：12.5 s · 播放中
看板画面：12.1 s · 等待更新
```

参数变化但时间未变化时，显示例如“HFOV 已修改，画面待更新”。不能只比较仿真时间来判断图像是否过期。

每次成功预览提交至少绑定：仿真时间（允许缺失）、帧／子帧、槽位集合、相机参数签名或版本、来源／会话身份、绘制与颜色配置、实际预览像素预算。沿用并扩展现有缓存键和版本机制，不另造不一致的“已更新”标志。

无有效仿真时钟时，显示图像成功绘制时缓存的帧／子帧，并注明“无仿真时钟”；不能用当前场景帧号给旧图标时间，也不能把缺失时间填成 0 s。

| 预览状态 | 行为要求 |
|---|---|
| 尚无图像 | 显示“画面准备中”，不展示虚构图像来源 |
| 请求已变化、尚未绘制 | 保留上一份有效图像，显示“等待更新”及时间／参数等变化原因 |
| 绘制中 | 能呈现时显示“正在更新”；不承诺同步 GPU 调用期间界面还能及时重绘 |
| 成功 | 整组图像与对应来源元数据一起替换，再清除过期／错误状态 |
| 失败 | 显示可处理的失败原因；同一有效会话内保留旧图并明确“更新失败，显示上次画面” |
| 场景／来源身份失效 | 清理失效缓存，不能把上一场景图像继续当作当前结果 |

不把单路草稿预览混入已确认四路组。失败组、半组或新元数据不能覆盖上一份完整组。

本轮不预设降低预览分辨率或更换调度架构。先补状态与测量；如发现本轮改动引入的重复刷新或资源问题，应完成修复。

### 3.4 集中的采集设置与导出前检查

在 View 侧栏增设“采集设置”折叠区，提供下列内容：

| 项目 | 要求 |
|---|---|
| 参与相机 | 列出 C1–C4 的安装／参与状态、每台输出长边和实际宽高 |
| 采集方式 | 明确区分当前时刻与时间序列 |
| 序列设置 | 开始时间、结束时间、采样间隔、实际首末采样点、实际采样数量 |
| 输出规模 | 显示 `N 个采样点 × M 台参与相机 = N×M 张 PNG`；当前时刻按 1 组计算 |
| 当前条件 | 草稿、参与相机、来源与可求值范围、颜色配置、像素预算等检查结果 |
| 导出入口 | 用户看清以上内容后点击导出，再选择目录 |

**单一数据来源：**每相机输出长边继续以现有相机参数为权威值。采集区和原编辑区必须复用绑定及确认机制，不能各存一份长期不同步的值。已安装相机参数修改仍经草稿校验／确认，不因在采集区操作而逐键提交。可以从采集区直接进入对应相机的输出参数编辑。

序列设置从操作符临时字段迁移为当前场景统一使用的一份设置；文件选择器只选择目录或读取同一份设置，不能再编辑另一套副本。打开文件选择器时不得重置用户刚设定的范围。更换来源后重新校验范围，失效则明确提示，不静默改成另一份导出任务。

采样清单继续使用现有 `start + n × step ≤ end` 规则和数量上限。结束时间不在网格上时不硬加末点；摘要与实际采集调用同一个采样计算入口。

实际宽高继续由 `tan(HFOV/2) / tan(VFOV/2)` 和该相机输出长边推导。不得引入独立宽高设置、强制 16:9 或自动裁切。记录焦距仍只存档，不影响画面。

预检查至少覆盖：未确认草稿、没有参与相机、无效数值或超限采样数量、序列来源不可求值或越界、非 sRGB 显示设备、不合法输出尺寸，以及现有安装／后端运行阻止条件。静态场景仍可导出当前时刻，缺少正式回放不应一律阻止静态单组导出。

目录选择结束、实际采集开始前重新检查当前条件，避免检查后场景变化而使用过期摘要；保留采集事务的运行期保护。预检查通过不等于 GPU 分配必然成功，运行期失败仍需明确报告并保留 incomplete 语义。

### 3.5 采集进度和取消反馈

分别显示已完成组数、正在生成的组号、该组目标仿真时间。静态场景显示帧／子帧和无仿真时钟提示。进度不能将“已完成 2 组”误写成“正在生成第 2 组”。

取消仍以完整单组之间为边界，保留已完成组和原有 incomplete／frames.jsonl 提交规则。若已有一组在执行，停止不得留下被标成完整样本的半组；若当前就在组间收到取消，不应额外启动下一组。

区分“用户发起取消”“程序已接受请求”和“已停止”。可见提示使用“取消将在当前组完成后生效”等准确文案，但不能在尚未收到事件时谎称“请求已接受”，也不承诺 GPU 调用中立即响应。

分别测量取消请求的接受延迟和停止延迟。完成、取消、异常后的时间、播放状态与统计保护继续沿用现有事务规则。

### 3.6 布局导入摘要与提交

导入流程为：选择文件 → 读取并完整校验 → 显示四槽摘要 → 用户确认 → 一次提交。选择文件不直接替换布局。

| 当前槽位 | 文件中的槽位 | 摘要 |
|---|---|---|
| 已安装 | 有相机且配置有变化 | `C1 将替换`，展示备注名、参与状态及主要参数变化 |
| 空 | 有相机 | `C2 将创建` |
| 已安装 | 缺失／空 | `C3 将清空` |
| 空 | 缺失／空 | `C4 保持为空` |
| 已安装 | 配置相同 | `C1 配置不变` |

显著说明：“这是完整布局替换；文件未列出的槽位会清空。”不得默认改为逐槽合并。

摘要必须对应本次已经读取并校验的内容。确认时若当前布局、模型或会话已变化，重新生成摘要或拒绝提交；不能直接使用旧摘要确认另一套影响。若重新读取的文件内容变化，也必须重新展示。

校验失败、用户取消或提交失败不得留下部分替换布局。整套成功且确有变化才记入一步相机撤销；配置完全相同不入历史。

### 3.7 相机专用撤销

提供“撤销上次相机修改”按钮，并显示可撤销操作说明，例如“撤销：清除 C3”。不接管 Blender 全局 Ctrl+Z；首版不新增重做、历史树或复杂历史面板。

| 操作 | 历史规则 |
|---|---|
| 拖动、连续输入、阶段切换 | 不逐次记录 |
| 确认安装／位置／方向／FOV／输出参数修改 | 一次成功确认记一步 |
| 清除槽位、改变参与状态 | 每次成功且有变化的操作记一步 |
| 导入整套布局 | 四槽整体记一步 |
| 查看、切换卡片、取消草稿 | 不记录 |
| 校验失败、操作失败、前后布局没有实际变化 | 不记录 |

历史只在本次会话内保存，采用有界队列，首版保留最近 20 步。不自动写磁盘，不承诺关闭文件或重启后还能撤销。

快照保存完整四槽可恢复配置：槽位与空槽状态、备注名、参与状态、XYZ、朝向、双 FOV、记录焦距、输出长边、裁剪参数、安装模式、锚点、偏置确认和安装校验相关字段。不能只保存 XYZ 和角度，也不能恢复表面安装时遗留目标对象旧的研发模式确认字段。

撤销约束：

1. 编辑草稿或采集期间禁用，并说明需先处理草稿或结束采集；不能偷偷提交、取消草稿或终止采集来执行撤销。
2. 只恢复相机布局，保留当前仿真时间、帧／子帧、播放状态、形变与原有统计／历史；普通播放、暂停、寻址不应单独使布局历史失效。
3. 绑定场景／会话和模型身份；加载文件、跨场景、模型重建或模型签名变化后清理失效历史并提示。原地修改网格不能仅靠对象指针识别。
4. 执行前检查当前布局是否仍是历史预期的提交结果。外部修改或 Blender 全局撤销造成历史脱节时，不强行覆盖；清理失效历史并说明原因。
5. 复核布局与安装约束，完整恢复成功后才移除该历史项；普通恢复失败时当前布局和有效历史保持不变。判定历史已失效的情况按上一条清理。
6. 成功后刷新相机引用、选中槽位、外部标记及预览缓存。四格继续显示四格；单路目标恢复为空时转为清楚的空槽提示或四格，不引用已删除相机。清除旧图或标为待更新，不能把撤销前图像标成恢复后的结果。

现有 `layout_dict` 可作为快照格式基础，现有布局校验可复用；**不能直接把现有导入操作符当成撤销实现。** 当前导入会重建相机对象，UI 导入还会退出当前观看控制器；最终删除／发布阶段需要补齐失败回滚和引用更新。实现应在布局层形成可复用的提交／恢复边界，不扩展为全场景撤销系统。

## 4. 操作延迟基线

先测量，再决定第二轮性能优化位置。本轮不以猜测驱动渲染调度重构，不预先承诺持续 FPS 或某个毫秒指标。

| 时间节点 | 含义 |
|---|---|
| t0 | 输入由外部测试工具发出或可观测的用户动作时刻 |
| t1 | 插件收到并处理对应输入 |
| t2 | 对应有效参数状态开始绘制 |
| t3 | 对应图像完成并提交 |
| t4 | 对应图像完成视口绘制／可观测显示 |

分别记录输入等待、刷新等待、绘制耗时和显示阶段；有可靠 t0、t4 才报告相应端到端指标。仅有函数计时不能称为用户操作到画面显示延迟；视口回调完成也不等同于物理屏幕发光，报告中注明测量边界。

场景至少包括首次单路、首次四路、连续方向拖动、数值修改、停止拖动后的最终参数画面，以及采集期间取消。连续输入同时记录输入次数、实际绘制次数、最终图像参数版本和松手后是否仍追赶旧状态。

每组结果记录机器／GPU、系统、Blender 版本、源码版本或文件指纹、模型与来源包、像素预算、相机数量、窗口大小、UI 缩放、冷／热缓存条件和样本数。重复测量报告中位数、P95 与最大值；样本不足时保留原始值并注明，避免将单次测量当作统计结论。

测量结论用于区分输入阻塞、单次绘制成本、无效重复刷新及展示等待。低清交互、停止后高清或最新状态合并列入第二轮候选；无论采用何种方式，都不能改变 FOV、裁切画幅或隐藏机舱／支架等实体来换取速度。

## 5. 实施路径与模块边界

从实际 Git 仓库根目录工作，遵守 [AGENTS.md](../../AGENTS.md) 和项目 Blender 开发技能；保留用户未提交修改。先核对当前实现和已有测试，再按以下顺序增量实施。

| 顺序 | 工作 | 主要现有入口 |

## 7. 交付与保持的边界

实施完成后交付源码、相关测试、更新的使用说明和 v3 实施记录。实施记录分别列出：**新增内容、复用内容、实际运行的检查、失败与修复、未验证范围、延迟基线**。本文保持需求性质，不提前写“已通过”。

保留以下边界：

- T1 的四个独立固定槽位；默认机舱与 Down 不占槽。相机随机舱运动，不跟随叶轮，不自动追踪。
- 双 FOV、内参、坐标约定、真实遮挡、安装距离／穿壳／支架校验和已有数据来源口径不变。
- 不重跑 FAST.Farm，不修改雷达标定、形变数据或净空统计；复用正式结果包。
- 不为性能隐藏机舱、轮毂、叶片、塔筒或真实支架；仍只排除已声明的显示辅助。
- 采集保留当前帧、序列只读求值、同刻整组、颜色、元数据和失败组合同；不自动发实时后端暂停命令。
- 用户确认、取消、观看及撤销不主动写文件；显式导出与用户保存 Blender 文件保持原语义。
- 不承诺四路 30／60 FPS、完整叶片覆盖、毫米级可辨识性或现场精度。
- 不自动更新全局安装、构建交付 ZIP、提交推送或发布版本。若后续另行要求交付安装包，再记录包版本、哈希与安装版验证。
- macOS、后台、源码和安装版证据不能互相替代；Windows／Linux 等未实际运行环境明确标为未验证。

## 8. 后续两轮，仅保留规则

### 第二轮：布置效率与有依据的性能优化

增加相对 T1 机舱局部坐标的“从顶部观察／从底部观察／从尾部观察”和“定位所选相机”。只移动外部布置观察视角，不修改研发相机，不用未经验证的固定安装坐标替用户选点。

增加位置步长 0.01／0.10 m、角度步长 0.1°／1°及修改前后变化量；这些是交互档位，不是模型精度承诺。继续允许任意合法数值，并使用同一安装校验。

增加“只复制镜头参数”：默认 HFOV／VFOV，可选记录焦距和输出长边；不复制 XYZ／朝向，不独立复制任意宽高。复制先进入目标草稿，目标空槽仍为空，成功确认后才安装并记录历史。

根据第一轮实测决定低清拖动、停止后高清或刷新合并，不改变取景与真实遮挡，不默认加入 WASD 自由移动研发相机。

### 第三轮：软件内 A/B 比较

首版只对能够按历史时刻确定性、只读求值的正式回放开放“在 A 时刻生成 B”，复用现有序列求值与恢复机制。不能只修改界面时间而声称恢复了历史物理状态。

| 操作 | 行为 |
|---|---|
| 暂存参考 A | 在会话内生成整组图像及各自布局、来源信息，全部成功后才显示“已暂存”；不自动写文件 |
| 查看参考 A | 只显示已有快照，不改布局，不移动当前时间 |
| 在 A 时刻生成 B | 使用当前已确认布局在 A 时刻只读求值；完成或失败后按有效会话恢复进入前状态，保护统计 |
| 采用 A 布局 | 预览替换影响并确认后只替换布局，保留当前时间，记入一步专用撤销 |

重新暂存失败时保留上一份有效 A；图像、布局与来源元数据作为整组提交。场景／来源失效时不得将旧快照标为当前可严格比较的结果。

比较条件分为：

- **研究变量：**位置、方向、HFOV／VFOV等可以不同，并列出差异；A、B 各自记录布局。布局哈希不同是正常现象，不是比较失败条件。
- **控制条件：**来源数据、模型与物理状态、目标时刻、颜色及绘制配置需要核对一致；不一致时明确说明不能当作严格同条件比较。
- **输出规则：**采用相同长边预算等统一规则；实际宽高允许因双 FOV 比例变化而不同，并记录实际尺寸。

每次优先显示同一槽位的完整画幅 A／B 并排图，可切换 C1–C4。位置或 FOV 改变后不承诺逐像素对齐；不做叠加差分、图像配准、拼接或八图铺满。

自动布局优化、完整覆盖评分、自动跟踪、拼接与复杂镜头特效不纳入这三轮。后续如做光轴命中或单点遮挡判断，必须称为局部检查，不能据此宣称完整覆盖成功。
