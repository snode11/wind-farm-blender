# WFRL Blender 视觉方向

> Part 1 · Deliverable 3 / 3
>
> 状态：作为 Blender 静态原型与后续实现的视觉基线
>
> 关联文档：[功能对等基线](./feature-parity.md) · [演示流程](./presentation-flow.md)

## 1. 设计结论

WFRL 采用“工业控制室”视觉方向：深石墨工作区、低饱和冷色表面、青蓝交互主色、白灰风机实体，以及克制的科学色带。

它首先是可信的工程工具，其次才是演示画面。界面需要让观众在三秒内回答三个问题：

1. 当前是什么场景和运行状态？
2. 画面中的数据来自真实后端、导出计算，还是演示代理？
3. 下一步最重要的操作在哪里？

视觉气质应当精密、安静、可追溯。不要做成游戏 HUD、霓虹驾驶舱或传统 Blender 属性面板的堆叠。

## 2. 设计原则

### 2.1 数据来源比装饰更重要

所有科学数据组件必须显示 `DIRECT`、`EXPORTED` 或 `SYNTH`。标签与数据本身处于同一视觉层级，不放在难以发现的帮助页面中。

颜色只帮助扫视，文字和图形仍需独立表达来源：

- `DIRECT`：绿色标签 + 实心圆点 + “直读”。
- `EXPORTED`：蓝色标签 + 空心圆点 + “导出”。
- `SYNTH`：琥珀标签 + 菱形 + “合成”。

这套编码对应 `status.fidelity` 和 `channel.provenance`。色弱用户即使无法区分色相，也能通过图形和文字判断来源。

### 2.2 主状态只有一个视觉中心

每个时刻只保留一个主操作：就绪时是开始，运行时是暂停，暂停时是继续，结束时是重新运行。次要操作降低对比度，危险操作使用红色描边而非大面积红底。

### 2.3 3D 负责空间关系，Panel 负责证据

3D 视图回答“发生在哪里”，Panel 回答“发生了什么、数值是多少、来源是什么”。不要把完整遥测数字悬浮在每台机组周围，也不要让用户只凭颜色估算物理量。

### 2.4 动效表达状态变化

转子、偏航、变桨、尾流和相机移动都服务于状态解释。禁止无意义的呼吸灯、循环闪烁和与物理时间无关的粒子特效。

### 2.5 展示尺度与物理尺度分开

Blender 中的塔筒、轮毂、机舱和叶片统一按真实米制 1× 建模。旧 Studio 的整机 5× 显示比例不迁移；远距离可读性由相机取景、屏幕空间标签、选中描边和 LOD 解决。

只有柔性形变、箭头、视锥、点位和标签可以使用独立的展示倍率。凡是倍率不为 1×，必须在对应图层旁显示倍率，并且不得改变遥测、坐标、净空、载荷或后端输入。

## 3. 1920×1080 标准布局

演示布局使用四区结构。窗口缩放时优先保住状态、3D 主体、来源标签和运行控制。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│  WFRL  场景 / 模式      CONNECTED · RUNNING · step 024      MIXED 14:32 │ 48
├───────────────┬──────────────────────────────────────┬───────────────────┤
│ Scene         │                                      │ Run               │
│ 场景摘要      │                                      │ 主操作与进度      │
│               │              3D WORLD                ├───────────────────┤
│ Channels      │                                      │ Telemetry         │
│ 来源与订阅    │                                      │ 当前机组与全场    │
│               │                                      ├───────────────────┤
│               │                                      │ Safety / Events   │
│               │                                      │ 规则或演示阶段    │
├───────────────┴──────────────────────────────────────┴───────────────────┤
│  可折叠时间线 / 曲线抽屉                                                │ 240
└──────────────────────────────────────────────────────────────────────────┘
      288 px                    自适应                         376 px
```

### 3.1 尺寸规则

| 区域 | 标准尺寸 | 规则 |
|---|---:|---|
| 顶部状态条 | 48 px 高 | 始终可见，不滚动。左侧是场景和模式，右侧是生命周期、step、来源和时间。 |
| 左侧导航 | 288 px 宽 | Scene 常开，Channels 可折叠；演示时不显示文件系统树。 |
| 3D 主视图 | 剩余宽度 | 最小 720×540；画面中心保留给机组与尾流。 |
| 右侧检查器 | 376 px 宽 | Run 固定在顶部，Telemetry 居中，Safety 在底部。 |
| 曲线抽屉 | 0 / 240 / 360 px 高 | 默认 240 px；关闭时保留 32 px 抽屉把手。 |
| 页面外边距 | 16 px | Panel 间距 12 px，Panel 内边距 16 px。 |

### 3.2 双视图

`view.dual` 默认使用 62% 世界视图和 38% 机组视图。分隔线宽 6 px，可拖动并吸附到 25%、50%、80% 三个预设。右视图顶部始终显示机组 ID、相机名称和“几何视野”标签，避免把视锥当作真实相机图像。

### 3.3 小窗口降级

| 窗口 | 降级方式 | 不得隐藏 |
|---|---|---|
| ≥1600 px 宽 | 完整四区布局 | 全部关键内容 |
| 1366–1599 px | 左侧缩到 240 px；右侧缩到 328 px；曲线图例换行 | 生命周期、主操作、来源、单位 |
| <1366 px | 左侧变成抽屉；右侧保留；双视图默认 50/50 | Safety 严重事件、`status.fidelity` |
| <900 px 高 | 曲线抽屉默认关闭，Panel 内部滚动 | 顶部状态条、Run 控制 |

以上像素值以 Blender UI Scale 100% 为设计基准。实现时按实际 UI Scale 换算，不把固定像素写成跨平台不可缩放的绝对尺寸。

### 3.4 信息架构

Part 1 冻结的是一个产品工作区和一组辅助入口，不是把所有功能塞进同一屏：

```text
WFRL Workspace
├── Global Header
│   ├── Presentation / Development 模式
│   ├── connection.status
│   ├── run.status / run.progress
│   └── Screenshot / Record
├── Left Region
│   ├── Scene：选择、校验、摘要、入流、控制量、说明
│   └── Channels：分组、来源、订阅和数据年龄
├── Center Region
│   ├── World View
│   ├── Turbine / Sensor View
│   └── Camera / Wake / Terrain 快捷控制
├── Right Region
│   ├── Run：模式、主要动作和进度
│   ├── Telemetry：当前机组与全场
│   ├── Safety / Demo Events
│   └── Manual：展示姿态，默认折叠
├── Bottom Region
│   ├── Curves / Timeline
│   └── Logs：Development 模式可见
└── Auxiliary Surfaces
    ├── Scene Picker + 字段级校验
    ├── Interactive / Formal Train 配置
    ├── Replay checkpoint + 兼容性检查
    ├── Preflight (`diagnostic.preflight`)：Blender、Python、MPI、FAST.Farm、Bridge
    ├── Capture：分辨率、帧率、输出位置
    └── Add-on Preferences (`config.paths`)：路径、端口和默认场景
```

`workspace.mode` 的 Presentation 布局保留 Header、核心 Panel 和曲线，不显示日志、文件路径和高级配置。Development 布局使用同一状态源，只增加诊断和编辑入口，不维护第二套业务逻辑。

配置入口采用任务弹层或 Blender 对话框，关闭后回到原视图；Preferences 只保存机器级路径。场景内容、训练参数和 checkpoint 属于当前会话，不写进全局 Preferences。

### 3.5 Blender 实现映射

视觉规范分为“语义必须一致”和“像素尽量接近”两级。不得为了复刻 Web 控件而绕开 Blender 的稳定 UI API。

| 层级 | Blender 实现 | 必须达到 | 可近似处理 |
|---|---|---|---|
| 原生 UI | `UILayout`、Panel、Operator、Property、UIList、Popover | 控件语义、顺序、启禁状态、文案、tooltip、键盘可达 | 圆角、原生按钮 hover、系统字体字重 |
| 自绘 2D | `gpu` / `blf` draw handler | 曲线、来源 badge、状态覆盖层、机组标签、选中描边 | 抗锯齿和平台字体度量的小差异 |
| 3D 场景 | Collection、Object、Material、Light、Camera | 真实米制、稳定命名、材质、灯光、相机、科学图层 | Eevee 平台间的轻微光照差异 |
| Workspace | Area / Region 布局与 App Template | Presentation 与 Development 布局、重启恢复 | 像素级区域宽度，按 UI Scale 允许 ±8 px |
| Theme | App Template 或用户主动选择的主题 | WFRL 自绘区和 3D 颜色符合 token | 原生 Blender 控件采用当前主题的最接近值 |

Extension 不自动覆盖用户的全局 Blender Theme。若 App Template 未启用，功能和信息层级仍必须成立；颜色 token 只对 WFRL 自绘层、3D 材质和可控区域强制生效。

## 4. 色彩系统

### 4.1 基础界面色

| Token | 色值 | 用途 |
|---|---|---|
| Canvas | `#0B0F14` | 应用最外层背景和 3D 视图外框。 |
| Surface | `#121922` | 常规 Panel。 |
| Surface Raised | `#18212C` | 弹层、选中卡片、曲线抽屉。 |
| Surface Hover | `#1E2A37` | 行和按钮悬停。 |
| Border | `#2A3745` | 1 px 边框与分隔线。 |
| Border Strong | `#3A4A5C` | 键盘焦点之外的结构边界。 |
| Text Primary | `#F2F5F7` | 标题、关键数值、按钮文字。 |
| Text Secondary | `#A9B4C0` | 标签、单位、说明。 |
| Text Disabled | `#687584` | 禁用和不可用状态。 |
| Accent | `#2CB7D6` | 主按钮、焦点、选中机组。 |
| Accent Hover | `#57C9E1` | 主按钮悬停。 |
| Focus Ring | `#78D7EA` | 2 px 键盘焦点环。 |

界面不使用纯黑 `#000000` 或纯白大面积背景。深色表面之间依靠明度和边框分层，不依靠强投影。

### 4.2 语义色

| 语义 | 色值 | 使用范围 |
|---|---|---|
| Success | `#55C27A` | 正常、连接成功、`RUNNING`。 |
| Info | `#5AA7FF` | 启动、说明、可恢复提示。 |
| Warning | `#F1B44C` | `PAUSED`、接近限制、非物理说明。 |
| Danger | `#E45B5B` | `FAILED`、block 事件、停止按钮描边。 |
| Neutral | `#8B98A7` | `READY`、`STOPPED`、无数据。 |

语义色不可占据大面积 3D 背景。严重事件采用 4 px 左边框、图标、标题和时间，整张卡片只加 8%–12% 的同色底。

### 4.3 保真度色

| 来源 | 色值 | 图形 | 标签文案 | 旧 Studio 对应色 |
|---|---|---|---|---|
| `DIRECT` | `#55C27A` | ● | DIRECT · 直读 | `#3C8C46` |
| `EXPORTED` | `#5AA7FF` | ○ | EXPORTED · 导出 | `#14508C` |
| `SYNTH` | `#F1B44C` | ◆ | SYNTH · 合成 | `#AA6E1E` |

新颜色保持旧 Studio 的绿、蓝、琥珀语义，但提高了深色背景上的亮度。任何颜色调整都必须三类一起验证，不能把 `SYNTH` 改成比 `DIRECT` 更显“成功”的绿色。

### 4.4 指标色

指标颜色在 3D、表格和曲线中保持一致：

| 指标 | 色值 | 补充编码 |
|---|---|---|
| yaw | `#5AA7FF` | 方向箭头 |
| pitch | `#55C27A` | 三叶片角标 |
| RPM | `#B58CFF` | 旋转图标 |
| power | `#2EC4B6` | 闪电图标 |
| reward | `#F1B44C` | 星形标记 |
| load / clearance | `#FF945C` | 载荷波形 / 距离线 |

机组身份不再消耗一套额外颜色。曲线用线型和标记区分：T1 实线圆点、T2 虚线方点、T3 点线菱形。这样同一颜色始终代表同一物理指标。

## 5. 字体与数字

### 5.1 字体策略

- 普通界面使用 Blender 当前 UI 字体，不写死 Windows 或 macOS 字体名称。
- 中文首选系统可用的无衬线字形；缺字时回退到 Blender 默认字体。
- 数值、step、时间和日志使用等宽或表格数字特性；无法单独指定时保持数字列右对齐。
- 单位不使用斜体，不依赖希腊字符才能理解。

### 5.2 字号层级

| 层级 | 1080p 字号 | 字重 | 用途 |
|---|---:|---:|---|
| Display | 32 px | 650 | 演示阶段提示，只出现一处。 |
| Page Title | 24 px | 600 | WFRL 或当前工作区标题。 |
| Section | 18 px | 600 | Panel 标题、当前机组。 |
| Body Strong | 14 px | 600 | 主状态、关键数值、按钮。 |
| Body | 13 px | 400 | 普通标签和表格。 |
| Caption | 12 px | 400 | 单位、来源、时间和注释；不得更小。 |

关键数值采用“数值大、单位小但相邻”的格式，例如 `3.42 MW`。缺失值显示“等待”“不支持”“断线”或 `NaN`，禁止显示为零。

### 5.3 数值显示合同

默认精度沿用旧遥测中已验证的可读尺度；导出文件保留原始精度，不受 UI 四舍五入影响。

| 字段 | UI 格式 | 单位 | 备注 |
|---|---:|---|---|
| yaw | `+0.0` | ° | 始终显示正负号。 |
| pitch command / measured | `0.00` | ° | 指令与实测分行。 |
| torque | `0.0` | kN·m | Bridge 输入若为 N·m，由 UI 换算。 |
| RPM | `0.00` | rpm | 画面插值不改变显示值。 |
| turbine / farm power | `0.00` | MW | 训练轮次汇总允许 `0.000`。 |
| reward | `+0.0000` | 无 | A1 固定为 0 且不作为主曲线。 |
| TI / normalized load | `0.000` | 按字段定义 | 不把两个字段合并成一个单位。 |
| flex / clearance | `+0.00` | m | 净空允许负值。 |
| wind speed | `0.00` | m/s | 请求值与生效值分别显示。 |
| time / latency | `0.0` | s | 超过 60 s 后可显示 mm:ss。 |

场景名最多显示两行，每行约 32 个中文字符；超出时末尾省略并提供完整 tooltip。文件路径使用中间省略，保留盘符或根目录及文件名。顶部状态条始终单行，空间不足时先隐藏次要时间戳，不截断运行状态和来源。

## 6. 间距、形状与层级

采用 4 px 基础网格：4、8、12、16、24、32。Panel 圆角 8 px，按钮圆角 6 px，标签圆角 999 px。边框默认 1 px，焦点环 2 px，选中机组轮廓 2 px。

界面使用三层深度：

1. Canvas：容纳整个工作区。
2. Surface：Panel 和 3D 容器。
3. Surface Raised：选中卡片、弹层、抽屉。

不要同时使用强阴影、渐变、发光和粗边框。弹层允许使用 `0 12 32 / 28%` 的单层阴影；普通 Panel 无阴影。

## 7. 组件规范

### 7.1 顶部状态条

顶部状态条固定显示：

- 场景名和后端。
- 当前模式：Demo、Interactive Train、Formal Train 或 Replay。
- `connection.status` 与 `run.status` / `run.progress` 两个独立 badge。
- 当前数据来源摘要。
- 最近一次更新的时间或延迟。

连接与运行不是同一个状态轴：

- Demo 显示 `LOCAL DEMO`；A2/A3 显示 `DISCONNECTED` 或 `CONNECTED`。
- 运行生命周期固定为 `READY` → `STARTING` → `RUNNING` / `PAUSED` → `DRAINING` → `STOPPED`，异常进入 `FAILED`。

连接 badge 位于运行 badge 左侧。后端断线时保留最后一个运行状态和数据年龄，再进入 `FAILED`；不能用 `DISCONNECTED` 覆盖“当时正在运行”这一事实。所有状态都有文字和图标，不得只用颜色。

顶部来源摘要只在当前可见字段来源一致时显示 `DIRECT`、`EXPORTED` 或 `SYNTH`；来源超过一种时显示 `MIXED`。`MIXED` 只是摘要，每个数值和图层仍须保留自己的权威来源标签。

### 7.2 Scene Panel

`panel.scene` 首屏只展示场景名、后端、机组数、控制步和来源。布局、入流、控制量与说明使用折叠组。`scene.notes` 使用琥珀图标和普通文字，不使用红色，避免把已知限制误读成故障。

场景校验失败时，错误贴近字段显示；保留上一个有效场景，不让 3D 视图闪空。

### 7.3 Channels Panel

`panel.channels` 每行由通道名、来源标签、订阅开关和最近更新时间组成。关闭 `channel.set` 后，整行降到 55% 明度并显示“已停止采样”，不能只把开关变灰。

来源详情通过点击或悬停查看；主标签仍常驻。通道很多时按 actuator、sensor、derived、visual 分组，而不是按字母排序。

### 7.4 Run Panel

`panel.run` 顶部只允许一个高强调主按钮。模式选择在未运行时可改，进入 `STARTING` 后锁定。

| 状态 | 主按钮 | 次按钮 | 危险操作 |
|---|---|---|---|
| READY / STOPPED | 开始演示、开始训练或开始回放 | 配置 | 无 |
| STARTING | 显示当前启动阶段 | 查看日志 | 请求停止 |
| RUNNING | 暂停 | 单步禁用 | 停止 |
| PAUSED | 继续 | 单步 | 停止 |
| DRAINING | 无 | 查看日志 | 无 |
| FAILED | 重试 | 复制诊断 | 安全清理 |

主按钮最小 120×36 px，普通按钮最小 88×32 px，纯图标按钮最小 32×32 px。

### 7.5 Telemetry Panel

`panel.telemetry` 先显示当前机组，再显示全场汇总。每行结构固定为名称、值、单位、趋势、来源。yaw、pitch 指令与 pitch 实测必须分行，不用同一个“桨距”概括。

关键数值右对齐；变化量使用上/下箭头和正负号，不用红涨绿跌的金融习惯。超过正常范围时，先显示规则和阈值，再改变颜色。

### 7.6 Safety Panel

`panel.safety` 按验收路径切换语义，不能让 A1 的视觉夹具冒充 SafetyLimiter 输出：

- A1 标题为“演示事件”，默认展示脚本阶段摘要、阶段计数和最近三条事件；每条只要求时间、机组 ID、阶段与说明，并固定标为 `SYNTH`。
- A2/A3 标题为“Safety”，默认展示规则摘要、触发计数和最近三条 `safety.events`；每条事件必须包含严重级、机组 ID、step、请求值、应用值和原因，并显示实际来源。

A2/A3 的严重级样式固定为：

- block：红色左边框 + 八边形停止图标。
- warn：琥珀左边框 + 三角图标。
- info：蓝灰左边框 + 圆形信息图标。

新 block 事件在 Panel 标题上增加计数，不用持续闪烁。用户打开 Panel 后计数可清零，事件记录不删除。

### 7.7 Manual Panel

`panel.manual` 在演示布局中默认折叠，并改称“展示姿态”。内部固定显示“仅影响画面，不写入仿真或策略”。yaw、pitch、RPM 的锁定状态用锁图标和 `SYNTH` 标签表达。

### 7.8 按钮、开关与输入

- Primary：Accent 实底，只用于当前主操作。
- Secondary：Surface Raised + Border。
- Destructive：透明底 + Danger 描边；确认后才允许实底。
- Disabled：保留文字可读性，同时显示禁用原因。
- Toggle：开启时同时改变轨道、滑块位置和文字状态。
- 数值输入：单位固定在输入框右侧，不让用户手工输入单位。

键盘焦点使用 Focus Ring，悬停不能代替焦点。任何只在悬停时出现的信息都应能通过点击或键盘打开。

## 8. 3D 世界规范

### 8.1 背景、网格和灯光

- 3D 背景从顶部 `#111A24` 过渡到底部 `#0B0F14`，地平线不做高亮光晕。
- 网格主线使用 `#425163`、20% 不透明度；次线使用 10%。
- 坐标轴只保留必要刻度，默认 x/y 各四个标签、z 两个标签。
- 使用柔和环境光和单一方向光建立形体；不要使用彩色舞台灯。
- 接触阴影帮助风机落地，但阴影不得覆盖尾流色带。

### 8.2 风机材质

| 部件 | 基础色 | 材质方向 |
|---|---|---|
| 塔筒 | `#D8DEE6` | 哑光金属，粗糙度约 0.55。 |
| 叶片 | `#EEF2F5` | 略亮于塔筒，粗糙度约 0.48。 |
| 机舱 | `#818D9A` | 中灰，保持轮廓。 |
| 轮毂 | `#AAB4BF` | 介于叶片和机舱之间。 |
| 选中轮廓 | `#2CB7D6` | 2 px 屏幕空间描边或等效高亮。 |

风机 ID 使用面向相机的小型标签，格式为 T1、T2、T3。标签不随距离缩到不可读，也不遮挡轮毂。

### 8.3 入流与控制意图

入流箭头使用半透明青蓝，长度表达方向，不把未经标定的箭头长度当作风速刻度。yaw 目标使用转子平面附近的弧形箭头；实际 yaw 由机舱姿态表达。指令和实测同时出现时，指令用虚线，实测用实线。

### 8.4 尾流

| 类型 | 视觉形式 | 必须显示 |
|---|---|---|
| `wake.proxy.toggle` | 轮毂高度半透明速度平面 | `SYNTH`、速度单位、色带范围、更新时间 |
| `wake.disxy` | FAST.Farm 导出的水平切面 | `EXPORTED`、高度、文件时间、延迟 |
| `wake.rings` | 低不透明度扩散流管与稀疏流线 | `SYNTH`、纯视觉说明 |

速度场使用 perceptually uniform 色带，优先 `cividis`；同一比较中的最小值和最大值保持固定。无新帧时冻结上一帧并显示数据年龄，不能让颜色自动重标造成“尾流突然改善”的错觉。

尾流圆环使用青绿基调，线宽 1.5–2 px，近端最高 45% 不透明度，向下游渐隐。圆环不能比真实 DisXY 更亮；二者同时开启时，默认降低圆环到 18%。

### 8.5 Lidar 与相机

`sensor.lidar.visual` 使用细射线和小点，不使用大尺寸发光球。点云色带与速度场一致，并显示采样状态、数据年龄和来源。

`camera.frustum` 使用 1.5 px 青蓝线框和 12% 面填充。相机视图顶部显示目标机组、FOV、俯仰和“几何视野”；当前接口不含真实图像时，不使用“视频”“直播”等词。

### 8.6 地形

`terrain.set` 只作为低对比背景：山地使用灰绿，戈壁使用暖灰棕，平地使用中性灰。地形饱和度不超过尾流色带的 35%，并常驻“装饰 · 不参与物理”标签。

## 9. 曲线与表格

### 9.1 曲线结构

- 横轴默认使用仿真时间或 step，二者不可在同一图中无标识切换。
- 纵轴必须显示单位；截断零点时画出明显的 axis break 或说明。
- power 与 reward 可使用独立纵轴，但轴标题、刻度和线色必须对应。
- 当前值显示在曲线右端，历史最大值不默认抢占视觉中心。
- `curve.demo-filter`、`curve.train` 和 `curve.replay` 使用相同的指标色和机组线型。
- 缺帧用断线表达，不把前值连成长平台。

### 9.2 图例与来源

图例顺序固定为指标、机组、来源。来源标签放在图表标题右侧，不塞进每条图例。导出截图必须包含场景名、模式、时间窗口、单位和来源。

### 9.3 表格

表头使用 Surface Raised；数值列右对齐，文本列左对齐。行高至少 32 px。选中行只改变背景和左侧标记，不反转整行文字颜色。表格滚动时表头固定。

## 10. 相机语言

### 10.1 三个固定机位

相机从真实米制场景包围盒计算，不写死世界坐标。令焦点 `C` 为扩展后包围盒中心，`S` 为 x/y/z 最大跨度；尾流开启时，包围盒沿下游方向额外包含可见尾流长度。

| 机位 | 投影与参数 | 位置规则 | 构图 |
|---|---|---|---|
| `camera.world.iso` | Perspective，FOV 40° | `C + (-S, -S, +S)`，朝向 `C`，up 为 +Z | 三机均可见，入流从左前方进入，保留尾流下游空间。 |
| `camera.world.top` | Orthographic | `C + (0, 0, +2S)`，up 为 +Y；ortho scale 为扩展后 xy 跨度的 1.15 倍并适配宽高比 | 风场占画面约 70%，机组 ID 不重叠，坐标方向明确。 |
| `camera.world.side` | Perspective，FOV 40° | `C + (0, -2S, 0)`，朝向 `C`，up 为 +Z | 地平线位于下三分之一，避免透视压扁机组。 |

传感器相机优先读取场景参数；缺省值冻结为 FOV 40°、pitch -30°。`camera.fov.set` 范围为 5°–90°，`camera.pitch.set` 范围为 -90°–30°。相机测试从同一常量读取这些值，解决 G07 的实现与文档漂移。

### 10.2 聚焦机组

选择 `camera.focus.select` 后，先用描边确认目标，再在 350 ms 内移动相机。不要瞬移，也不要绕场旋转一整圈。聚焦后仍保留一个小型全场定位提示，避免用户失去上下游关系。

### 10.3 演示镜头顺序

与 [演示流程](./presentation-flow.md) 的 S1–S6 对齐：

1. S1 使用等距全场景。
2. S2 保持镜头不动，让叶片和转子承担变化。
3. S3 略微抬高，给尾流留出下游空间。
4. S4 切到 62/38 双视图并聚焦 T1。
5. S5 镜头保持稳定，只展开曲线抽屉。
6. S6 收回曲线，返回等距全场景并停留。

## 11. 动效与刷新

| 动效 | 建议时长 / 频率 | 规则 |
|---|---|---|
| Panel 展开 | 160–200 ms | ease-out；内容高度稳定后再出现滚动条。 |
| 相机切换 | 300–400 ms | ease-in-out；保留空间方向。 |
| 选中高亮 | 120 ms | 淡入，不循环脉冲。 |
| 数值变化 | 120–180 ms | 数字直接到真实值，可短暂高亮变化方向。 |
| yaw / pitch 展示插值 | 250–400 ms | 只平滑渲染姿态；Panel 立即显示当前后端值。 |
| 转子 | 每渲染帧 | 按 RPM 和真实帧间隔积分；暂停时冻结。 |
| 尾流圆环 | 每渲染帧或 30 fps | 速度随 RPM 的展示规则；始终标 `SYNTH`。 |
| 新安全事件 | 180 ms | 卡片滑入一次；禁止持续闪烁。 |

提供 Reduced Motion 选项后，相机和 Panel 动画缩短为 0–80 ms，保留状态切换但关闭循环尾流动效。数据采样和物理步进不受该选项影响。

## 12. 状态、空态和错误

| 状态 | 视觉表达 | 文案原则 |
|---|---|---|
| 等待首帧 | 中性骨架或短横线 | “等待第一帧”，不显示 0。 |
| 通道关闭 | 行降明度 + 关闭图标 | “已停止采样”，不写“隐藏”。 |
| 本场景不支持 | 空态 + 原因 | 说明缺少的配置或能力。 |
| 数据过期 | Warning + 数据年龄 | 保留上一帧，但明确它不是当前值。 |
| 可恢复错误 | Info / Warning 卡片 | 给出下一步动作。 |
| 致命错误 | Danger 卡片 + `FAILED` | 保留诊断和安全清理入口。 |

错误不应直接用原始 traceback 覆盖主视图。首层显示用户可理解的原因、影响和恢复动作；完整日志放在可复制的详情区。

`status.data-age` 从每个通道的 metadata 读取预期发布周期 `P`。首帧前显示“等待”；数据年龄不超过 `1.5P` 为新鲜，超过 `1.5P` 为“延迟”，超过 `3P` 为“过期”。周期未知时使用当前场景控制步作为 `P`。连接心跳与通道新鲜度分开判断，单个低频通道过期不能把整个 Bridge 标成断线。

## 13. 可访问性与可读性

- 普通文字与背景对比度目标不低于 4.5:1，大字不低于 3:1。
- 不以颜色作为唯一信息载体；状态、来源、严重级都有图标和文字。
- 1080p 演示中最小文字 12 px，关键状态不小于 14 px。
- 交互目标最小 32×32 px，相邻危险操作间隔至少 12 px。
- 键盘焦点顺序遵循顶部状态、左侧配置、运行控制、遥测、安全、曲线。
- 图表支持高对比模式：增加线宽、标记和网格，不简单反转颜色。
- 截图和录屏仍能读出场景、模式、单位、来源和时间。

## 14. 文案风格

文案使用短句和可执行动词：加载场景、开始演示、暂停、继续、单步、停止、开始回放。避免“提交”“确认”等不能说明结果的泛化按钮，Formal Train 的“提交正式训练”除外。

科学限制使用事实描述：

- 推荐：“SYNTH · 用于展示交互，不进入 reward。”
- 推荐：“EXPORTED · 高度 90 m，数据延迟 1.2 s。”
- 不推荐：“真实感尾流”“AI 优化成功”“智能安全保护”。

错误文案使用“发生了什么 + 影响 + 下一步”，例如：“checkpoint 动作维度为 1，当前场景需要 3；回放未启动。请选择兼容 checkpoint。”

## 15. 禁止项

- 不使用霓虹紫、扫描线、玻璃反射和大面积外发光营造“高科技”。
- 不用红色表示普通功率高低；红色保留给故障和 block 安全事件。
- 不用彩虹色带表达连续科学量。
- 不让地形、天空或尾流特效压过风机与状态信息。
- 不隐藏来源、单位、数据年龄或任何非 1× 的局部展示倍率。
- 不把 `SYNTH` 曲线做得比 `DIRECT` 证据更醒目。
- 不在同一屏同时展开 Scene、Channels、Manual 的全部细节。
- 不在演示中使用不可预测的自由轨道镜头。
- 不把 Blender 原生编辑器、控制台或文件路径暴露给老板演示画面。

## 17. 验收标准

### 17.1 三秒识别测试

向未参与设计的人展示任一核心画面三秒后，对方应能指出：当前场景或机组、运行状态、主操作以及数据来源类别。任一项答不出，先调整层级，不通过增加说明文字补救。

### 17.2 一致性检查

- [ ] 同一指标在 3D、表格、曲线中使用同一颜色。
- [ ] 同一机组在曲线中使用同一线型和标记。
- [ ] 所有科学图层都有来源、单位和数据年龄。
- [ ] 指令、实测、展示锁定三种状态不会共用同一视觉表达。
- [ ] 状态颜色、图标、文字三者一致。
- [ ] A1 截图中的科学数据都明确标为 `SYNTH`。
- [ ] A2/A3 无数据时不会回退到无标签的代理结果。

### 17.3 演示检查

- [ ] 按 [presentation-flow.md](./presentation-flow.md) 的 80 秒流程切换时，没有布局跳动或镜头丢失。
- [ ] Scene → Run → Telemetry → Safety 的注意力顺序清楚。
- [ ] 曲线抽屉展开后仍能看到选中机组和 `run.status`。
- [ ] 最后一帧可停留问答，不依赖循环动画维持画面。

### 17.4 可访问性检查

- [ ] 灰度截图中仍可分辨三类来源和三台机组。
- [ ] 200% 界面缩放下关键控制不被裁切。
- [ ] 仅用键盘可到达开始、暂停、继续、单步和停止。
- [ ] Reduced Motion 下不丢失任何状态信息。

## 18. 设计取舍

### 为什么选择深色工作区

深色背景能让白灰风机、尾流色带和状态卡片同时成立，也适合会议室投影。代价是低对比灰字很容易不可读，因此正文和单位都有明确的最低亮度，不能照搬旧 Studio 的浅色界面数值。

### 为什么保留旧保真度色相

现有 Studio 已用绿、蓝、琥珀区分直读、导出和合成。新方案只提高深色背景上的亮度，不改变语义，减少迁移时的认知断层。代价是琥珀同时承担 Warning，需要依靠菱形和完整标签区分 `SYNTH` 与警告。

### 为什么指标用颜色、机组用线型

如果指标和机组都依赖颜色，三台机组乘多个指标会迅速失控。指标固定色、机组固定线型能让跨 Panel 对照更快，也更适合色弱用户。代价是密集曲线仍需通过筛选器减少同屏数量。

### 为什么不追求写实天气

云层、雾和高反射材质会降低速度场、Lidar 点和风机轮廓的辨识度，还容易暗示不存在的物理条件。WFRL 选择干净的工业环境，把视觉预算留给可验证的信息。
