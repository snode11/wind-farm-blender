## 开发机日常安装

[安装记录](../../publication/daily-installation.json)核对 195 文件、94 个新后台进程模块来源、持久启用、WFRL 主入口注册及 6 个配置文件保护。独立后台检查覆盖真实相机代理／约束和光学失效，以及 T1/T2/T3 Down、保存重开与无遮罩恢复。日常安装和隔离安装分别核对；两者均来自交付身份标识的同一 ZIP。

观察视口关闭画幅外遮罩和额外画幅边界，周围场景保持可见；真实相机 FOV、内参与原图采集画幅保持各自定义。代理通过 COPY_TRANSFORMS 跟随姿态，位置、yaw/pitch/roll、输出尺寸和记录焦距变化复用对象与镜头数据。来源相机、HFOV/VFOV、裁剪距离或场景画幅比例改变时重建并校准；相机视图保持 CAMERA，自由透视／正交观察保持原状态。观察会话完全释放后停止 watch，无资源泄漏清理完成前按 0.25 s 重试；重开重新注册。

最终包、原始验证和回退备份由安装记录索引。[清理清单](../../publication/daily-installation-cleanup.json)保留可恢复映射。原始日志中的临时路径表示测量时来源；留存 environment.json 不表示临时 profile 仍存在，复验前须建立匹配的新环境。

## 当前功能与使用

- **风机手动控制**：**N → 风机控制 → 创建 / 进入手动场景**，提供单机／全部朝向、统一／分别变桨、RPM、叶轮角度和运行／暂停／停转。公开扩展提供 rootkink 恒速变桨试验、独立 T1 Down 及配套源码视频作业控制；朝下／侧向／顺桨预设、按机组当前值微调、三机参数概览及 JSON 保存／载入；多值字段以 * 标记，统一桨距覆盖三片叶片。批量启用分别变桨保留已启用机组的独立桨距，仅初始化从关闭切换为开启的机组。零 RPM 风机保持暂停，全部零 RPM 时禁用运行。独立刚性场景、材质与环境保留原 demo，预设和载入后暂停；不生成物理求解或测量结果。[完整操作及边界](风机手动控制.md)。
- **叶片外形**：MAPPO 侧栏在默认 NREL 和合成 rootkink 之间切换，保留时刻、所选机组及相机设置。rootkink 继续使用 NREL 保存运动、载荷来源和雷达读数；其合成外形不代表厂家 CAD 或独立物理求解。NREL 缺陷编辑及重建对照须先退出，相机编辑、观察或采集会话须先结束。
- **统一重建对照**：**N → MAPPO → 打开几何重建示例…** 打开完整风机分屏，可切几何／同源纹理。右侧复用源风机塔筒、机舱、轮毂和机械展示结构，三片叶片仍为保存的重建估计。
- **视图与时间**：共享播放／暂停、单帧步进、复位和退出；中段／叶尖观察点仅定位一次，手动缩放、平移和绕转在播放后保留。原始／增强显式切换先显示两侧整机；保存重开恢复模式、显示设置、时间和视角。
- **三相机**：默认复位恢复整盒安装姿态和 C1/C2/C3 参数，支持完整布局撤销并保留帧、子帧及自由视图。已有默认且原生有效时保持对象和撤销历史；采集、草稿、安装或后端忙碌时拒绝，提交失败回滚。WATCH / LAYOUT 当前相机及退出快照保持有效引用。
- **普通离线工作台**：三台 NREL 风机 60 秒柔性回放、六类合成缺陷、同刻原图、默认双束／S1、TLS 候选及旧 B2。ZIP 内置数据、规范场景和 packed 纹理，无需作者路径或在线后端。
- **相机清理与稳定刷新**：代理对象或镜头数据损坏时独立释放观察资源、恢复预览与主视口并显示错误；关闭及延迟恢复遵守场景播放归属。同源纹理稳定刷新复用已验证绑定，身份、清单、来源或撤销状态变化后重新校验，保留用户自由视图。

公开 0.3.40 扩展还包含完整播放覆盖和循环判定、回放包单次校验复用及 PNG 采集不分配显示纹理。拒绝帧与非有限重建结果的历史／先验保护、启动器停止确认与持续监管及构建输出保护使用当前项目源码；外部重建求解器、启动器、Bridge 和构建工具不随扩展 ZIP 安装。具体软件合同与适用检查见[源码验证](#源码软件合同与验证)。

公开 0.3.40 前端根据可见网格、数值测量、缺陷与导出消费者选择形变计算范围，保持隐藏 T1 的结构叶尖测量与共享塔架运动，并复用每次加载时校验的遥测数组。计时分别覆盖形变缓存查询与叶片重新绑定；实现见[前端维护说明](../../blender_frontend/README.md#51-三机结果包与九片形变)。工作量计数不等于 FPS，检查结论按下表的实际载荷使用。

项目后端对全场功率实行预期机组完整性校验，缺测保持无效；Bridge 在无客户端时仍推进任务生命周期，以独立有界队列处理可合并观察与可靠事件。Interactive 训练按每台机组的联合动作概率计算 PPO 比率，见[接口与生命周期](../../blender_frontend/README.md#55-实时连接与控制生命周期)和[算法配置](../training/MAPPO_SETUP.md)。普通 Python 包包含机型 YAML，并声明读取所需的 PyYAML 依赖；[环境安装](../setup/setup_local.md#2-python-环境floris-与算法开发)与 Blender ZIP 安装分别进行。

源码和资源通过不同入口分发：[源码分支](https://github.com/snode11/wind-farm-blender/tree/wind-farm-rl-all-work)用于实现、测试与文档；[project-resources-v1](https://github.com/snode11/wind-farm-blender/releases/tag/project-resources-v1)用于[资源清单](../PUBLICATION.md)标识的正式运行输入和证据，不作为新的扩展版本。资源恢复须保留清单规定的相对路径与来源身份。

手动场景与三相机、缺陷编辑器的串联暂缓，不属于当前交付范围。

独立 normal/close 净空演示由[交付清单](../../dist/lidar-delivery.json)指定两个外部结果包，使用[项目源码启动器](../../scripts/blender/open_clearance_demo.py)。清单与两包是正式运行输入，须一同保留；读取器核对包文件摘要、模型／片段身份及预计算统计，缺失或损坏时明确报错。清单的版本和 archive 字段标识其引用的 0.3.9 附件，不代表当前源码或公开扩展身份；该专用入口不安装扩展、不启动求解器，与扩展内置三机 MAPPO 离线回放分别使用。
