# 手动场景研究接口

本文描述工作区源码的研究操作器、属性和脚本。**风机控制**栏目使用[基本控制面板](风机手动控制.md)，不绘制冻结试验、Down 视频、外形选择或显示精度控件。安装载荷的能力与来源按发布及安装身份分别核对。

## 场景与冻结试验

`manual_control.confirm_trial(scene)` 整体校验 T1 当前实际姿态与 `scene.wfrl_manual_trial` 中的目标，冻结起点并开始试验。`trial_action(scene, action)` 接受 `START`、`PAUSE`、`RESET`、`END`：共同试验时钟控制叶轮和三片桨距，暂停同时冻结二者，复位回到试验起点，结束保留当前姿态。这些试验命令与普通控制面板的自动顺桨命令分开。

`wfrl_manual_trial` 的 `select_b1`／`select_b2`／`select_b3` 选择叶片，`target_b1_deg`／`target_b2_deg`／`target_b3_deg` 保存目标，`duration_s` 为正变桨时长；`interpolation` 为 `SMOOTH` 或 `LINEAR`。填写目标不应用姿态；未选叶片保留起始实际桨距。T1 启用试验时锁定外形、RPM 和普通姿态修改。`PitchTrial.pose_at(t)` 使用同一试验时间计算累计叶轮方位和桨距，达到目标后保持。

试验前若需立即设置起始桨距，应显式将 `scene.wfrl_manual_pitch_rate_deg_s` 设为 0，再写入起始姿态；普通场景的默认桨距是 90°、普通变桨速度为 5°/s，不能据输入目标推定模型已经到位。

## Down、外形与显示精度

`bpy.ops.wfrl.manual_down_view(turbine='T1')` 打开所选机组 Down；T1/T2/T3 使用各自机舱挂载，`manual_down.ensure_down_camera()` 创建或复用场景拥有的相机。`scene.wfrl_manual_blade_shape` 选择 `rootkink` 或 `nrel5mw`；切换保留姿态并更新配套装配，冻结试验启用时拒绝切换。

`scene.wfrl_manual_display_detail` 为 `OVERVIEW`、`STANDARD` 或 `CLOSE`，分别使用每片 4,417、8,065、15,361 个基础顶点。进入 Down 及视频副本使用近景，源场景与 MAPPO 柔性网格分别管理。

`bpy.ops.wfrl.manual_down_video('INVOKE_DEFAULT')` 提供所选机组 MP4／JSON 导出参数，要求匹配的 FFmpeg／FFprobe；冻结试验启用时使用独立后台视频作业。便捷导出在独立副本中只驱动所选机组，其他机组保留快照姿态；视口方式需要可见窗口。输出通过帧数、尺寸、帧率、时间戳及完整解码校验后拒绝覆盖地提交。

## 导出变桨视频

单叶片 20°、三分钟工况使用 rootkink 模型：起始三片均为 0°，T1 保持 9 RPM，仅选 B1，目标 20°，变桨方式为匀速，变桨时长 4 s、目标保持 176 s。前 4 s 的 B1 桨距为 `5t` 度，之后保持 20°，B2/B3 全程保持 0°；总长 180 s、4500 帧，叶轮持续旋转。

可从仓库根目录用以下命令生成该工况；`--output` 必须显式指定，已有 MP4、悬空符号链接及正在被其他作业占用的输出均不覆盖。命令等待最终结果，只有完成验证和发布才成功退出；失败或取消返回非零状态：

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup \
  --python-exit-code 1 --python scripts/blender/generate_manual_pitch_video.py \
  -- --output /absolute/path/T1-Down_B1-20deg_180s.mp4
```

需要脱离运行时，在生成命令末尾显式加 `--detach`；它仅确认启动，打印的 `job_path` 指向持久化的 `job.json`，不能据启动成功判断成片成功。关闭源 Blender 不会终止独立监管进程。启动后保存源 `.blend` 可保存面板关联，重开后恢复查询与取消；没有保存关联时，可直接用作业路径管理，无需打开 Blender：

```bash
python3 -B scripts/blender/manage_manual_video.py status --job /absolute/path/job.json
python3 -B scripts/blender/manage_manual_video.py wait --job /absolute/path/job.json
python3 -B scripts/blender/manage_manual_video.py cancel --job /absolute/path/job.json
python3 -B scripts/blender/manage_manual_video.py retry --job /absolute/path/job.json
```

`wait` 等待收尾；`retry` 默认等待，也支持 `--detach`。上述管理命令的最终结果退出码为完成 `0`、失败 `1`、取消 `130`、失去联系 `3`；`status` 对运行中的作业返回当前状态。取消会先请求终止，必要时强制停止该作业进程组中的 Blender、FFmpeg／FFprobe 及其子进程，完成收尾后才确认取消；若交付已经完整提交并核验，则保持完成。监管通过作业凭据验证本机端点，不会凭磁盘中可复用的 PID 杀进程。无法联系时显示 `LOST`，不推断为失败或取消；仍被进程持有的输出锁继续阻止重复作业。

视频旁边的 `<文件名>_data_<标识>/` 保存 `job.json`、PNG 母版、逐帧时间与姿态表、相机参数、试验配置、场景副本、状态及运行日志。只有所有帧生成后才产生完整母版凭据 `master.json`。编码、解码验证或发布失败后，`retry` 校验作业、配置、快照、源码与外部资源、相机、姿态表、连续帧数、每帧内容及编码参数，再仅执行编码、验证和发布；完整且属于该作业的已编码文件可复用。缺帧、损坏、来源不符、混合作业或没有完整母版凭据时拒绝，不补帧、不做逐帧渲染续传。此时需要使用新的输出名重新生成。已成功作业拒绝重试并保留成功状态；未知视频或他人文件不被覆盖。

输出在帧数、尺寸、时长、时间戳和严格解码通过后，先在目标文件系统暂存完整文件，再用拒绝替换的原子提交发布。渲染前检查该文件系统的提交和冲突保护能力；不支持硬链接的目标可使用原生的拒绝替换提交，无法安全发布时提前报错。并发新建的文件或符号链接仍会阻止最终发布，失败清理自有暂存文件。输出目录中的 `.wfrl-output-*.lock` 是持久化锁名，作业结束释放锁但保留文件，避免删除锁名造成并发竞争；不要在作业运行时手动删除锁文件或作业目录。

工作区源码的失败／取消状态允许在外部命令行对同一作业重试；面板异步刷新已过期的状态缓存，取消请求在后台核对当前 attempt。界面显示“正在查询”或等待取消确认时仍按活动作业处理，已完成交付保持终态。

冻结试验后台导出需要完整工作区源码、本机 **FFmpeg／FFprobe** 和独立 **Python 3.11+**；安装扩展使用偏好的 **Project directory** 指定配套项目。监管解释器可用 `WFRL_VIDEO_PYTHON` 指定，须支持 `flock` 和 `waitid(WNOWAIT)`；缺少接口时在启动前拒绝。便捷 Down 视频使用单独入口与独立场景副本。短片、监管与恢复检查不代表完整视频或渲染性能验收。

生成速度由电脑和渲染设置决定，25 fps 是成片播放帧率。每帧采样 `t=k/25` 的确定姿态，关闭运动模糊，属于瞬时合成成像；不模拟实体相机曝光或真实风机控制器。当前不接入 RTSP 或识别算法。
