## 2026-09-15–16 原方案与执行记录

日期：2026-09-15  
当轮状态：基础脚本与单机实体形变短片段已完成源码验证；三机 MAPPO 非稳态风客户演示尚待实施（不是当前总状态）。
范围：沿用现有 FAST.Farm 计算后端和 Bridge，最终在现有 Blender 风场模型中展示。

## 1. 演示目标

客户在 Blender 中看到风机正常运转，同时能看出叶片具有弹性：叶根保持连接，中段到叶尖连续弯曲，弯曲程度随时间变化，叶尖出现有幅度的往复摆动。

这种运动应由仿真结果驱动。不同圈的运动允许包含周期成分，同时应体现非稳态风作用下的变化，避免每圈重复同一条人工正弦曲线。

**最终显示对象是现有风机的叶片实体模型。** 独立 Python/OpenCV 预览用于验证计算与数据；最终客户演示在 Blender 内完成。

## 2. 已确定的总体路线

采用“提前计算、保存结果、离线回放”的方式。

```text
非稳态风况 + 风机结构模型 + MAPPO 控制策略
                         ↓
              现有 FAST.Farm 后端计算
                         ↓
       导出并校验形变、姿态、叶尖与相关状态数据
                         ↓
                  本地轻量回放包
                         ↓
             现有 Bridge 回放服务与数据接口
                         ↓
          Blender 叶片网格形变、叶尖轨迹与读数
```

- 后端提前完成物理求解，客户演示时读取已经保存的数据。
- 必须接入现有 FAST.Farm 后端和 Bridge，不新增 FastAPI Web 服务。
- 演示时可以运行轻量 Bridge 回放服务，但不需要持续运行 FAST.Farm 求解器或强化学习训练。
- 初步以约 **60 秒有效展示片段**为目标，后续按展示需要扩展至 120 秒。显示目标为稳定 **60 FPS**：片长与帧率独立，60 秒在 60 FPS 下约显示 3600 帧；按正常速度播放，不因提高帧率而加速。此为目标，尚未完成目标电脑实测。
- 用户确认：播完自动暂停在最后一帧，叶片、标记和轨迹保持最后状态；由用户手动重播，不自动循环。
- 仿真总时长可以更长；正式展示片段应避开启动瞬态，具体截取范围由结果检查确定。

离线回放将物理求解开销移出展示过程。Blender 仍需要更新网格和绘制轨迹，因此回放包大小、缓存和轨迹数量仍需控制。

## 3. 风况与三台风机的控制行为

### 3.1 风况

客户版需要非稳态风况：风速随时间变化，转子覆盖范围内不同位置承受不同来流，叶片据此产生结构响应。

计划采用与 FAST.Farm 配套的湍流风场输入；具体生成工具、参数与工况配置在物理实施阶段核实。风场变化应与驱动叶片的仿真输入一致，不能只让画面里的风动起来。

用户同意试几组更强、带时间变化的风况，选择真实摆动清楚的片段；风速与波动强度由短片段结果筛选，不在前端夸大形变。

现有单机稳态风归档结果可用于检查数据读取、坐标转换和显示链路，不能据此宣布客户版非稳态风演示已经完成。

### 3.2 三台风机与偏航

- 最终面向场景中的 T1、T2、T3 三台风机，每台使用对应的姿态和叶片数据。
- 避免当前演示中播放几秒后三台风机按预设动画统一向侧面偏转的表现。
- 用户希望机舱调整来自项目实际控制逻辑，呈现合理、平滑的调整。
- 用户最新确认：本 demo 使用项目已有的**三机 MAPPO** 路线，取代此前的 PPO 选择。优先核实并复用三机 FAST.Farm 对应模型；训练记录存在不等于可直接部署，仍需确认检查点、归一化参数及三机配置。
- 偏航幅度和变化速度应由控制约束及结果决定。用户希望偏转较小，这应在工况与策略设计中实现，不直接在前端缩小或伪造策略输出。

叶片弹性摆动与机舱偏航是两个运动过程，回放时组合到同一姿态中，并使用同一仿真时刻。

## 4. 后端需要提供的数据

单独一个叶尖位置不能确定整片叶片的形状。后端需要输出从叶根到叶尖沿长度分布的截面信息。

建议回放包至少包含：

| 数据 | 用途 |
| --- | --- |
| 仿真时间与机组编号 | 三台风机、视角和读数同步 |
| 每片叶片的截面位置及朝向 | 驱动连续弯曲，并保留截面姿态信息 |
| 三片叶片各自的叶尖参考点 | 标记与轨迹 |
| 机舱偏航、转子方位角、转速和变桨状态 | 组合整机与叶片运动 |
| 坐标系、单位及变换约定 | 正确转换到 Blender 场景 |
| 数据来源、有效性与完整性信息 | 区分仿真、估计、缺失与演示数据 |
| 同步展示所需的风况、控制与净空数据 | 保持画面和读数一致 |

实施时需要明确：截面数据是局部形变还是已经包含旋转、偏航的世界坐标，避免在 Blender 中重复施加运动。

FAST.Farm 中的各机组由 OpenFAST 计算；正确配置结构模型和可视化输出后，可以保存变形后的叶片表面。FLORIS 本身不求解这类结构形变。已确认读取和传输环节存在缺口：原始 VTP 含截面周界点，但读取器只保留了均值；后续应从原始几何提取截面姿态或保留必要表面信息。此外仍须核实物理模型、三机输出设置、实体绑定和读数更新，不能把全部工作概括为“多读几个字段”。能够恢复的运动以所用结构模型为准，不能把未启用的弹性扭转当作已有输出。

本轮读取器已经能从归档表面数据提取截面周界的坐标均值与叶尖参考点。这条路径可验证截面运动，但这些均值不等于结构中性轴；完整截面朝向与实体网格的绑定仍需在后续集成中处理。

最终客户包应保存回放所需的轻量数据，避免演示现场逐帧解析大量原始表面文件。当前原始文件读取方式属于开发验证阶段。

## 5. Blender 中的叶片显示

- 使用现有叶片外形和材质，让叶片实体随仿真截面运动连续变形。
- 叶根保持正确连接，叶片中段到叶尖平滑过渡，不用一根轮毂到叶尖的直杆代替完整叶片。
- 三片叶片分别绑定自身数据，旋转过程中保持编号一致。
- 叶尖标记与实体叶片使用一致的参考点定义和坐标变换，避免标记脱离叶片。
- 网格驱动方法在检查现有拓扑后确定；可以采用截面绑定等方式，不在本方案中提前锁定具体实现。
- 保留真实仿真幅度。优先通过取景、观察方向和片段选择，使客户看清柔性运动。

**叶片弯曲是演示的基本状态。** 无论轨迹开关是否开启，叶片都持续按回放数据旋转、弯曲和回摆。

## 6. 侧边“叶尖轨迹”开关

放入现有 Camera 相机与演示侧边区域，复用当前回放交互。

### 6.1 颜色与内容

| 叶片 | 轨迹与当前叶尖标记 |
| --- | --- |
| 叶片 1 | 橙色 |
| 叶片 2 | 蓝色 |
| 叶片 3 | 红色 |

颜色跟随叶片编号，不因转到不同位置而交换。避免使用绿色，以区别现有荧光绿风场。

### 6.2 开关行为——按最后一次讨论确定

1. 打开 demo 时，默认没有彩色轨迹或叶尖辅助标记。
2. 点击开启后，从当前叶尖位置开始记录和显示；不预先加载一整圈历史线。
3. 播放继续时，轨迹从一个点、短弧逐渐延伸，随着旋转形成一圈，再继续形成后续圈。
4. 轨迹记录真实三维位置；叶片弹性运动使路径产生前后偏移和起伏，不同圈不必完全重合。
5. 关闭后，三种颜色的辅助轨迹和叶尖标记全部隐藏，叶片运动继续。

此前“一开启就显示完整历史圈”的建议已经取消。数据虽然预先计算，画线仍按演示进度逐步展开。

轨迹缓存需要有上限。建议容纳数圈并让较旧部分逐渐淡出；具体圈数和淡出效果通过画面密度确定，不将“最近 3 秒”或“两圈”作为已经定下的要求。

### 6.3 回放与视角规则

| 操作 | 预期行为 |
| --- | --- |
| 暂停 | 叶片、标记和轨迹停在同一时刻 |
| 播放到片尾 | 自动暂停并保持最后一帧，等待用户手动重播 |
| 暂停时转动观察相机 | 只改变观察角度，不推进仿真时间 |
| 切换 Down、全景或其他视角 | 保持当前时刻，显示同一组形变与三维轨迹 |
| 关闭轨迹 | 隐藏轨迹及辅助标记，继续显示叶片运动 |

以下采用实施建议，尚未逐项确认：再次开启时从空白重新记录；拖动进度、从头重播或切换工况时清空旧轨迹，从目标时刻重新绘制。这样可避免跨越跳转时刻或片段首尾画出错误连线。

多机总览时同时显示多少台机组的轨迹，需要根据遮挡与可读性决定；每台机组内部保持上述三色编号约定。

## 7. 观察视角与验收

### 7.1 Down 内侧观察

复用用户新加的 Down 视角，从叶片内侧观察叶尖经过与叶片变形。

最低视觉要求：在该相机中，肉眼能够清楚看到叶片有幅度地摆动，且连续运动不呈现完全重复的固定曲线。仅看到叶片刚性转动、或只有标记点在动，不算完成。

### 7.2 全景同步

全景、单机视角与 Down 观察同一组物理状态。切换镜头不重置时间、不更换形变数据。全景中的可辨认程度受取景尺度影响，应结合单机与 Down 视角共同验收。

### 7.3 客户演示验收清单

- [ ] 三台风机使用对应的非稳态仿真结果与控制状态。
- [ ] Blender 实体叶片连续变形，叶根连接正确，叶尖与实体同步。
- [ ] Down 内侧视角能清楚观察到随时间变化的弹性摆动。
- [ ] 全景与相机视角使用同一仿真时刻。
- [ ] 轨迹默认关闭，开启后从短弧逐渐画成圈，关闭后辅助线与标记全部消失。
- [ ] 橙、蓝、红三色保持叶片编号一致，换相机不会产生额外轨迹。
- [ ] 暂停、重播、寻址与切换工况没有跨时刻连线或状态不同步。
- [ ] 偏航来自 MAPPO 控制逻辑，符合设定的幅度与速率约束。
- [ ] 本地回放无需现场求解或训练；持续播放时缓存有界，流畅程度通过目标电脑实测。
- [ ] 数据来源与无效状态明确，画面幅度和读数能够对应仿真结果。

## 10. 方案审查：实施前需要补齐的缺口

审查日期：2026-09-15。总体路线可保留；以下来自文档与当前代码静态核对，属于待验证的实施风险，不表示已经发生运行故障。

### 10.1 MAPPO 模型与三机物理环境的适配

仓库已有 `Dec_Turb3_Row1_Fastfarm`、标记为 `mappo` 的三机训练记录。用户已选择沿用此路线，不再以七机 PPO 入口作为接入对象。首先盘点对应的可用模型，核对机组数量与顺序、观测和动作维度、单位、目标角度或角度增量的动作含义、控制周期及归一化统计量；不匹配时完成适配与评估，再决定是否需要训练。

回放包应记录 MAPPO 检查点标识或哈希、环境配置、归一化参数来源、风场种子，以及策略命令与实际偏航。限幅和速率约束在物理计算阶段执行，回放使用实际响应。60 秒片段用于展示运动，不能单凭片段宣称 MAPPO 提高发电量或降低载荷；如需展示收益，增加相同风况下的基线评估。

### 10.2 截面路径尚不足以绑定实体叶片

当前 `wfrl/blender_bridge/tip_replay.py` 对截面周界取均值，仅导出 `sections_m/tip_m`，没有完整截面朝向。仅沿中心路径弯曲仍可能丢失扭转或出现截面翻转、叶根错位。

绑定前需确定未变形参考几何、截面局部基、展向对应和叶根连接变换；明确预弯、预锥、轴倾角、变桨、转子旋转与偏航分别在哪一层施加。先验证零形变姿态，再验证弯曲与旋转组合。叶尖参考点必须与实体上的约定点对应，不能默认截面均值就是外形最尖端。

### 10.3 单机链路尚未覆盖三机同步

当前读取器按包的单个 `turbine_id` 生成单机快照，`sample_from_snapshot` 要求选定一个机组。三机同步仍需聚合、机组映射和统一时间轴。

应规定共同有效时间区间、缺帧处理和包完整性校验。不能复制单机形变作为另外两台各自的仿真结果；无效数据不能继续显示成当前有效值。

### 10.4 采样与插值规则不够具体

应分别记录物理输出步长、MAPPO 控制周期与渲染时间，以回放时间统一采样姿态、形变、标记和读数。方位角跨越 360° 时需展开，截面朝向需保持旋转连续性，避免将 359° 到 1° 按普通标量插值造成倒转。

用户已同意补充中间画面、跨 360° 保持正确转向，以及减小数据量时保留真实摆动。降低采样率后应与原始结果比较叶尖位置及形变峰值误差，防止滤掉真实摆动。跳转和手动重播时清空旧轨迹，从目标时刻重画；片尾自动暂停并保留最后画面，不自动循环，也不连接片尾与片头。

### 10.5 可见性与量化验收不足

非稳态风输入本身不能证明摆动肉眼可见。三机长时计算前，先用短片段验证柔性响应、Down 取景和实体绑定；检查扣除整机刚体运动后的叶尖位移，避免把偏航、旋转或相机运动当作弹性摆动。

用户已确认以稳定 60 FPS 为显示目标；实际能否达到需在目标电脑验证。验收前需确定目标电脑、允许的帧率波动、内存上限、同步误差、叶根连接误差、叶尖绑定误差及降采样误差的数值标准，由原始数据和短片段实测确定。本轮不虚设已经达标的阈值。现有净空是叶尖参考点到同高度塔筒截面的距离，不代表整叶片最小碰撞间隙。

### 10.6 建议的实施关口

1. 验证单机短片段的完整截面姿态、实体形变与可见性。
2. 核实 MAPPO 与三机环境接口，验证约束后的实际控制响应。
3. 完成三机统一时间轴及轻量包导出，再生成正式展示片段。
4. 在目标电脑验证交互、精度、性能及脱离原始数据目录后的可移植启动。

本轮仅修订方案，未启动训练、仿真、Blender 集成或发布。

相关能力依据：[OpenFAST 可视化输出说明](https://openfast.readthedocs.io/en/main/_downloads/5f2ddf006568adc9b88d8118dc3f1732/FAST8_README.pdf)、[FLORIS 模型说明](https://www.nlr.gov/research/software/floris-flow-redirection-and-induction-in-steady-state)。


## 11. 按项目技能复查：补齐完整演示链路

使用技能：[windfarm-blender-dev](../../.agents/skills/windfarm-blender-dev/SKILL.md)。按其中的数据格式、物理算法、回放同步和安装交付检查要求复查。以下为静态证据和实施要求，未运行新仿真或 Blender 性能测试。

### 11.1 把“支持输出”变成明确的交付步骤

抽查 `results/lidar/raw/normal-v1/FarmInputs/Case.fstf`：`NumTurbines=1`，总时长 36 秒；WT1 开启表面动画输出，目录中 WT2/WT3 的配置为 `WrVTK=0`。这些配置只能证明该单机归档的用途，不能证明其他工况也相同，更不能作为三机 60 秒正式数据已齐全的证据。

实施时需逐项交付：

1. 三机正式配置及足够的仿真时长，截取稳定后的约 60 秒共同区间。
2. T1/T2/T3 共九片叶片的表面或截面姿态数据，逐台核实实际输出。
3. 保留朝向和参考几何的轻量包，以及能传递这些字段的 Bridge。
4. Blender 中真正使用这些字段的网格驱动。现有 `clearance_replay.py` 的姿态更新主要设置机舱、转子和变桨，不能替代实体弯曲实现。
5. 原始表面、轻量包和 Blender 同一时刻的对照，证明形状没有在中途丢失或变错。

### 11.2 弯曲与弹性扭转要分清

抽查归档为 `CompElast=1`（ElastoDyn），叶片前后及侧向弯曲开关已开启。它可以作为弯曲显示的起点；补齐截面朝向也有必要，但不能因此声称已计算叶片沿长度的弹性扭转。后者如成为需求，应评估 BeamDyn 模型与参数，再决定新求解范围。当前 demo 以真实弯曲摆动为主，不自动扩大为必须升级结构模型。

能力依据：[OpenFAST 官方 BeamDyn 说明](https://openfast.readthedocs.io/en/v3.5.3/source/user/beamdyn/introduction.html)。

### 11.3 60 FPS 需要重新安排播放时间

现有 `clearance_replay.py:sample` 将保存的帧编号按固定 `wfrl_clearance_timebase_fps` 映射到仿真时间，仅改变 Blender FPS 会改变播放速度。因此新 demo 不能只把设置框改为 60：必须将显示帧、原始数据采样和播放时间配套安排，保证仿真 60 秒正常播放仍约为现实 60 秒，并回归暂停、寻址与手动重播。

60 FPS 不要求 MAPPO 每秒决策 60 次。算法按原控制周期运行，画面在中间补出平滑动作；原始采样能否保留摆动细节另行验证。卡顿时整组姿态、叶尖和读数必须使用同一目标时刻；不能让其中一项单独落后。性能测试应覆盖三机实体、风场和轨迹同时开启的实际画面。

### 11.4 更强的风还要核对控制器是否适用

本轮找到候选权重 `results/checkpoints/mappo_fastfarm_Dec_Turb3_Row1_Fastfarm_mappo_s0_level_E128_none.pt`，但没有加载或评估。后续优先核实该模型，而非仅凭训练记录或文件名宣称可用。风况变强后应验证策略输出和实际偏航是否仍合理；明确 MAPPO 控制哪些动作，转速与变桨由哪个控制器或设置负责，避免两个控制来源同时写入。

短片段应同时检查叶片摆动、转速与控制状态。抽查旧归档 `GenDOF=False`，不可直接把这种固定转速验证配置当作新风况下完整控制响应的证据。

### 11.5 新叶片数据必须配新读数和一致的观察位置

若客户版改了风况和形变，净空真值、雷达模拟读数与统计须从同一新片段生成；不能复用旧单机片段的数字配上新叶片。读取不到对应数据时应显示未就绪。若物理计算启用了塔筒或机舱运动，需同步相机、雷达安装点和整机姿态；若保持刚性支撑，应在物理配置与显示端保持一致。

新增字段需约定包版本与兼容规则。旧包缺少形变所需信息时可以继续用于原有演示，但不能自动当作完整柔性包。最终安装包及随附数据须离开开发目录验证启动，避免源码中能读到的数据在客户电脑上缺失。

### 11.6 本轮结论

预计算、离线回放、三机 MAPPO、约 60 秒、60 FPS 目标和片尾暂停的总体路线可保留。当前应先打通一个短片段的“物理输出 → 完整数据 → 实体叶片 → 同步读数”，再扩展到三机正式片段；这些缺口需要实施和验证，本次审查没有将其标为完成。
