# 自动检查

[Checks 工作流](../../.github/workflows/checks.yml)在 pull request、`main`／`wind-farm-rl-all-work` 分支 push、`v*` 标签 push 及手动触发时运行。宿主与 CPU 数值检查使用 Ubuntu 24.04 的 Python 3.11 和 3.12；两者通过后，标签与启用 `native` 的手动运行还执行 Blender 后台及隔离安装检查。工作流只读取仓库，测试结果作为 Actions artifact 保留 14 天，不发布附件或替换日常安装。

## 宿主合同

[requirements-ci.txt](../../requirements-ci.txt)提供前端宿主、发布身份和 Bridge 协议／进程生命周期检查的依赖。宿主视频监管测试要求 POSIX Python 提供 `os.waitid`、`os.WNOWAIT`、`os.P_PID` 和 `flock`；Python 版本号本身不保证这些接口存在。

从 Git 根目录使用具备上述能力的 Python 环境：

```bash
python -m pip install -r requirements-ci.txt
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=blender_frontend:. python -m pytest \
  blender_frontend/tests tests/test_release_identity.py -q -p no:cacheprovider
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=blender_frontend:. python -m pytest \
  tests/blender_bridge \
  --ignore=tests/blender_bridge/test_episode_worker.py \
  --ignore=tests/blender_bridge/test_farm_power_validity.py \
  --ignore=tests/blender_bridge/test_training_progress.py \
  --ignore=tests/blender_bridge/test_trainer_stop.py -q -p no:cacheprovider
```

前端宿主集包含临时目录中的扩展可重复构建检查。Bridge 选择不包含依赖 PyTorch／WFCRL 的训练 worker、功率训练、实际训练进度与 Trainer 停止测试；这些测试使用[训练环境](../training/MAPPO_SETUP.md)独立运行。宿主模拟结果不代表真实后端训练或求解验收。

## CPU 数值合同

[requirements-ci-numerical.txt](../../requirements-ci-numerical.txt)在宿主依赖上提供固定 PyTorch 与无窗口 OpenCV。CI 使用 PyTorch 官方 CPU 索引，不安装求解器、MPI、WFCRL 或 GUI；求解与图形依赖只在实际创建采样器或视图时加载。

```bash
python -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.13.0
python -m pip install -r requirements-ci-numerical.txt
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=blender_frontend:. python -m pytest \
  tests/test_numeric_imports.py tests/test_fastfarm_training_integrity.py \
  tests/test_stage3_comparison.py \
  tests/test_blade_recon_scoring_contract.py tests/test_policy_action_contract.py \
  tests/test_interactive_ppo_objective.py -q -p no:cacheprovider
```

该选择检查实验配置与完成身份、对照运行配对、恢复前校验、RNG／奖励状态、GRU 逐步和分段前向、相邻步价值归一化、回合截断、同模型评分及动作合同。物理依赖不可用时仍须完成数值计算；合成真值检查使用微型本地图像，不生成正式研究结果。Bridge 循环连接测试按截止时间累计 TCP 分片，等待目标握手或快照，重连使用新的帧解码器；固定等待或单次 `recv()` 不作为完成条件。

## Blender 后台与安装

专项后台选择包括柔性回放保存恢复、非手动序列采集事务和同源纹理资源回滚：

| 脚本 | 检查范围 |
| --- | --- |
| `farm_reopen_settings_regression.py` | 临时文件保存重开后的仿真映射、输出与预览配置、机组及来源身份；`WFRL_REOPEN_VARIANT=farm/dual/tls` 选择来源。 |
| `farm_capture_transaction_regression.py` | 真实 Scene／Window／View Layer 上的归属、映射变化、已提交组和恢复保护；图像与播放使用适配器，不证明 GPU 像素或原生播放。 |
| `split_mappo_texture_rollback_regression.py` | helper 分配及激活故障、自有数据块回收、外部引用与用户保留资源保护、Scene 生命周期和完整样本重试。 |

工作流从 Blender 官方下载地址获取固定的 Linux Blender 5.2.1，核对固定 SHA-256 后运行。具体后台选择由 [ci-native-tests.txt](../../configs/ci-native-tests.txt)维护，涵盖 WFRL 主入口、手动运动状态、变桨、原生控制冲突、冻结试验、姿态撤销、场景恢复和场景关联，以及相机加载／模块重载失效、跨 Scene／相机标记／视口的对象归属保护与连接身份恢复。短 PNG 动画检查覆盖完成、取消、源状态保留及独立回放恢复失败时的前置拒绝；视频生成脚本另核对近景网格与冻结试验准备，模式切换检查其他 Scene 的动画、可见性和历史保护；相机采集检查覆盖单次求值几何提取、签名／碰撞几何一致性及原生网格、修改器和镜头变动保护。连接恢复脚本使用原生 RNA 和本地 socketpair，不启动 TCP Bridge 或真实训练，不验证确认框的鼠标操作；这些后台检查不测量可见窗口 FPS。

本地可复用相同选择；输出须为新目录：

```bash
python scripts/blender/run_regressions.py \
  --blender /path/to/Blender --test-list configs/ci-native-tests.txt \
  --output /path/to/new-native-results
python scripts/blender/validate_frontend_package.py \
  --blender /path/to/Blender --output /path/to/new-package-results
```

运行器使用上述宿主依赖，为每个脚本启动独立工厂进程和配置目录，同时核对源码来源、稳定摘要、正常退出、完成标记及最终 JSON。未预期的 Python traceback（包括 ExceptionGroup）覆盖成功凭据；脚本声明的预期异常按完整类型／消息及次数核对，普通说明和 JSON 转义文本不作为执行异常。进程收尾通过继承的运行标识和创建时间追踪自有后代，父进程退出不代替清理完成。缺失、超时、跳过和未完成不作为通过；失败仍保留诊断文件。安装检查构建独立 ZIP 并使用隔离扩展 profile。宿主 JUnit、后台结果和包验证保存在工作流的 `ci-results/`。

这些检查只覆盖软件合同与声明输入，不测量可见窗口交互、完整片段 FPS、完整视频、科学精度或现场性能。工作区检查、公开包和日常安装的身份分别按[发布状态](../blender/发布状态与验证范围.md)使用。

## 发布身份摘要

[README](../../README.md#当前身份与安装来源)中 `release-identity` 标记内的版本、文件数量与载荷关系取自明确指定的交付 JSON 和 [daily-installation.json](../../publication/daily-installation.json)。安装记录宣称与公开包同一载荷时，核对状态、版本、归档摘要及文件数必须一致；独立安装可以使用不同版本。摘要不由工作区 manifest 推定公开载荷，也不修改原验证记录。

```bash
python scripts/ci/check_release_identity.py --release publication/blender-0.3.42.2.json
python scripts/ci/check_release_identity.py --release publication/blender-0.3.42.2.json --write
```

默认检查不写文件，不一致时退出失败。`--write` 只替换唯一成对标记内的摘要，保留其余正文。当前发布记录的路径由命令和工作流参数明确指定；发布对象变化时，参数指向对应交付记录。
