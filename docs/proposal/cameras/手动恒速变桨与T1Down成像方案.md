# 手动恒速变桨、T1 Down 成像与视频输出方案

## 目标与适用范围

已确认的目标是：在手动场景中设定恒定叶轮转速，选择同一台风机的一片、两片或三片叶片，分别输入目标桨距角；确认后，各叶片通过连续动画到达目标桨距，T1 Down 相机观察相同模型并输出图像和离线视频。需要视频流时，再将对应素材按约定方式交给同事接收。

用户负责运动设置、变桨动画、相机成像和输出接口；同事负责接收这些素材并开展后续识别算法工作。本方案的交付终点是同事能够读取图像、视频文件或约定的视频流。识别方法、算法实现、识别结果和算法精度验收由同事负责，不作为用户这一部分工作的完成条件。

叶轮转角与叶片桨距是两个独立变量：

- 叶轮转角：三片叶片共同绕主轴转动的方位角，由恒定 RPM 和试验时间确定。
- 叶片桨距：每片叶片绕自身长轴转动的角度，是各片独立的动画输入。

工作区源码支持独立手动场景中的 **rootkink 叶片模型、T1 单组恒定 RPM 变桨和固定 T1 Down 观察**，变桨方式可选平滑或匀速，操作见[手动控制说明](../../blender/风机手动控制.md)。工作区同时提供冻结试验起点的独立后台渲染、PNG 母版及 MP4 输出，尚未进入公开安装包或日常安装。手动工况的 RTSP 接入与接收端联调不在当前实现范围。输出要求为 1920×1080、25 fps，默认先用 8 s 平滑变桨，再保持目标桨距继续旋转 7 s；全程使用同一正 RPM，总长 15 s、375 帧。同事接收方式仍待确认。

场景采用现有手动控制的刚性模型与预设运动，不启动 FAST.Farm、Bridge 或训练，不生成对应的气动载荷、柔性形变、功率或雷达结果。变桨动画表达规定的姿态变化，不模拟实体执行器的动力学。

## 操作流程与参数

试验对象为 T1 的 B1/B2/B3，采用商用形制叶根拐点改型 rootkink；三片叶片始终存在，选择叶片只决定哪些桨距参与修改，不隐藏未选叶片。T2/T3 的已有参数不受该试验影响。

当前操作流程为：进入手动场景 → 设置恒定 RPM 和初始姿态 → 选择叶片并输入各自目标桨距及变桨时长 → 确认并开始 → 观察 T1 Down → 设置目标保持时长 → 导出 MP4。文件传输与接收方式按实际约定；手动工况的文件推流和接收端联调尚未验证。

当前输入和读数如下：

| 项目 | 当前行为 |
| --- | --- |
| 恒定转速 | 使用 T1 RPM 输入；一次试验内固定，结束试验后可调整 |
| 叶片选择 | B1/B2/B3 独立勾选，可选一片、两片或全部；未选叶片保持已有桨距 |
| 目标桨距 | 每片分别填写，只是待应用值；填写期间不改变实际模型 |
| 当前桨距 | 显示各叶片当前实际动画角度，与目标值分开 |
| 变桨时长 | 一个共同的正时长，使选中叶片同时开始、同时结束；默认 8 s，界面最小 0.01 s |
| 确认并开始 | 一次校验所选叶片和目标值，以当前实际姿态为起点启动试验；无选择或参数无效时不改变模型 |
| 运行／暂停 | 共用试验时钟；暂停同时冻结叶轮旋转和变桨动画 |
| 复位试验 | 暂停并恢复该试验保存的起始姿态；重新开始可重复预览 |
| T1 Down | 切换至固定下视相机，运行状态与试验时间保持不变 |
| 目标桨距保持 | 默认 7 s，变桨结束后保持目标桨距并继续按规定 RPM 旋转 |
| 导出 MP4 | 从最近确认的起点生成完整视频，默认 15 s；后台进度、取消与完成后打开视频由手动面板提供 |

采用单次试验、一组目标值的交互：点击“确认并开始”时，记录同一时刻的叶轮方位和三片实际桨距，并将试验时间设为零。叶轮按已设置的正 RPM 运行，选中叶片立即开始过渡。叶轮原本已在旋转时保留当前方位，不跳回零度；原本暂停时直接开始，不要求再次点击另一个运行按钮。

试验暂停后使用“继续”恢复同一时钟，不重新从零变桨。复位暂停并恢复保存的起始姿态，可继续重复同一试验；确认另一组目标前，先结束当前试验并保留当前姿态。试验期间锁定 T1 姿态、RPM 和目标输入，通用运行／暂停／复位入口也使用试验时钟，不由普通叶轮时钟重复写入 T1。

动画输入沿用现有预览范围：RPM 为 0–30，桨距为 −30° 至 90°。恒速旋转试验要求 RPM 大于零，变桨时长为有限正数；这些是界面范围，不是实体风机运行限值。先校验所有目标，再一起开始，不能让部分叶片已动作、其余叶片因输入错误被拒绝。过渡起点取各片当前生效的桨距；切换独立桨距模式不得改变未选叶片的实际桨距。

现有“三片统一桨距”会覆盖独立桨距。试验界面应明确区分统一设置与独立叶片设置，避免填写独立目标时触发统一覆盖。

## 运动与时间定义

恒定转速为 n RPM 时，未取模的叶轮角度定义为：

`theta(t) = theta0 + 6 * n * t`，角度单位为度，时间单位为秒。

显示角度可以对 360° 取模，累计转角必须保留圈数。沿用现有 B1 方位角零点与正方向，保留三片叶片的 120° 装配间隔、轴倾角和预锥角，不把“朝下”解释为叶片在世界坐标中绝对竖直。

对选中叶片 i，以共同的开始时刻和时长计算归一化时间：

`u = clamp((t - t_start) / duration, 0, 1)`

平滑方式使用 `s(u) = 3*u*u - 2*u*u*u`；匀速方式使用 `s(u) = u`。

`beta_i(t) = beta_i_start + (beta_i_target - beta_i_start) * s(u)`

平滑方式的起止变桨速度为零；匀速方式的变桨角速度为 `(beta_i_target - beta_i_start) / duration`，完成后变桨速度为零。两种方式均在到达目标后保持目标桨距。不同叶片可有不同目标值，但共用同一次事件的开始时刻、时长和变桨方式。未选叶片保持起始时生效的桨距。

`manual_motion.PitchTrial.pose_at(t)` 根据冻结起点、RPM、三片目标、选择和时长，同时确定累计叶轮方位和三片桨距。试验开始时 t 为零，视口按实际经过时间推进；暂停时长不计入运动。`.blend` 保存试验配置、模型身份与试验时间，重开和撤销重做后暂停。离线渲染复用该计算，直接按输出时间采样，不依赖视口 FPS、定时器调用次数或机器渲染速度。

## T1 Down 成像

在手动场景中复用 T1 Down 的挂点计算和光学预设：相机挂在机舱坐标系上，光心位于实际机舱前部底壳挂点下方 0.40 m，光轴沿机舱局部正下，水平视场为 110°，镜头偏移为现有预设。具体安装定义见 [Down 说明](../../blender/T1Down机舱下视.md)。

`ensure_gimbal()` 默认按 `WFRL.Turbine.T1.YawRoot` 查找对象；手动入口显式传入手动条目的 `yaw_object`、独立相机名和归属标识，复用挂点与光学计算。相机和镜头独立归属于手动场景，无需先加载 MAPPO，不引用原 MAPPO 相机。当前仅接入 T1 Down，不串联 C1/C2/C3 共盒三相机或缺陷编辑器。

相机观察的叶片必须就是手动控制驱动的叶片。相机随机舱朝向变化，不随叶轮旋转、不追踪单片叶片。一次试验固定机舱朝向、相机安装、镜头、输出画幅、灯光和模型身份；调整这些条件应生成另一份试验配置。

必须保留机舱、轮毂、叶根封口、塔筒及叶片自身的真实遮挡。T1 Down 是局部下视成像，不要求整片叶片或完整叶轮始终在画面中，也不通过隐藏结构或动态变焦制造可见性。

成像检查应覆盖选定 RPM、桨距范围和过渡过程，核对：

- 叶片进入画面以及离开画面的区间。
- 画面是否显示对应叶片实际的变桨变化。
- 叶片轮廓、纹理、遮挡和画框裁切的实际情况。
- 不同叶片经过时是否存在画面异常或输出时间不连续。

已有 Down 有限姿态检查不构成这一运动范围的可见性验收。交付样片应如实呈现该机位的可见区间与遮挡；同事可据样片提出图像输入要求，用户负责按双方约定提供成像与输出。

相机固定时，选中多片叶片不意味着它们会同时进入画面。变桨时长如果短于相邻可用观察区间，某片可能在离镜时完成变桨。需要展示每片的变化过程时，建议延长动画，使其覆盖至少一圈的经过机会，并按实际画面确认；仅延长视频中目标桨距保持的时间，不能补回已经结束的变桨过程。

## 离线图像与视频

导出使用最近确认的运动配置，包括试验起始姿态、恒定 RPM、所选叶片、各片目标桨距和变桨时长。模型、材质与灯光由导出时的场景副本保存；后台恢复固定 T1 Down 机位，并记录输出相机、画幅、帧率、片长和采样方式。即使预览已经变到目标角，导出仍从该试验的起始状态计算；不能只保存当前最终姿态，再将其旋转成片。

`manual_video.py` 保存独立场景副本与已确认配置，启动 Blender 后台进程；`manual_video_render.py` 读取作业，恢复 T1 试验起点并逐帧计算。后台停用手动墙钟，只驱动 T1，T2/T3 固定在快照姿态。独立作业不改变原窗口预览，也不受随后窗口操作影响。渲染采用 EEVEE，产品入口默认 16 个采样。

对 N 帧、帧率 f 的视频，视频时间和试验采样时间均为 `t = k / f`，其中 k 从 0 到 N−1。片段时长为 N/f，采样范围为 `[0, N/f)`；默认最后一帧对应 t=14.96 s，编码片长为 15 s。每帧直接计算这一时刻的完整姿态，关闭运动模糊。成像采用瞬时采样，不模拟实体快门或曝光积分。

输出规格为 1920×1080、25 fps；默认变桨时长 8 s，随后保持目标桨距 7 s，总计 15 s、375 帧。全程使用设定的正 RPM，保持阶段只停止桨距变化，叶轮继续旋转。手动面板固定使用该画幅和帧率，变桨时长及目标保持时长可调整，两者之和必须为 0.04 s 的整数倍。编码复用现有 25 fps 编码器；柔性回放渲染器自己的尺寸与来源校验保留。

PNG 保留逐帧母版，再编码 MP4。输出取相机渲染图像，不录制 Blender 窗口；侧栏、鼠标和视口尺寸不进入成片。逐帧核对帧数、顺序、时间戳和严格解码，不能把缺帧补成重复帧。每次试验使用独立输出目录，配置不匹配时不能混入已有帧或覆盖其他素材。

原始图像和视频不叠加角度、叶片编号或检测线。试验参数与用于核对的姿态数据单独保存。固定采样方式、画幅与色彩设置，保留材质和遮挡；交付说明明确素材来自刚性动画与合成成像。

输出组织如下，用户选择的 MP4 路径与中间文件目录位于同一父目录：

```text
trial.mp4
trial_data_<标识>/
  video.mp4
  master_frames/
  frames.csv
  camera.json
  experiment.json
  scene.blend
  job.json
  status.json
  process.log
  checks/
```

面板显示渲染进度并允许取消；取消或失败保留中间文件。已有 MP4 和已有作业结果均拒绝覆盖。编码完成后先核对帧数、尺寸、时间戳、时长并严格解码，再将完整视频写入用户选择路径。FFmpeg／FFprobe 缺失时明确报错。

`master_frames/` 使用连续的 `000000.png` 等文件名，`frames.csv` 保留现有编码器需要的 `frame_id`、`video_pts`，两者均从零连续编号；时间基为 1/f。`time_s` 是视频与试验共用的 k/fps 时刻，另存固定 RPM、累计叶轮方位、三片桨距和 `transition`／`hold` 标记。

`camera.json` 保存对应分辨率下的相机配置；`experiment.json` 保存冻结试验、时长与采样定义、场景副本摘要、rootkink 资源摘要及实际加载源码身份。向同事交付视频与约定参数即可；逐帧 PNG、相机配置和时间表按其接收需求提供。姿态核对使用 `frames.csv` 中的同刻参考值，其使用方式由同事决定。

## 视频流与同事接收接口（手动工况待接入）

离线 MP4 是本方案明确的成片输出。若同事需要流接口，建议复用前端现有的 FFmpeg／MediaMTX RTSP 文件推流：选择已经生成的 MP4 → 启动推流 → 同事连接读取。现有入口采用循环播放，支持主动停止；播完自动停止不是该入口已经具备的选项，不默认增加该功能。

采用文件推流时，流中的画面由该文件决定，不随 Blender 中随后修改参数、暂停或切换视角而改变。新的试验须生成对应视频，停止当前推流后更换来源。交付说明须给出片段时长与循环行为，避免将重播误认为新的连续运动。

前端推流服务默认只供本机读取；同事在另一台电脑上接收时，须启用已有局域网读取设置，并提供输出电脑的局域网地址。`127.0.0.1` 地址不能直接用于另一台电脑。实际接收检查应在约定的接收端执行，不用输出端播放器成功代替同事能够连接。

当前 Blender 动画实时生成并立即推送图像属于另一种采集方式，现有文件推流入口不能直接提供。是否需要这种实时采集属于待确认的输出要求，不能将已有 RTSP 文件播放描述为已具备实时成像输出。

同事接收接口只约定素材与传输：

| 项目 | 约定内容 |
| --- | --- |
| 文件素材 | MP4，按需提供对应 PNG；文件输出与流接收按约定选用 |
| 视频属性 | 编码、分辨率、帧率、时长和时间戳 |
| 图像来源 | 固定 T1 Down、模型身份、运动与变桨参数 |
| 流接口 | 需要流时约定协议、接收电脑、读取地址、启动／停止、循环及断开行为 |
| 辅助信息 | 相机配置、试验参数、按需提供的独立姿态标签 |

识别算法如何使用文件、视频流和辅助信息，由同事决定。

## 建议试验与验收

建议使用以下工况覆盖需求，具体目标角度由样片确认：

| 工况 | 需要核对的行为 |
| --- | --- |
| 三片固定同一桨距 | 恒速、固定成像和输出时间连续 |
| 仅 B1 变桨 | B1 连续变化，B2/B3 保持；RPM 和叶轮相位连续 |
| B1/B2 变到不同角度 | 独立目标值、共同起止时间、B3 保持 |
| 三片分别变桨 | 三个不同目标值与同一时钟的成像一致性 |
| 暂停、继续和重放 | 叶轮与变桨共同冻结，继续无跳变；重放可复现 |
| 桨距范围边界与离镜区间 | 保留真实成像与遮挡，不修改画面制造可见性 |
| 视频文件 | 文件可完整解码，内容包含选中叶片的变桨过程及完成后恒速运动 |
| 约定的视频流 | 接收端可连接并显示对应工况，循环和停止行为明确 |

已确认的三分钟单叶片工况使用 rootkink 叶根拐点模型：9 RPM，起始三片均 0°，仅 B1 按 5°/s 匀速变到 20°，变桨时长 4 s，随后保持 176 s；B2/B3 始终保持 0°。视频使用同一固定 T1 Down 机位，全程叶轮旋转，输出 180 s、25 fps、4500 帧。9 RPM 对应 54°/s、约 6.67 s 一圈；全片名义旋转 27 圈，相邻帧叶轮方位差为 2.16°，变桨期间 B1 相邻帧桨距差为 0.2°。4 s 变桨短于一圈，不能保证固定 Down 连续看见完整变桨过程；目标保持期间可反复观察一片 20°与两片 0°的成像差异。

验收分别判断：

- 运动：确认后直接启动试验，选中叶片连续到达目标值，未选叶片保持；变桨不改变规定 RPM 或装配关系，暂停和继续不跳变。
- 成像：相机观察同一动画几何，切换视角不改变试验时刻；记录实际可用观察区间。
- 导出：即使预览已结束，仍能导出从起始姿态到目标姿态的完整过程；PNG 与视频的帧数、尺寸和时间映射一致，压缩视频可严格解码。
- 推流：需要流接口时，同事能按约定地址连接，解码出的尺寸、帧率和内容与所选视频一致；循环、断开及停止行为明确。
- 交付：素材、参数说明及约定辅助文件可对应，同事可以接收并读取。

## 输出约定与待确认接口

运动采用单次确认、共同变桨时长、可选平滑／匀速方式和固定 T1 Down。离线输出为 1920×1080、25 fps，默认 8 s 变桨加 7 s 目标保持；指定正 RPM 在完整片段内固定。三分钟单叶片工况使用 4 s 匀速变桨加 176 s 保持。离线成片由工作区源码提供，公开包、日常安装和跨平台运行尚未验证。文件传输方式和是否需要流接收由实际接收需求确定；需要流接口时可衔接已有 RTSP 文件推流。实时采集与推送当前 Blender 画面尚未得到明确需求，不作为已确认的必做功能。
