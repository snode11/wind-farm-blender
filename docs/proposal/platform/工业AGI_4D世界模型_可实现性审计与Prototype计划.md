# 风电场工业 AGI：四周 Prototype 实施计划

计划原更新：2026-09-09；当前对齐：2026-10-08。范围仅限 `wind farm RL` 文件夹。本文仍是四周工作量估计与实施关口，本次只更新文档，不启动仿真/训练，不表示新的预测器、联合控制对照或原型验收已完成。

当前 Blender 发布版 0.3.17.1 已含保存 MAPPO 柔性回放、三相机、NREL 缺陷编辑器、便携轮廓重建示例及同源601样本纹理对照；它们不等于本文的动作条件世界模型或双通道联合控制已交付。版本与已有失败边界见[发布状态](../../blender/发布状态与验证范围.md)。表面重建的最新执行另见[研究入口](../叶片表面重建_2026-10-06/README.md)，不能合并成原型完成证据。

## 1. 交付目标与可实现性

约四周交付一个三台风机的“偏航＋叶片集体变桨”仿真 Prototype：沿用 Blender 工作台、Bridge 和 FAST.Farm，在时间轴上记录物理仿真状态，用小型数据预测模型比较候选控制方案，再由经验规则和现有安全层筛选动作。

这个限定范围的工程原型具有可实现性，前提是第一周通过本机 FAST.Farm 变桨实效验证。四周是工作量估计，按一名熟悉代码的全职开发者、有可用仿真环境计算，不是研究效果保证。取消原来的“7/10”评分：现有证据不足以量化成功概率。

四周验收聚焦链路完整、预测可评估、控制真实生效；不承诺增发电收益、通用工业 AGI、完整三维流场预测或实机部署。预测器的构建与评估是必交项，优于基线和联合控制收益属于待验证结果。大规模风场、独立变桨 IPC、转矩优化和新一轮大规模 RL 留在本期之外。

## 3. 控制范围：偏航＋叶片集体变桨

每台风机的动作采用现有增量接口：`[yaw_delta_deg, pitch_delta_deg]`。首版为集体变桨：同一台机组的三片叶片共用一个桨距命令，不实现三片叶片独立的 IPC 控制。转矩沿用基线控制器。

必须遵循当前代码语义：

- FLORIS 路径只实现 yaw，不用于验证 pitch 的功率、载荷响应。不能将前端叶片旋转当作物理变桨成功。
- FAST.Farm 示例注明 pitch 是 `PitchRef` 的下界，实际桨距可能被内置控制器覆盖。首版保留该语义，不在四周内另换底层变桨控制器。
- `pitch` 与 `pitch_meas` 必须分开：前者可能是 MDP 累积指令，后者从底层实际测量转换成度。动画和跟踪误差优先使用实际反馈，缺测明确标识。
- `safety.py` 当前定义 pitch 步长界限 1 度、速率参考 8 度/秒、状态范围 0–45 度；这些是代码配置，不是机组安全认证。第一周结合算例和控制器核查后冻结测试范围。
- 不将恢复命令为零称为紧急安全停机。异常时停止优化器下发，按已验证的基线控制与仿真停止流程处理。

上述 PitchRef 语义来自本项目场景注释、安全层和驱动代码；本次没有验证加载的控制器二进制与注释所述实现完全一致，必须以运行响应复核。

第一周需分别验证基线控制器主导区间和外部桨距下界可生效区间，记录命令、实际桨距、转速、功率与可用载荷。当前 snapshot_adapter 将 FAST.Farm 的 rotor_speed 标记为由功率和转矩推导的量；不得据此声称独立转速传感器验证或超速保护验收。若实际桨距无法响应或响应语义不清，变桨验收判失败，优先解决底层问题，不以界面演示代替。

## 4. 4D 与三驱动的最小实现

本期交付“空间定位＋时间演化”的降阶世界模型原型：保存风机位置、轮毂高度、时间、来流、偏航、实际桨距、转速、功率、可用载荷与动作历史。空间截面、动画代理和物理测量分别标识来源；不宣称已恢复完整三维流场。

- **物理驱动**：FAST.Farm 提供动态轨迹和控制响应；FLORIS 仅作稳态偏航参考。
- **数据驱动**：用已有及新采集的 FAST.Farm 轨迹训练一个小型时序预测器，优先预测各机功率与实际桨距。Persistence 为必要基线，MLP 或 GRU 只选一个，限制调参预算。
- **经验驱动**：将可行区间、速率限制、基线控制器覆盖条件、停止条件和动作拒绝原因显式记录。首先使用可解释规则，不建立复杂专家智能体系统。

预测器输入过去状态与候选动作序列，输出短期响应。建议初始使用 30/60 秒预测窗、至少覆盖场景主要延迟的历史窗，第一周依据采样率和轨迹确定。若需要验证完整下游尾流影响，评估窗口必须延长，不能用短窗代替。

物理时间、求解器时间步、策略更新周期和渲染时间分别记录。现有 README 的 FLORIS 60 秒与 FAST.Farm 3 秒控制步不能直接按相同步数比较。“多时间尺度”首版采用变桨每个控制周期可更新、偏航较慢更新的调度规则，周期第一周冻结；这不是表格型多尺度 Q-learning 收敛保证。

反事实采用“相同初始化和来流、重放相同历史、分叉候选动作”的离线实验；不假设 FAST.Farm 已支持任意状态快照克隆。未来来流若使用预知数据，应标记为已知来流实验，不能充当在线预测证据。

## 5. 四周安排

| 周次 | 重点 | 交付物 | 验收门槛 |
|---|---|---|---|
| 第 1 周 | 双控制量合同与端到端基线 | 三台机组 yaw/pitch 场景、命令/实际反馈记录、单位与时钟表、Blender 实测显示 | 两通道有真实物理响应证据；基线覆盖可解释；停止后进程正确退出 |
| 第 2 周 | 时序数据与世界模型基线 | 统一轨迹格式、回放导出、小型预测器、按 episode 分割的数据集 | 无跨窗口数据泄漏；报告每台机组和各 horizon 误差、与 Persistence 比较 |
| 第 3 周 | 三驱动候选评估 | 有限候选库、动作条件预测、规则过滤、离线 FAST.Farm 复核 | 基线、偏航、变桨、联合控制均有离线对照；记录预测排序与物理排序差异 |
| 第 4 周 | 集成与验收 | Blender 可见完整流程、重复场景评估、异常演示、报告与演示素材 | 能加载→运行→查看命令与反馈→停止→查看历史→导出；预测叠加与失败状态可见 |

候选库限制为少量已通过约束检查的动作模板，不在三机二维动作空间穷举。先生成离线物理结果供复核；实时演示使用小模型或预计算结果，并明确标注，避免把慢速仿真包装为实时预测。

## 6. 验收方法

### 控制与平台

- 同一场景分别运行基线、仅偏航、仅变桨、联合控制。基线保留原机组控制器，不是将实际桨距强制设为零。
- 对齐来流、初始化、预热、物理评估时长与功率单位；报告能量、功率跟踪、桨距跟踪和执行器动作量。
- 真实载荷仅在有明确通道、单位与映射时报告；没有疲劳模型就不声称寿命改善。
- 注入非法动作、反馈缺失和连接异常，验证拒绝、告警与停止路径；“测试场景未违规”不等于全工况安全保证。

### 数据模型

- 以整段 episode/来流序列划分训练、验证、测试，避免随机拆分相邻帧；冻结测试后不用于调参。
- 第一周先小规模计时，再按剩余算力冻结采集量，不预设未经测量的大规模训练预算。
- 报告 MAE/RMSE、候选动作排序准确率及失败案例；如数据足够，增加简单分位数误差区间，并报告经验覆盖率。
- 模型没有优于 Persistence 时明确判定预测模块未达标；保留物理参考路径交付，并写明缺口，不能宣称世界模型有效。
- 三驱动首版验证数据预测、物理复核和规则筛选的协作链路，不承诺全面消融。若比较候选选择器，所有分组均保留同一安全层，不为消融关闭约束。

## 7. 工期风险与取舍

四周优先保证：真实变桨、统一时序、一个预测基线、有限反事实、现有界面完整链路。可压缩的是美术包装、候选数量和模型结构，不压缩动作语义验证。

第一周若 FAST.Farm 运行或变桨控制器接线受阻，第二周继续数据格式、规则和界面工作，但联合控制物理验收保持未通过；应调整交付日期或能力声明。既不以 FLORIS 代替变桨验证，也不把 SYNTH 数据当作实际仿真反馈。

本期后续再考虑：独立变桨 IPC、recurrent actor 完整研究、NetworkMQL、规模扩展、真实 SCADA 同化、完整三维场预测、HIL 和实机。

## 7A. 再审结论与四周执行约束

### 必须澄清的三个边界

1. **Replay 不是现成的历史轨迹播放器。** `wfrl/studio/trainer.py::_replay_policy` 加载 checkpoint 后重新推进仿真，并记录部分历史。首版必交为完整数值轨迹导出与历史曲线查看；Blender 现有内置几何结果已有保存数据驱动播放，但它不自动覆盖新 Prototype 的双控制量轨迹；该原型的精确历史播放须按新记录合同另行接入。不能把重新仿真称为逐帧复现旧运行。
2. **控制模型不可直接复用为双动作策略。** 现有 checkpoint 可能仅有 yaw。新增 yaw/pitch 场景必须显式检查 controls、动作维度和归一化。四周首版采用规则/脚本候选，不要求训练新双通道 RL；旧 yaw 策略只作为偏航参考。
3. **数据覆盖必须包含干预。** 只用零动作或单一策略轨迹无法可靠比较未见过的变桨动作。采集经过约束的偏航、变桨和联合动作模板；预测仅用于数据覆盖范围内的候选，超范围退回已验证模板。

### 双控制量的任务目标

设置两个独立场景，分别比较，避免混成一个不透明加权奖励：

- **尾流偏航场景**：固定来流，比较基线与偏航的能量；变桨保留基线或作为受控变量，不承诺增加桨距能增发电。
- **限功率/跟踪场景**：选择物理可达的场级功率目标，验证集体变桨是否能产生可解释的功率调节；报告跟踪 RMSE、实际桨距和动作量。无目标指令就不报告“功率跟踪性能”。

第一周冻结目标范围、动作幅度、偏航保持周期和评估时长；不能拿限功率损失当成算法失败，也不能用减少发电解释为已降低真实疲劳。

### 20 个工作日的容量分配

- 第 1–3 天：本机后端、变桨实效和基线接管验证；第 3 天作关键依赖判定。
- 第 4–5 天：记录合同、动作模板、小样本计时；冻结实验清单。
- 第 6–10 天：数据采集、整段划分、Persistence＋一个小模型、误差报告。
- 第 11–14 天：两类场景的有限候选物理对照、规则筛选与结果对齐。
- 第 15–17 天：复用 Bridge/Blender 接线，补历史导出和可见状态。
- 第 18–20 天：回归、故障场景、报告和修复缓冲；不新增模型或展示功能。

预算按实际计时计算：`episode 数 ×（初始化＋预热＋历史重放＋分支评估＋停止清理）墙钟时间`。旧动态训练脚本说明中的约 0.6 秒/控制步只能作为历史参考，不是当前机器承诺。重复相同确定性运行检验可复现性，不充当独立样本增加统计置信度。

### 完成与效果分开验收

**工程完成**：两通道物理响应可解释、来源与单位齐全、数据可导出、预测评估可复现、固定候选四组对照齐全、界面和停止清理通过。**模型有效**：在冻结测试集上较 Persistence 有增量预测能力且动作排序有支持。**控制有效**：达到事先设定的能量或跟踪目标。这三项分别报告；工程完成不能替代后两项。

阈值应在第一周用传感器/接口精度、基线波动和任务需求确定并锁定，不在看到测试结果后放宽。第一周若变桨实效不通过，四周联合控制交付不再成立；压缩候选数量和美术工作可以保工期，假装物理功能已完成不可以。
