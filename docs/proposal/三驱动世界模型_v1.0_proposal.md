> 版本：v1.0　|　编制日期：2026-08-21　|　定位：从 Studio 仿真 App 出发，做「感知硬件—物理仿真—世界模型」一体化闭环的第一版落地
>
> 关联文档：`material0`（三驱动世界模型架构）、`material1`（工业 AI 一体化平台）、`material2`（风机智驾 DevOps）、`material3`（自动驾驶端到端 + 世界模型范式）

## 一、背景与定位

四份 material 已把方法论说透：**数据驱动 + 物理驱动 + 经验驱动**融合的世界模型，覆盖「感知—诊断—决策—控制—进化—经营」六个子方向，用汽车自动驾驶验证过的「端到端 + 世界模型 + 影子模式」范式，把风机当成一台工业机器人来开发。

但方法论要落地，**第一颗钉子必须钉在「感知」上**——没有物理保真的感知层，后面的世界模型就是无源之水：

1. **世界模型需要真值监督**（material2/3）：编码器要从「传感器序列 → 隐状态」，隐状态的物理含义来自传感器的真实安装位姿与成像模型。相机装在哪、看到什么，直接决定了 `z_t` 里编码了什么信息。
2. **物理驱动要求可解释的成像链路**（material0 3.2）：相机不是黑箱，它的视野是由**风机结构几何 + 安装点位 + 镜头参数**唯一确定的。这条链路必须能在仿真里逐帧复现，才能做 Sim2Real。
3. **我们已经有了底座**：`wfrl/studio` App 已实现 FAST.Farm/FLORIS 物理后端 + PyVista 三维实时可视化 + 传感器通道体系（power/actuator/bladeload/lidar/**camera**），并且相机传感器已经能按真实 NREL-5MW 几何（轮毂高 88 m、叶尖半径 63 m、悬伸 5 m）算出安装位姿、实时渲染出机舱视角。

因此 **v1.0 的范围收敛为：以风电场/风机为对象，做出第一个可商业化的「净空相机」感知产品 + 其在 Studio 里的物理保真仿真闭环**。这既是三驱动世界模型的感知层地基，本身也是一个能单独卖钱的工业产品（叶片净空监测是风电运维的刚需）。

### 1.1 什么是「净空相机」

**叶尖净空（blade-tip clearance）**是叶片扫过塔筒时叶尖与塔壁的最小距离。净空过小 → 扫塔风险（叶片打塔，整机报废级事故）；净空监测是大叶轮、柔性叶片机组的强制安全项。

**净空相机**：装在**机舱底面、靠近轮毂**的工业相机，镜头近乎垂直向下、略偏向叶片侧，逐帧拍摄从下方掠过的叶片，通过图像测量叶尖到塔筒的实时净空。它是本方案感知层的**首款硬件产品**，也是世界模型的一路关键输入。

## 四、第一阶段详细设计：风电场与风机

### 4.1 产品设计 D1：净空相机（工业相机 + 补光灯）

净空相机装在机舱外底部，环境严苛（高空、强振、盐雾、−30~50 ℃、昼夜全天候），因此选型按**工业级/宽温/高防护/全局快门**定义。以 NREL-5MW（叶尖线速度 ~80 m/s、三叶片 6~13 rpm）为设计工况。

#### 4.1.1 成像需求推导（为什么是这些参数）

- **叶尖线速度**：额定 12.1 rpm、叶尖半径 63 m ⇒ 叶尖速度 ≈ 2π·63·12.1/60 ≈ **80 m/s**。
- **运动模糊约束**：要叶尖成像模糊 < 1 像素、相机到叶尖 ~15 m、视场覆盖 ~20 m/1920 px ≈ 0.0104 m/px ⇒ 曝光时间 < 0.0104/80 ≈ **130 μs**。故必须**全局快门 + 最短曝光 ≤ 100 μs + 强补光**。
- **帧率**：一片叶尖掠过镜头视场（~20 m 视宽 / 80 m/s ≈ 0.25 s）内至少取 8~10 帧定位 ⇒ 帧率 ≥ **40 fps**（设计取 60 fps 余量）。
- **分辨率/测距精度**：净空测量精度目标 ≤ ±0.3 m@15 m。0.0104 m/px 下，3 像素定位误差 ≈ 0.03 m 几何分辨，留足裕度 ⇒ **1920×1200（2.3 MP）** 起步，高配 **2592×2048（5 MP）**。

#### 4.1.2 工业相机规格（净空相机 CAM-CLR-01）

| 类别 | 参数项 | 规格（标准配置 / 高配） | 依据 |
|---|---|---|---|
| **图像传感器** | 类型 | 1/1.8″ 或 2/3″ CMOS，**全局快门（Global Shutter）** | 高速叶尖不拖影 |
| | 像元尺寸 | 3.45 μm | 灵敏度/分辨率平衡 |
| | 分辨率 | 1920×1200 (2.3 MP) / 2592×2048 (5 MP) | §4.1.1 推导 |
| | 帧率 | ≥ 60 fps @全分辨率 | 叶尖时序采样 |
| | 动态范围 | ≥ 70 dB（HDR 模式 ≥ 90 dB） | 逆光/阴阳面 |
| | 快门/曝光 | 5 μs ~ 10 ms，最短曝光 ≤ 100 μs | 运动模糊约束 |
| **镜头** | 接口 | C-Mount / M12 工业接口 | 可换镜头 |
| | 焦距 | 6 mm（宽） / 8 mm，对应对角 FOV **~90° / ~70°** | 覆盖叶片掠过带 |
| | 光圈 | F1.4~F2.0（大光圈，暗光进光） | 配合短曝光 |
| | 景深 | 覆盖 8~25 m（叶尖到机舱距离带） | 净空区间 |
| **接口/供电** | 数据接口 | GigE Vision（PoE）/ USB3 Vision；高配 10 GigE | 机舱长线传输 |
| | 触发 | 硬件触发 + 方位角同步（与主控/编码器对齐叶片相位） | 只在叶片入场时曝光 |
| | 供电 | PoE 或 24 VDC，整机 ≤ 8 W（相机本体） | 机舱供电 |
| **环境/可靠性** | 防护等级 | **IP66/IP67**（外壳），带加热除霜 | 高空盐雾雨雪 |
| | 工作温度 | **−30 ℃ ~ +55 ℃**（宽温） | 全天候 |
| | 抗振 | ≥ 5 Grms（随机振动），符合机舱振动谱 | 塔筒/机舱振动 |
| | 防雷/EMC | 浪涌防护，符合 IEC 61400-24（风机防雷） | 高空雷击 |
| | MTBF | ≥ 50,000 h | 运维周期 |
| **同步/标定** | 时间同步 | PTP/IEEE-1588，与 SCADA/主控对齐时间戳 | material2 HDF5 时间对齐 |
| | 外参标定 | 出厂 + 现场棋盘格/结构特征标定，位姿写入配置 | 复现成像链路 |

#### 4.1.3 补光灯规格（净空补光 LED-CLR-01）

夜间/浓雾/逆光时叶片下表面照度不足，短曝光（≤100 μs）更吃光，必须主动补光。选**红外 + 白光双模、频闪同步**：

| 参数项 | 规格 | 依据 |
|---|---|---|
| 光源类型 | 850 nm 近红外 LED 阵列（主）+ 可选白光 LED（辅） | 红外夜间不扰邻、不炫光 |
| 工作模式 | **频闪同步（Strobe）**：与相机曝光同步，仅曝光窗口点亮 | 峰值功率高、均值低、省电防眩 |
| 峰值光通量 | ≥ 3000 lm（白光）/ 等效红外辐照满足 15 m@100 μs 成像 | 短曝光进光量 |
| 频闪频率 | ≥ 60 Hz，占空比可调（与帧率联动） | 匹配 60 fps |
| 照射角 | 与相机 FOV 匹配（~90°），可调俯仰 | 覆盖叶片掠过带 |
| 供电/功耗 | 24 VDC，均值 ≤ 15 W（频闪），峰值另计 | 机舱供电 |
| 防护/温度 | IP66，−30~55 ℃，带散热 | 同相机 |
| 寿命 | LED ≥ 50,000 h | 运维周期 |

> **补光与相机的硬同步**是这款产品的技术要点：曝光窗口 ≤100 μs 时，只有频闪补光在同一窗口打出足够峰值照度，才能既冻结 80 m/s 的叶尖、又保证信噪比。这条「曝光—补光—方位角触发」三同步链路，在 D3 仿真里以「相机只在叶片进入视场时出图 + 补光锥体可视化」体现。

### 4.2 挂机方案 D2：风机结构点位选择

净空相机的**安装点位**决定了能不能拍到叶尖、会不会拍到塔筒（穿模）、以及净空的测量几何。我们把风机结构离散成若干候选挂载点，每个点位给出相机的默认位姿，并说明适用性。坐标系与 `wfrl/viz/geometry.py`、`animate.py` 同源（真实 NREL-5MW：轮毂高 88.04 m、叶尖半径 63 m、悬伸 −5.02 m 上风向、轴倾 −5°、塔基直径 6 m）。

#### 4.2.1 结构点位候选表

| 点位 ID | 结构位置 | 相机朝向 | 优点 | 风险/约束 |
|---|---|---|---|---|
| **`nacelle_down`（推荐/默认）** | 机舱底面、**轮毂—塔筒中点偏轮毂**侧 | 近乎垂直向下、偏离竖直 10° 朝叶片 | 正对叶尖掠过带，净空测量几何最优；避开塔筒穿模 | 需机舱底开窗/吊装支架 |
| `nacelle_front` | 机舱前端下沿（转子平面正下） | 垂直向下 | 最贴近扫掠面 | 视野窄，仅覆盖单一相位 |
| `hub` | 轮毂/导流罩下方 | 随转子转 | 跟叶片一起动，可看叶根 | 旋转坐标系、供电走滑环，工程复杂 |
| `tower_up`（v2.0） | 塔筒上部朝上仰视 | 向上看叶尖 | 从下往上测净空 | 逆光严重、镜头易积污 |

**为什么默认选 `nacelle_down` 且靠轮毂**：侧视图里机舱前端是轮毂+叶片、机舱中部是塔筒。相机放在「轮毂与塔筒之间、偏轮毂」处、镜头朝正下方略偏叶片侧——这样：
1. 叶尖掠过带正好在镜头正下方，净空（叶尖到塔壁）在画面里是可直接量测的几何量；
2. 相机站在转子平面上风侧一点，塔筒（在转子下风向 5 m、底径 6 m）落在视野边缘之外，**不穿模**；
3. 与真实商用净空相机的吊装位置一致（对标已有产品的机舱底吊装方案）。

#### 4.2.2 位姿模型（已在代码中实现，v1.0 固化为方案库）

安装位姿由「结构点位偏移 + 相机内参（俯仰/FOV/相对偏航）」唯一确定，随机组偏航一起旋转：

```
真实轮毂中心 real_hub = 塔顶 + 上风向 × 悬伸(5.02 m)，高度 88.04 m
相机位置 pos = real_hub + 下风向 × (0.3×悬伸)   ← 轮毂↔塔筒之间偏轮毂
              + 竖直 × (−0.03×R)                ← 机舱底面下方约 2 m
视线 look     = 由竖直向下起，向叶片(上风)侧掀开 (90°+pitch)
              pitch = −90° ⇒ 正下方；−80° ⇒ 偏离竖直 10° 朝叶片（默认）
上向量 up     = 正交化(look, 参考轴)，look 近竖直时用机舱轴防退化
FOV           = 90°（默认，广角俯拍）
```

这套模型的数值特性（已验证）：pitch −90°→−45° 时相机始终在机舱底轮毂侧、视线从正下方平滑掀向叶片、up 向量全程与 look 正交（`up·look=0`，无万向节退化/闪烁）；相机恒在塔筒上风侧，塔筒不穿模。

#### 4.2.3 方案配置（写进场景 YAML，D5）

```yaml
sensors:
  - type: camera
    turbines: "T1"
    params:
      mount: nacelle_down     # 结构点位（D2 方案库）
      pitch: -80.0            # 偏离竖直 10° 朝叶片
      fov: 90.0               # 广角俯拍
      yaw_off: 0.0            # 相对机舱轴偏航
      # ── 以下为 v1.0 新增的产品化参数（D1 → 仿真）──
      resolution: [1920, 1200]
      frame_rate: 60
      exposure_us: 100
      illum: {type: ir_strobe, angle: 90, sync: azimuth}
```

### 4.3 相机仿真功能 D3：实时 + 物理保真

在 Studio App 右侧双视口中，实时渲染「选定挂机方案下，该相机在**真实尺度**机组上拍到的画面」。物理保真体现在四个层面：

1. **真实几何**：右视口里重建一台 1:1 真尺度机组（叶尖 0.5 m 宽是真值），相机位姿严格按 D2 模型算，不是拍脑袋摆镜头。
2. **实时姿态**：叶片的偏航/方位角/桨距/**柔性变形**逐帧来自物理后端（FAST.Farm 动态气弹 / FLORIS 稳态），相机看到的是叶片此刻的真实形态与转动。
3. **成像链路一致**：FOV/俯仰/分辨率宽高比按 D1 相机参数设置视锥；曝光/补光以「叶片入场触发 + 补光锥体」表达（叶片不在视场时相机不"出图"）。
4. **稳定成像**：右视口相机由方案参数（俯仰/FOV 滑块）驱动，**鼠标不介入**（`InteractiveOff`），裁剪范围按机组包围盒钉死——彻底消除此前"拖动闪现不同焦距""某些角度才稳"的问题（根因：共享交互器与每帧位姿 snap 打架 + 相机贴近包围盒时自动裁剪面跳变，均已修复）。

同时在主视口画出该相机的**视锥线框 + 补光锥**，一眼看清"这台相机罩住了叶片的哪一段"。相机通道可在「数据通道」面板一键开关（关闭相机/雷达即生效）。

### 4.4 净空量测 D4：从仿真读出真值

物理后端已能算叶片三片掠塔时的**最小间隙 clearance(n,3)**（真值，不含显示放大）。v1.0 把它接到相机视野：

- 在相机画面里叠加净空标尺/读数（当前叶尖到塔壁距离）；
- 记录「相机位姿 + 帧 → 净空真值」配对，作为 D3 输出的**带标签数据**——这正是 material2/3 里世界模型编码器要的"传感器 + 真值"对，为 v2.0 的图像净空反演模型准备监督信号。

| 相机传感器 `wfrl/channels/sensors.py::CameraSensor` | 已有 `camera_pose()`、真实几何常量、mount 语义 | 扩展 D1 产品参数（分辨率/帧率/曝光/补光）；固化 D2 方案库 |

| App 交互 `wfrl/studio/app.py` | 相机右视口、FOV/俯仰滑块、通道面板 | 挂机方案下拉（D2）、产品参数联动、稳定成像（已修复闪烁） |
| 物理后端 `wfrl/fastfarm_driver.py` / FLORIS | 叶片位姿、柔性变形、掠塔净空真值 | 净空真值接口对齐相机帧（D4） |
| 场景配置 `scenes/*.yaml` | camera 传感器已可配 | 增补产品化参数 schema（D5） |
| 数据资产 | — | 「位姿+帧+净空真值」导出接口（→ world model 训练，v2.0） |

**与三驱动的对应**：D1/D2/D3 是**物理驱动**（成像链路第一性、几何可解释）；D2 方案库沉淀选点经验是**经验驱动**；D4 导出的带标签数据喂给 v2.0 世界模型是**数据驱动**的入口。三驱动在感知层已闭合。

## 八、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 仿真画面与真实相机成像差距大 | Sim2Real 失真 | S3 对标真实净空相机样片做几何/畸变校验；先保证几何真值一致，畸变/噪声留 v2.0 |
| 高速叶尖运动模糊在仿真里未体现 | 与真机成像不符 | 成像触发 + 曝光窗口建模；必要时加运动模糊后处理（可选） |
| 结构点位与真实机型不匹配 | 方案不通用 | 位姿模型全部参数化（几何从 geometry 载入），换机型只改常量 |
| 硬件选型周期长 | 阻塞样机 | S4 并行采购，软件不依赖实物；先用规格书驱动仿真 |
| 补光同步（曝光/频闪/方位角）复杂 | 产品落地难 | v1.0 在仿真里先验证三同步逻辑，硬件同步做成可配置触发接口 |

## 九、总结

v1.0 不追求把六个子方向一次做完，而是**把三驱动世界模型的感知层地基夯实**：交付一款可商业化的净空相机（工业相机 + 补光灯完整定义）、一套基于风机结构点位的挂机方案库、以及一个物理保真、实时、可复现的相机仿真闭环。它一头连着能单独变现的风电运维刚需（叶尖净空监测），一头为 v2.0 的世界模型准备了带真值的训练数据接口——正是 material0「物理为基、数据为翼、经验为魂」在感知层的第一次完整落地。

**一句话**：先让每一台仿真风机上的相机，都能物理保真地"看见"叶片；再让世界模型学会从这些画面里"理解"风机。
