################################useful notes
Stable-Baselines3（SB3）是一个完全独立的第三方库，跟 Gym 和 WFCRL
  都没有「自带」关系。三者是各管一段、需要我们自己组装起来的独立组件。

  三者的关系：谁提供什么

  ┌─────────────────────────────────────────────────────┐
  │  Gymnasium (gym)   ← 只是一套「接口标准/协议」          │
  │    定义 reset()/step()/action_space 长什么样          │
  │    它本身不含算法，也不含具体环境                       │
  └─────────────────────────────────────────────────────┘
          ▲                                    ▲
          │ 遵守这个标准                          │ 遵守这个标准
          │                                    │
  ┌───────────────────┐              ┌──────────────────────┐
  │  WFCRL             │              │  Stable-Baselines3    │
  │  提供「环境」        │              │  提供「算法」           │
  │  风场仿真 step()    │  ──数据──►    │  PPO/A2C/SAC/DQN...    │
  │  返回 obs/reward   │  ◄─动作──     │  负责训练神经网络       │
  └───────────────────┘              └──────────────────────┘
       独立安装的包                         独立安装的包

  - Gymnasium：只是一份接口约定（reset/step
  的签名、动作/观测空间的定义方式）。它像「插座标准」，本身既不发电也不是电器。
  - WFCRL：提供环境（风场物理仿真），是「发电的一方」——负责 step() 返回观测和奖励。它遵守 Gym 标准。
  - SB3：提供算法（PPO 等），是「用电的一方」——负责根据环境反馈训练神经网络。它也遵守 Gym 标准，所以理论上能对接任何
  Gym 环境。

  因为双方都遵守同一个 Gym 接口标准，它们才能拼在一起——这正是 Gym
  存在的意义：让「环境」和「算法」解耦，各自独立开发，靠标准接口对接。（而我们的 sb3_wrapper.py 就是补上 WFCRL
  那几处没完全对齐标准的小缝隙。）

  SB3 是独立安装的证据

  回顾我们的部署，SB3 是单独 pip 装的，不是随 WFCRL 或 gym 来的：

  pip install stable-baselines3[extra]   # 单独安装，还顺带拉了 torch、tensorboard

  它由一个独立团队（DLR-RM）维护，跟 WFCRL（Inria/IFP）、Gymnasium（Farama 基金会）是三个不同的项目。

  SB3 主要是什么功能

  一句话：SB3 是「强化学习算法的现成实现库」。它把经典 RL 算法打包成开箱即用的组件，你不用自己从零写 PPO
  的损失函数、GAE、经验回放这些。

  具体在我们项目里它干这些活：

  ┌────────────────────────────────────────────┬──────────────────────────────────────────────────────┐
  │                    功能                    │                    对应我们的代码                    │
  ├────────────────────────────────────────────┼──────────────────────────────────────────────────────┤
  │ 提供 PPO 算法                              │ PPO("MultiInputPolicy", env, ...)                    │
  ├────────────────────────────────────────────┼──────────────────────────────────────────────────────┤
  │ 搭建神经网络（actor + critic MLP）         │ net_arch=[128,128]，SB3 内部建网                     │
  ├────────────────────────────────────────────┼──────────────────────────────────────────────────────┤
  │ 训练循环（采集 rollout、算 GAE、梯度更新） │ model.learn(total_timesteps=100000)                  │
  ├────────────────────────────────────────────┼──────────────────────────────────────────────────────┤
  │ 动作采样 / 推理                            │ model.predict(obs, deterministic=True)               │
  ├────────────────────────────────────────────┼──────────────────────────────────────────────────────┤
  │ 模型存取                                   │ model.save() / PPO.load()                            │
  ├────────────────────────────────────────────┼──────────────────────────────────────────────────────┤
  │ 配套工具：环境向量化、归一化、日志         │ DummyVecEnv、VecNormalize、Monitor、TensorBoard 日志 │
  └────────────────────────────────────────────┴──────────────────────────────────────────────────────┘

  没有 SB3，我们就得手写 PPO 的全部内部机制（前面讲的那些 clip loss、GAE 递推、mini-batch 更新）。SB3
  把这些封装好，我们只需要配置超参 + 提供一个符合 Gym 接口的环境，就能训练。

  一句话总结

  SB3 既不是 Gym 自带也不是 WFCRL 自带，而是独立的第三方 RL 算法库（DLR-RM 维护）。Gym 提供接口标准、WFCRL
  提供环境、SB3 提供算法——三者靠 Gym 标准解耦对接。SB3 的核心功能是提供 PPO
  等算法的现成实现，替我们完成建网、训练循环、推理和模型存取。

  什么是"尾流场"

  风机转动时会从上游空气里"抽走"能量,导致它背后的风速下降、并产生湍流——这片风速变低的区域就是尾流(wake)。

  来流风 →→→→  [风机T1]  ~~~尾流~~~→  [风机T2]
    8 m/s              风速降到 5-6 m/s
                       T2 站在 T1 的尾流里,吃到的风更弱 → 发电少

  "尾流场"就是整个风场里每一点的风速分布图(前面 wakefield_*.png
  画的就是它)。偏航控制的意义,就是把上游风机的尾流"偏转"到旁边,让下游风机避开,从而提升总功率。

  "稳态" vs "动态" 的核心区别

  关键在于要不要模拟时间演化。

  稳态(FLORIS)——只算终点

  想象你把风向、风速、所有偏航角固定住,然后问:"如果这个配置一直保持下去,风吹了很久很久,最终每一点的风速会稳定在多少?"

  FLORIS 用一组解析/半经验公式直接算出这个最终答案,不管中间过程:

  输入:风速8m/s、风向270°、7个偏航角
          ↓ (代数方程,一次求解)
  输出:稳定后的尾流场 + 各风机功率

  - 没有时间维度——它不告诉你"第 3 秒尾流飘到哪、第 10 秒又如何"
  - 快:一次方程求解,毫秒级

  动态(FAST.Farm)——模拟全过程

  FAST.Farm 则真的一小步一小步地模拟时间推进:尾流像烟一样从上游飘向下游需要几十秒,途中有湍流涡旋、有随时间波动:

  t=0s: 尾流刚离开 T1
  t=5s: 尾流飘到一半
  t=30s: 尾流到达 T2,风速开始下降
  t=31s, 32s... 湍流让它持续抖动

  - 有完整时间演化,更接近真实物理
  - 慢:要迭代成千上万个时间步,还得 MPI 并行

  一个类比

  - 稳态(FLORIS):像问"这锅水烧到最后会是几度?"→ 直接告诉你 100°C,不管加热过程。
  - 动态(FAST.Farm):像用温度计每秒记录一次,画出从 20°C 慢慢升到 100°C 的完整曲线。

  对我们 RL 训练意味着什么

  我们的环境每一步 env.step(yaw) 时,FLORIS 做的是:

  ▎ "假设这组偏航角保持稳定,最终尾流场长这样,总功率是 8730 W。"

  它跳过了尾流传播的动态延迟。这带来一个简化:现实中你调了偏航角,下游风机要几十秒后才感受到变化;而 FLORIS
  里这个变化是瞬间生效的。这对训练"该转多少度"这类稳态策略够用,但不检验时间延迟、湍流响应这类动态效应——那正是之后要靠
  FAST.Farm 验证的部分。

  一句话总结

  "稳态"= FLORIS 不模拟风流动的时间过程,直接用方程算出"风况和偏航角固定后,一切稳定下来的最终尾流场和功率"。好处是极快(
  毫秒级),代价是忽略了尾流传播延迟和湍流的动态变化——那些要 FAST.Farm 才能捕捉。

❯ 我的问题：
  那和动态的区别在哪儿？静态也是env.step(yaw)后得到每个风机的局部风况呀，是不是动态的每个风机的局部风况是随机的？

● 不是随机的——动态的局部风况是"有物理规律地随时间演化"，不是随机数。这个区别很关键，别混淆了。

  "随时间变化" ≠ "随机"

  动态仿真里每台风机的局部风况确实每步都在变，但这个变化是由物理规律决定的，不是掷骰子：

  动态 FAST.Farm 里 wind_speed 的变化 = 两个来源叠加

  ① 确定性演化（主体）：尾流传播的物理过程
     T1 偏航 → 尾流慢慢飘向下游 → T2 风速按物理规律渐变
     这部分完全由物理方程决定，可复现

  ② 湍流脉动（叠加的噪声）：大气本身的随机抖动
     即使一切稳定，风也会小幅上下抖（真实大气就是这样）
     这部分才带随机性

  所以准确说法是:动态风况 = 确定性的尾流演化 + 小幅湍流噪声,主体是规律,不是纯随机。

  三种"变化"要分清楚

  你的困惑可能来自把几种不同的"变化"混在一起了。列个表:

  ┌────────────────────────┬────────────────────┬─────────────────────┬──────────────────────┐
  │        变化来源        │    稳态 FLORIS     │   动态 FAST.Farm    │       是随机吗       │
  ├────────────────────────┼────────────────────┼─────────────────────┼──────────────────────┤
  │ 来流风况（8m/s, 270°） │ 训练时每幕随机采样 │ 训练时每幕随机采样  │ 幕间随机（两者都有） │
  ├────────────────────────┼────────────────────┼─────────────────────┼──────────────────────┤
  │ 尾流传播过程           │ ❌ 无（瞬间到位）  │ ✅ 有（几十秒渐变） │ 不随机，物理规律     │
  ├────────────────────────┼────────────────────┼─────────────────────┼──────────────────────┤
  │ 湍流脉动               │ ❌ 无（干净值）    │ ✅ 有（持续抖动）   │ 随机（小幅噪声）     │
  └────────────────────────┴────────────────────┴─────────────────────┴──────────────────────┘

  关键洞察:稳态和动态的核心差别在中间那行"尾流传播过程",而这一行恰恰是确定性的,不是随机的。

  回到上一轮那个例子

  第 10 步把 T1 从 0° 转到 25°，看 T2 风速:

  动态 FAST.Farm:
  step 10: 6.2   ← 尾流还没飘过来
  step 11: 6.3   ┐
  step 12: 6.5   │ 这段渐变是【确定性】的——
  ...            │ 由"尾流以风速飘过 T1→T2 距离需要多少秒"决定
  step 40: 7.0   ┘ 换个随机种子重跑，这条渐变曲线几乎一样
  step 41: 6.9   ┐
  step 42: 7.1   │ 到了新稳态后的这些小抖动，
  step 43: 6.95  ┘ 才是【湍流随机】的部分（幅度小）

  - 6.2 → 7.0 的爬升过程:确定性,是物理延迟
  - 稳定在 7.0 附近的小抖动:随机,是湍流

  稳态 FLORIS 则直接 6.2 → 7.0 一步到位,既没有爬升过程,也没有抖动。

  一句话总结

  不对,动态的局部风况不是随机的。它主要是确定性的尾流传播演化(T1 改偏航后,尾流需要真实时间才飘到 T2,风速按物理规律渐变)
  ,只叠加了小幅湍流噪声才带一点随机性。稳态与动态的本质差别是"有没有尾流传播的时间过程"(确定性的延迟),而不是"随机 vs
  不随机"。来流风况的幕间随机采样则是两者共有的、独立的另一回事。
