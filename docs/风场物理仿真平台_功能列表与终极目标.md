## 一、我们为什么要做这个平台

风电正从"能发电"走向"精算收益、精管安全"，但整个行业的智能化被一个结构性矛盾卡住：

- **真机上做不起实验**。一台大兆瓦机组停机或误操作的代价极高，扫塔（叶尖打到塔筒）是整机报废级事故。想验证一个新控制策略、一套新传感器方案，没人敢直接上真机试错。
- **纯数据驱动的"黑箱"不敢用**。自动驾驶式的端到端模型在风电落地时遇到两道墙：一是安全上无法解释、无法给出物理边界；二是真实风场的极端工况（阵风、结冰、电网扰动、扫塔临界）样本稀少，学不出来。
- **传统仿真各自为政**。气动、结构、控制、尾流各有各的工具，几何对不齐、坐标不统一，换个机型就要重搭，更谈不上给 AI 提供带真值的训练数据。

**我们的判断**：风电智能化的地基，不是先堆模型，而是先建一个**物理保真、可反复试错、能产出带真值数据**的仿真世界。有了它，控制策略可以在"数字风场"里安全地训练上万次，传感器方案可以在上机前就验证视野与净空，而每一个结论都能追溯到物理规律、经得起风电专家审视。

> **这就是本平台的使命**：做风电场的"物理保真数字镜像"——一端连着真实机组的设计几何与物理规律，一端为 AI 决策与硬件产品提供可信、可复现、带真值的实验场。

## 二、我们的终极目标：三驱动世界模型（TDWM）

平台是通往一个更大目标的第一步——**面向风电场的三驱动世界模型**：在同一框架内融合

- **物理驱动为基**：气动/结构/传动/电气遵循第一性原理，提供真值监督、安全边界与仿真环境；
- **数据驱动为翼**：深度学习与强化学习在物理难以显式建模处高效逼近，加速仿真与决策；
- **经验驱动为魂**：把运维沉淀的工程经验与失败案例知识化，使系统不重复犯错、跨场景迁移。

终极形态覆盖**感知 → 诊断 → 决策 → 控制 → 进化 → 经营**六个方向，让每一台风机像一个会自我感知、自主决策、持续进化的工业机器人，在保证安全的前提下最大化全场收益。

**当前阶段（v1.0）聚焦最底层的两件事**：建成物理保真仿真底座，交付首款可独立变现的感知硬件（机舱净空相机）。上层的决策与经营留待后续版本，但接口已预留。

## 三、我们的设计红线：一切基于物理约束、经风电专家验证

这是贯穿整个平台的方法学，也是它区别于"炫技 Demo"的根本：

1. **几何取自真实设计数据，不是画着好看**。机组的叶片、机舱、塔筒、导流罩全部按 NREL-5MW 真实结构参数建模（轮毂高 88 m、叶尖半径 63 m、悬伸 5 m、轴倾 5°、塔基直径 6 m），渲染与物理**共享同一套几何常量**——画面里看到的机组，就是物理算的那台机组。

2. **数据分三级保真度，杜绝"以假乱真"**。每一路传感器都强制标注来源等级：**直读（DIRECT）**是仿真器真算出来的、可进奖励与安全约束；**导出（DERIVED）**是按明确公式推的；**合成（SYNTH）**只供感知层、不进控制。这不是界面标签，而是方法学约束——混用会让结论不成立。

3. **每一条约束都对应真实物理，并可追溯到源码**。偏航电机的散热限制、桨距指令是下界而非叠加、外部转矩会顶替基线且可能超速——这些不是拍脑袋的规则，而是从风机控制系统的真实语义反推、逐条代码化、每次触发都在界面标红并注明出处。

4. **关键建模改进经得起风电专家审视**。例如把偏航占空比从"回合累计、永不衰减"改为**滑动窗口散热恢复**模型——这更贴合真机偏航电机的实际散热特性，也正是它解锁了尾流偏航（wake steering）的场级增益。这类改动本身就是可写入论文、可向专家论证的建模贡献。

> **原则一句话**：我们宁可诚实地标注"这一路是合成的、这个尺寸是近似的"，也不制造无法被物理与专家验证的假精度。

## 四、已实现功能列表（均已在代码中落地）

> 说明：以下为**已经跑通**的能力；带 🚧 的为规划中、尚未实现，明确区分以便评审判断成熟度。

### 4.1 物理仿真后端

| 后端 | 保真层次 | 状态 | 用途 |
|:--|:--|:--:|:--|
| **FAST.Farm** | 场级动态（气弹 + 多机尾流动力学） | ✅ 已跑通 | 净空/载荷真值、最终验证；平台主力后端 |
| **FLORIS** | 场级稳态（解析尾流叠加） | ✅ 已跑通 | 尾流可视化、快速探索 |
| QBlade | 单机高保真（升力线自由涡） | 🚧 规划中 | 单机气动/涡格标定 |

- FAST.Farm 经官方 `mpiexec`/`MPI_Comm_spawn` 拉起，逐控制步回传**真实**功率、叶根弯矩、偏航、桨距（指令 + 实测）、转矩。
- **滑动窗口偏航占空比**已实现，替代上游"累计永不衰减"模型，贴合真机散热恢复。

### 4.2 多模态感知传感器体系

八路传感器，按保真度分级登记，**可单独订阅/停用**（取消勾选即真的停止采样计算）：

| 通道 | 保真度 | 内容 |
|:--|:--:|:--|
| 功率 `power` | DIRECT | 机组有功输出 |
| 叶片载荷 `bladeload` | DIRECT | 叶根挥舞/摆振弯矩 |
| 执行机构 `actuator` | DIRECT | 偏航/桨距/转矩，指令与实测双路 |
| 激光雷达 `lidar` | DERIVED | 前馈来流风速（5 束 × 3 测距门），有湍流盒时按真实风场插值 |
| 转子转速 `rotorspeed` | DERIVED | 由功率/转矩反解 |
| 振动 `vibration` | DERIVED | 由叶根弯矩谱推 1P/3P 与 RMS |
| 机舱相机 `camera` | SYNTH | 安装位姿 + 视野（几何，见 4.5） |
| 声发射 `acoustic` | SYNTH | 叶片健康指标，供运维回路 |

### 4.3 物理保真三维数字镜像

- **真实 NREL-5MW 几何重建**：从 OpenFAST 模板解析 19 段叶片、8 组翼型、12 站锥度塔筒、轮毂/导流罩，三片叶片独立建模（可各自不同桨距/变形）。
- **柔性叶片变形**：用 ElastoDyn 一阶振型 + 载荷标定（R²≈0.95–0.99）实时弯曲叶片。
- **叶尖—塔筒净空真值**：扫掠方位角计算叶尖与塔壁最小间隙，作为净空监测的几何金标准。
- **尾流与地形可视化**：FLORIS 稳态尾流面 + FAST.Farm 真实扰动风场面 + 随转速演化的尾流圆环；渲染级地形预设（平地/山地/戈壁，不进物理）。

### 4.4 Studio 交互式仿真 App（GUI）

围绕三维视口的五块面板 + 菜单：

- **场景面板**：机位/来流/控制配置，改 YAML 仿真与 3D 一起变。
- **数据通道面板**：按保真度着色的订阅开关，取消即停采样。
- **手动摆位面板**：逐机组偏航/桨距/转速滑块，上机前先摆姿态（纯几何）。
- **训练面板**：开始/暂停/停止，功率/奖励实时双曲线，逐轮统计表。
- **物理与安全约束面板**：动作被约束修改时按严重度标红，并注明源码出处。
- **菜单/工具栏**：尾流环、热力图、地形切换、主相机视角、相机传感器视锥开关。

### 4.5 机舱净空相机及其仿真（首款硬件产品）

- **相机位姿模型**（已跑通，纯几何）：由挂机点位 + 俯仰 + 偏航偏置唯一确定世界位姿，随机组偏航同步旋转，主视图画出视锥线框。
- **挂机点位库**（已跑通）：`nacelle_down / nacelle_front / hub / custom` 四类，`custom` 支持坐标指定（dx/dy/dz），用于手动验证挂机方案。
- 🚧 相机成像（实时视口出图）在当前 VTK 环境上尚未跑通；相机**不产出图像数据**，"看到什么"由视口切到该位姿呈现。

### 4.6 强化学习与安全约束层

- **真实 PPO / MAPPO**（已跑通）：共享参数 Actor/Critic + 中心化 Critic + GAE，前台/后台线程共用同一算法、检查点互通。
- **奖励塑形**：`level / centered / reference / step` 多种，含原始/塑形量诊断。
- **安全约束层**（已跑通且完整）：NaN 防护 → 步增量限幅 → 累积状态限幅 → 占空比判定 → 桨距/转矩语义 → 超速监测，逐条对应真实物理、每次修改记事件。
- **已验证结果**：参考型奖励解锁尾流偏航，实现约 **+5.5%（≈178 kW）** 场级发电增益。

### 4.7 机型定义与场景配置

- **机型定义文件 + 加载器**（新近完成）：一份 YAML 承载外壳外形 + 命名挂机点位库 + 气弹几何来源指针，缺省值精确对齐既有渲染、零行为变化。
- **场景配置**：5 套已校验场景（错列/成排/网格三机与六机），含机位/来流/控制/传感器的预检校验。

### 4.8 规划中（尚未实现，明确标注）

- 🚧 **QBlade 单机高保真后端**（L2 中保真档）。
- 🚧 **HDF5 带真值数据接口**：传感器帧 × 物理真值成对导出，面向后续世界模型训练。
- 🚧 **相机实时成像出图** 与图像畸变/噪声建模。

## 五、现状小结与下一步

**现在已经拥有**：一个能真算物理（FAST.Farm 动态 + FLORIS 稳态）、几何与真机一致、传感器分级可溯、能安全试错训练 RL、并已跑出正向发电增益的风电场数字镜像；加上首款净空相机的位姿与挂机方案验证能力。

**接下来（v1.0 收官）**：打通净空量测与 HDF5 带真值数据接口、交付净空相机产品规格与样机选型，把"物理保真仿真"正式变成"可给 AI 喂真值、可给产品做验证"的底座。

**再往后**：以本平台产出的带真值数据训练世界模型，逐层展开诊断、决策、控制、进化、经营——走向那个"风电场即工业机器人"的终极目标。

> 一句话收束：**我们不追求一次建成一切，而是先把物理地基夯实——每一个功能都基于物理约束、经风电专家验证，这是三驱动世界模型能走远的前提。**
