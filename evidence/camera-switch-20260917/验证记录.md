# T1 侧前方切回 Down · 2026-09-17

本机修复，未发布 GitHub。保留正式 0.3.3 包，在独立目录生成同版本本地修复包。

## 原因与修改

`draw_views()` 的三个 Down 按钮原先只设置 `turbine`，未设置 `angle`。Blender 鼠标调用操作符会沿用上次未被按钮覆盖的参数；点击侧前方后保留 `FRONT`，因此 T1 Down 仍然选择侧前方相机。现在三个 Down 按钮及全景明确设置 `angle='DOWN'`。

旧测试始终手动传入 angle，绕开了问题。现有 `farm_front_view_regression.py` 已改为读取实际面板绘制函数生成的按钮参数，检查所有五个按钮，并按按钮参数反复切换，逐次检查相机、暂停状态、帧号、仿真时间及轨迹保留。

## 验证

- macOS / Blender 5.2.1 LTS 实际窗口：旧代码点击「T1 侧前方 → T1 Down」，画面仍为侧前方；仅刷新修复后的绘制函数后，两轮「侧前方 → Down」均正确切换，界面保持 117.000 s / 已暂停。
- 原生后台旧代码基线在 `T1 Down` 缺少 angle 断言处失败：`baseline.log`。
- 源码原生回归通过：`fixed.log`、`fixed/checks.json`；同机组切换保留每片叶片 180 个轨迹点，完整转子构图检查、换机组轨迹重置及轨迹点数上限均通过。
- 本机安装 77 个文件的 SHA-256 均与新包 inventory 一致。只替换安装目录中的 `panels/farm_replay.py`，未更改物理数据。备份与安装路径见 `install.json`。
- 实际窗口从源码加载，安装目录独立进程的原生回归见 `installed.log` / `installed/checks.json`；两者验证范围分别记录。

源码原生命令（从仓库根目录）：

```sh

```

安装版使用同一脚本，增加 `WFRL_FARM_LAUNCHER=evidence/camera-switch-20260917/installed_launcher.py`，输出至 `evidence/camera-switch-20260917/installed`。
