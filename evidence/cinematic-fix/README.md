# Cinematic 修复与验证

## 修复

- 随机风向采用速度历史积分。新迹线从当前来风入口产生；已有移动迹线保留出生朝向，随速度积分移动，不再整体旋转。时间回退可重复。
- 后端重建后同步应用显示模式，暂停时也不会暴露绿色代理层。
- 前端动画时钟不再截断慢帧 dt；暂停停止推进，与训练时钟分离。
- 72 条细丝/风机，四分之三为移动短迹，减少永久长线、亮度和互相交叉的扰动。旧场景中已有曲线拓扑和材质可原地升级。

## 证据

- 新 motion regression 在旧实现失败：可见移动迹线最大速度 301.44 m/s；修复后 9.70 m/s（配置风速 8 m/s，允许程序化扰动）。测试同一移动迹线顶点，不是静态流线的年龄采样点。
- live regression 在旧实现失败：重建后 Cinematic 0、绿线对象 50；修复后 Cinematic 1、绿线 0。
- clock regression 在旧实现失败：0.8 秒慢帧被裁为 0.2 秒；修复后时间完整推进，暂停不推进。
- cinematic_smoke、wake_placement_smoke：PASS。
- 前端 Python 测试：151 passed in 6.29s。
- 本机安装目录独立进程运行 motion regression：PASS。
- front.png 为实际 Cycles 渲染；random-turn.mp4 为 48 帧、每帧间隔 0.25 秒的真实 Blender 输出，覆盖 t=4～15.75 秒。

## 使用与边界

已更新 Blender 5.2 本机扩展及 dist/wfrl_blender-0.2.0.zip。需要正常重启 Blender，运行中的旧模块没有强制热替换，也没有关闭用户进程。

迎风 ±10° 和 360° 随机模式保留。默认周期仍为 8 秒：40% 保持、60% 转向。这些控制仅影响展示。

轨迹与物体的作用仍是程序化近似，不含实际表面碰撞、CFD 或多机尾流耦合。频繁、大角度换向会形成弯折的历史迹线；它是可视化，不是训练风场数据。迎风模式改变基准机头时，当前参考方向会重新定义；历史积分重点解决随机模式的连续输运。
