# blade_recon0.2 完整性、Blender 兼容性与优化检查

日期：2026-10-07。对象：当前本地 `blade_recon0.2`；本次为审查与隔离验证，算法源码未改动。

**结论：它是可以运行的研究原型，独立纹理样例能在本机 Blender 5.2.1 LTS 中显示和更新；尚未达到直接接入当前风场工作流、可靠保存重开、处理实际动态相机数据的程度。**

v0.2 的主要新增是固定重建位姿后的表面灰度纹理反投影。`recon.py` 和 `camera.py` 与当前基础版相同，`model.py` 的计算逻辑不变。项目已经添加的 `input_bundle.py`、`window_surface_fit.py` 等不在这个新目录中，所以这个交付包不是当前项目代码的完整替代品。

## 3. 应优先解决的接入与可靠性问题

### P1：查看器会清空当前文件中的所有对象和已有帧回调

`blender_view.py:47–49` 遍历 `bpy.data.objects` 删除对象；189–190清空全局 `frame_change_pre`。隔离探针证实既有标记对象和回调均被删除。在含风场、MAPPO回放或其他场景的文件中运行会破坏当前会话内容。

建议复用项目现有“叶片三维重建”独立场景机制、对象所有权标记与回调生命周期，只管理本功能创建的对象和回调。本次测试均在新进程执行，未在原风场文件执行该清空路径。

### P1：保存重开丢失动画，纹理尚未打包

原脚本只创建进程内闭包回调，没有嵌入重建数据并在载入后恢复，也没有烘焙动画；材质图片仍引用外部文件。保存并重新打开实测叶片静止。即使本机仍能找到纹理，拷贝单个 `.blend` 到别处也没有完整便携保证。

建议接入现有读取器的数据嵌入与恢复机制，或交付烘焙动画，并 pack 纹理；验收要在新进程、源路径不可用的副本环境中检查保存重开。

### P1：动态相机、真实帧号与时间戳未接入

`recon.py:395–402` 仅加载一组静态相机，422/465使用固定 `dt=1/fps` 和 `t=k*dt`；`texture.py` 同样固定相机。导出器只导出一个 `--frame` 的标定。

项目现有 long32 数据使用 `T_cv_from_model`，新 `Camera.from_dict` 要求 `T_cv_from_world`，直接读取实测抛出KeyError。仅改字段名仍不能解决机舱/塔顶运动。真实样本首帧为42、t=4.2，新管线却从索引0查掩码并计时。

建议复用 `blade_recon/input_bundle.py` 的逐帧相机、明确 frame/t 和输入检查；现有历史动态求解适配已提供每帧更新 `fitter.cams` 的范例。先冻结并核对坐标合同，再让位姿和纹理两条路径使用同一份逐帧标定。

### P1：缺帧、缺掩码和零观测可被静默接受

实测反例：

- 两路文件ID分别为 `[1,2]`、`[1,3]`，`FrameSource` 按排序后的数组索引配成 `[2,3]`，无同步错误。
- 显式指定的掩码缺失，`segment` 静默退回自动阈值；100×100图像也接受7×9掩码。
- 全空掩码时，首帧求解返回 `success=true,cost=0,psi_std=0,observed_sections=0`。无信息方向通过伪逆变成零方差，不能解释为精确估计。

建议对显式输入缺失、身份/时间/尺寸不一致做明确报错；允许先验预测时独立标记 predicted/unavailable；不可辨识参数不能报零不确定度，保存求解器success/status/optimality及有效观测数量。

证据：[recon_probe.py](recon_probe.py)、[recon_probe.json](recon_probe.json)。

## 5. 值得做的优化

1. **先完善可追溯性和质量门槛。** 保存每个选中纹素的相机、帧号、原图像素位置，以及输入标定、掩码、recon和配置摘要。当前只保存融合结果、分辨率、计数，无法按文档承诺逐纹素回查来源。alpha>0目前主要表示存在正权重样本，应与“达到可分辨质量”分开。
2. **先减少重复计算。** `residuals` 为每个相机调用 `silhouettes`，每次都重复 `rotor.forward`。同一次残差先算一次网格，再分别投影，改动范围小。
3. **纹理按有效区域计算并减少内存。** 全画幅光栅化、距离变换和大尺度GaussianBlur是值得profiling的区域；默认累加器约205.4 MiB。best融合仍维护mean分支数组，可按模式分配，再考虑ROI/分块和低频图降采样。
4. **让分辨率约束对应目标缺陷。** 目前权重偏重面积分辨率；窄裂纹需要分别判断展向和弦向分辨率，不能只看图集纹素大小。
5. **几何与纹理联合优化放在后续。** 可用稳定表面特征重投影或光度一致性改善位姿与贴图位置，但必须在动态标定、观测身份和质量门可靠后增加，并用留出相机/帧评估。当前纹理不反馈几何，不能测鼓包高度或凹坑深度。

上述性能优化尚未实现或做前后benchmark，不承诺加速倍数或精度收益。建议实施顺序为：**安全接入与保存恢复 → 动态输入和质量门 → 数值/纹理正确性修复 → 计时后提速 → 联合几何优化**。
