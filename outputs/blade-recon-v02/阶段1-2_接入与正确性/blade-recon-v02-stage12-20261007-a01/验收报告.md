## 2. 第 1 阶段：接入、输入和求解可靠性

### 2.1 场景作用域与生命周期

纹理通过现有独立“叶片三维重建”入口进入场景；清理仅作用于本模块所有对象/回调，不再删除 `bpy.data.objects` 中所有对象或清空全局 `frame_change_pre`。源码原生测试确认：原风场对象和时间轴、外来回调保留；失败导入不改变活动场景；重注册去重自身回调；注销清理自身对象、处理器、定时器与界面。

相关实现为 `blade_recon0.2/blender_view.py`、`blender_frontend/wfrl_blender/blade_recon_data.py`、`blade_recon_review.py`、`panels/blade_recon.py` 及注册入口。原生证据为 `blender-source/visibility-fixed/create.json` 和 `blender-source/legacy-visibility-fixed/result.json`。后者还覆盖旧无纹理结果、稀疏 frame 身份、缺失真值保持隐藏、失败导入事务以及旧模型字节匹配。最终 `frontend-unit-final.log` 为 23 项主机测试，22 项通过、1 项因历史源路径缺失显式跳过；不能写成全部 23 项已执行通过。

### 2.2 同一逐帧相机、RGB/掩码和真实时钟

`InputSequence` 为几何与纹理提供同一 FrameRecord：真实源 `frame`、`t`、该帧相机、RGB、掩码和源索引。bundle 模式保留动态 `T_cv_from_model` 语义，不将字段改名后继续当静态世界相机使用。静态旧视频只在每路帧数、FPS、呈现时间与原图尺寸一致时使用；帧目录按数字文件身份匹配。

显式掩码缺失、坏文件、错误尺寸，坏 RGB，跨相机帧号/时间不一致和结果/输入时间不一致均产生诊断；显式掩码失败不退回自动分割。未声明掩码时才使用自动分割，并保存极性、最低对比度和最小面积阈值。纹理使用原输入掩码，不再隐式填洞；新 recon 的逐帧相机名称、尺寸、K/T 矩阵、标准化机组配置、声明文件路径/已有 SHA-256 和分割参数必须匹配。旧结果没有新增来源声明时保持兼容，并明确记录未做这项核对。

证据：`input-recon/unittest.log` 的 16 项回归全部通过；`input-recon/regression.json`；`texture/regressions.json`。真实动态输入短检查读取源帧 42、43，时间约 4.2、4.3 秒，逐帧外参最大变化 0.00463317，访问清单只有 manifest 与两帧 RGB/掩码。对应输出为 `input-recon/dynamic-two-frame/recon.json`，纹理接入证据为 `dynamic-texture/texture.json` 和 `dynamic-texture.log`。这个两帧检查采用 0.15 求解缩放，只证明动态输入/时钟/相机接入，不构成真实 MAPPO 精度验收。

### 2.3 无观测、先验预测和不可辨识方向

输出增加 `reconstruction_status`，区分 `no_observations`、`prior_prediction`、`unidentifiable`、`prior_assisted`、`image_constrained`，保留求解器 success/status/message/optimality。`reconstruction_valid` 仅表示求解器终止成功且存在局部图像约束；每帧仍保存 `geometry_acceptance=NOT_EVALUATED`。

`observation_std` 由不含先验项的图像雅可比计算，零空间和未观测方向保存为 JSON null；`posterior_std` 单独记录包含物理/时序先验的后验结果。仅在所有图像方向均有限时提供旧 `std` 字段，避免严格旧读取器把缺失方向当零误差。有限状态允许作为先验展示，但无效或仅先验结果不产生纹理覆盖。

原“全空观测 success=true/cost=0”反例现在仍如实保留 solver success=true、status=1、cost=0，同时 image rank=0、`reconstruction_valid=false`、状态 `no_observations`、全部图像方向不确定度 null、方位角后验 null。证据见 `input-recon/regression.json`。局部雅可比满秩和求解器正常终止，均不证明全局唯一性、真实误差或现场精度。

## 4. Blender 原生 120 帧恢复证据

`blender-source/visibility-fixed/create.json` 与 `reopen.json` 均为工作区源码、Blender 5.2.1 LTS 的后台原生 PASS。检查三片 RGBA 图集 packed 后的摘要、UV 和材质节点，几何/证据颜色、逐帧相机、后退寻址、单步及纹理/证据色切换；定时器提交后重新计算寻址/单步的可见状态，避免缓存可见性延迟。

创建和新进程重开检查均记录 120 帧结果包，重点帧 1、17、18、61、120 相对保存状态前向模型的最大顶点差约 7.6e−6 m。重开时外部输入路径不可用，仍从嵌入数据恢复。`blender-source/standalone-reopen.json` 进一步确认没有执行扩展或算法查看器时，原生绝对几何与证据动画、packed 图像和材质可独立恢复；其第 61 帧模型差约 4.19e−5 m，其余列出帧约 7.6e−6 m。

上述差值衡量 Blender 保存/回放几何与输入模型状态是否一致，**不是估计几何相对真实叶片的误差**。后台原生、构建、日常安装与实际窗口分别验证，见第 1 节和第 6 节；没有窗口帧率或每帧连续绘制验收。

### 使用入口

双击 [打开纹理重建样例.command](../../../../scripts/blender/打开纹理重建样例.command)，或从实际 Git 根目录执行：

```sh
/Applications/Blender.app/Contents/MacOS/Blender \
  --python scripts/blender/open_blade_recon_review.py -- \
  --recon blade_recon0.2/out/synth_tex/recon.json \
  --texture blade_recon0.2/out/synth_tex/texture
```

该入口使用日常已安装扩展，在新进程加载已有 120 帧纹理样例。样例不是完整高分辨率重算；纹理所在面可通过视角旋转查看。自己的结果使用独立 **N → 叶片三维重建** 导入入口；显式错误纹理会诊断并保留当前场景，不静默退回无纹理。

外部算法入口与具体参数见 [阶段运行说明](../../../../blade_recon0.2/docs/阶段1、2运行与验证.md)：

```sh
python3 blade_recon0.2/run.py --check-env
python3 blade_recon0.2/run.py recon --data <显式输入目录> --out <新结果目录>
python3 blade_recon0.2/run.py texture --data <同一输入目录> --recon <新结果目录>/recon.json --out <新纹理目录>
```

bundle 掩码由 manifest 声明，不允许另一个 `--masks` 覆盖身份。静态模式可明确指定同一 `--masks`。真值只在单独 `eval_texture` 评分器读取。

两种保存交付分别保留：
