# 实际 Blender RGB 掩码补救：输入实例门槛未通过

2026-10-07。范围为原 `actual/input` 的 42、43、45、47 帧 RGB、原图尺寸和相机标定；仅写入本独立目录。它们是录制的 MAPPO／Cycles 场景观测，不是现场实测。没有修改算法、源 RGB、旧掩码、旧重建或旧纹理。

**纯 RGB 补救能大幅减少云／静态背景占据，但尚未得到可靠的完整叶片实例轮廓。最终保留为 `FAILED_INPUT_INSTANCE_GATE` 候选；没有用它启动新的重建或纹理融合。**

## 三轮实际运行

第一轮采用全局颜色和高频统计：去噪 RGB 的低饱和／亮度，灰度高通局部 RMS，另保留实际红色叶尖像素。原 RGB 的平滑云带 RMS 中位约 0.51 灰度级，叶片／塔局部约 8–9；这是一组低采样 Cycles 图像的特征，不是通用实例分类能力。它去掉部分云内部，却仍保留云边缘、地平线带和连通塔体，不能接受为纯叶片掩码。

第二轮仅使用同一相机四张 RGB，构造去噪时间中位背景，保留 RGB 变化大于阈值的材料占据，再剔除至少三帧持续占据的像素。云和大部分塔体被去掉，但持续重叠的叶根也被删掉，塔边缘残条仍存在。近景 Patch／Crack 相机持续追随表面，时间差分会选中修补／暗线变化而非完整叶片；因此其时间差分明确仅用于诊断，未作为候选实例输入。

第三轮在宽视角放宽颜色支持，使用原始 RGB 的红色叶尖条件，最后剔除过薄／过短的残余组件。云带和塔残条消失，47 帧大体保留三个运动叶片及红尖；但 42 帧右叶片仍有内部断口，47 帧右叶片边缘受地平线持续背景侵蚀，WideB 下叶片被静止细长背景／持续重叠区域截断，叶根仍被主动排除。把这些缺失作为完整二值外轮廓传入当前目标会增加伪边缘和几何偏差风险，不能包装为分割成功。

- `candidates/<camera>/comparison-<frame>.png`：原 RGB、旧掩码、第一轮和初始时间差分的四联图。旧掩码只用于 literal 对照，未参与生成新掩码。
- `candidates2`：持久背景剔除小样、持久像素图、原 RGB 轮廓叠加。
- `candidates3`：最终宽视角候选与 RGB 叠加，未形成获准求解输入包。
- `candidate-evidence.json`、`persistent-evidence.json`、`last-candidate-evidence.json`：逐帧像素数、参数和 RGB／候选 hash。
- `result.json`：最终负门槛、输出逐文件 hash、16 张原 RGB 和原掩码的历史 hash 保持断言；`source_manifest.READ_ONLY.json` 是原输入 manifest 的字节副本，SHA-256 一致。frame／t／W／H／K／T 全部原样保存，未从连续索引重编号。
- 三个分割脚本只读 RGB 路径／图像尺寸／帧身份；没有导入叶片模型，没有读取 source mesh、姿态真值、缺陷标签、重建结果或投影先验。所有四帧 RGB 都参与宽视角背景估计，此依赖明确记录，不能把它们另算为未见过的分割留出帧。
