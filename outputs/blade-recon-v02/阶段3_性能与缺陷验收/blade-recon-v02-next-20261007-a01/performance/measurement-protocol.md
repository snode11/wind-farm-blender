# 性能测量协议

本协议在新缺陷输入及修复版重建结果尚未交付时固定。正式对照使用同一 RGB/掩码 bundle、同一 `recon.json`、同一 atlas/曝光/跳帧/融合参数及同一机器。几何真值、纹理真值和缺陷标注不进入 `texture.main`。

主要性能对照（新的缺陷完整 `best` 管线与历史 32 帧读取 2 帧）先用未优化的三份模块快照运行至少 3 个新的 Python 进程，后用优化版运行至少 3 个新进程。记录每次入口总耗时、输入加载、帧视角、归一化、配准、融合、输出耗时、峰值 RSS、加载字节与输入规模；汇总给出原始值、中位数及范围。`frame_views_total` 包含 `rasterize_nested` 与 `sample_view_nested`，这些嵌套计时不相加。

执行时根据协调者的范围收敛，将最初拟议的可选路径重复性能测量收敛为功能等值验证：`mean` 与 `best --register` 各进行一次前后完整运行，只判断质量/身份是否完全一致，不依据单次耗时报告这两个可选分支的提速。

对默认 `best`、可选 `mean`、`best --register` 检查相同路径的前后输出：9 张 PNG 的像素、`texture_data.npz` 全部数组（包括 `has/res_s/res_c/wmax/nview`、NaN 位置）、逐帧 frame/t/camera/source_indices 与配准结果。若像素和数值数组逐值一致，缺陷质量指标应完全一致；最终报告仍引用独立缺陷 ROI 评分并区分未通过门槛。

稀疏读取单独测量从较大 bundle 选择少数已重建帧的场景。选择按 `recon[:max_frames]` 的原始 `frame/t` 身份，不能把纹理帧数直接作为 bundle 前 N 行。保留原 bundle 的 `source_indices`。本次未选择的声明 RGB/掩码可以不解码；当前使用的文件 hash、原 manifest hash、frame/t 与动态标定仍须核对。未知声明身份、选中坏帧或真值路径仍须拒绝。

候选改动按实测瓶颈决定，允许减少未选择输入的预载、减少当前融合模式不用的累加器、只对有效纹素执行原图 remap。不得改变几何模型、目标函数、权重、透明度或观测门槛。当前快照位于 `before/`，摘要位于 `before/source-hashes.json`。几何残差重复生成网格由另一个工作单元负责，使用独立测量与等值验证。

历史 32 帧单次探针只用于确认 eager preload 和测试测量工具，不能作为新的缺陷性能验收或提速结论。
