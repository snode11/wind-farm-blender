# Blade Recon v0.2 性能及质量守恒报告

日期：2026-10-07。本次新缺陷完整 `best` 管线的入口耗时中位数从 **23.031 s 降至 17.881 s（下降 22.36%）**。图像、纹理保存数组、有效性、分辨率证据和原帧身份完全一致。完整管线的峰值 RSS 没有得到改善证明；这与确定减少的累加器数组分配分别报告。

## 实施与来源

- `texture.py`：相机光栅结果没有某叶片像素时，直接跳过该叶片的全图集表面构造。原采样的必要条件是 `fid//F == blade`，因此被跳过分支不可能贡献权重。
- `texture.py`：`best` 不分配／计算均值的 `num/raw`，`mean` 不分配最佳视角的 `best_val/best_raw`。保留 `den` 的原始 `w**POW` 运算、`has=den>0`、全部权重、透明度、分辨率与视角数量定义；直接 `Accum(atlas)` 调用保留双模式兼容。
- `input_adapter.py`：根据实际选中的重建 `frame` 声明 eager preload 的 allowlist，保留原 bundle 的 `source_indices`。稀疏选择不等于 bundle 前 N 行；annotation 的 `frame_index` 正确重映射，原 annotation 文件及其 SHA256 不变。未选择的声明文件可以不解码，当前选中文件及原 manifest 的摘要仍核验。
- `raster.py` 未改。RGB remap 的细分耗时仅约 0.092 s，相比全图集表面构造约 11.949 s 没有足够价值，本次保留原 remap。

未改几何模型、目标函数、纹理权重、归一化、注册搜索或证据门槛。重建重复网格计算的独立优化由另一工作单元报告。

未优化模块位于 `before/`，受控优化测量版本位于 `after-source/`，均有 source-hashes.json。根审阅发现旧 legacy numeric `explicit_mask` shortcut 可绕过 bundle 未知文件身份检查；最终只允许 `source.bundle is None` 使用旧 shortcut。该一行收紧已保存 `source-final/`、`final-provenance-delta.patch` 和 `final-source-delta.json`，没有倒写已测快照。最终完整 `best` 再运行一次，只作定性等值验证，全部输出与受控优化版本完全相同；该次并发验证耗时不用于性能结论。

## 环境与规模

同一 Apple M5 Pro、18 CPU、24 GiB 内存（Mac17,8），macOS 27.0 arm64。外部 Python 3.12.14，NumPy 2.5.3、SciPy 1.18.1、OpenCV 5.0.0（18线程）。每次使用新的 Python 进程；`measure_texture.py` 调用实际 `texture.main`，记录输入加载、帧视角、采样、归一化、配准、融合、输出、峰值 RSS 和文件摘要。源 `model/recon` 在正式前后测量中的摘要一致，snapshot overlay 只替换本工作单元的三个模块，并共享同一真实 strict loader。

新的冻结输入为 `synthetic/dataset/input`：12 帧 `[2,4,6,8,11,14,17,20,23,26,29,32]`，原始时间为 frame/10；每帧 Global 816×636 与动态 Inspection 1024×768。RGB+mask 解码数据共 62,659,584 bytes。参数为 `--atlas-dr .01 --atlas-cols 768 --fusion best`，无 skip、register、曝光或帧上限；图集 6150×768，共三片叶片 14,169,600 纹素。

**读取 12 帧不等于融合 12 帧**：原重建有效性门槛只允许其中 3 帧进入 `frame_views`，实际 12 个相机×叶片视角贡献；前后均保持这一事实。其余状态不会因性能优化获得纹理证据。几何／缺陷门槛仍由原验收报告判断。
