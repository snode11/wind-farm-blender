## 3. 交付一：短片、规格和最小适配

### 3.1 首轮输出规格

| 项目 | 执行约定 |
| --- | --- |
| 相机 | 保留默认 T1/C1、C2、C3 的位置、方向及各自视场；不自动跟踪目标、不按叶片裁掉原画面 |
| 分辨率 | 首选三路原图路径，保留默认 **1920×1080**；以实际导出尺寸为准，每路单独生成 K |
| 输出帧率 | **20 fps、恒定帧率仅作为 2 s 链路试片初值**；正式帧率依据 B1 一次过境各叶段的有效帧数、跨帧位移和跟踪结果冻结，不能由可播放性认定采样足够 |
| 时间窗口 | 先做 **2 s 链路试片（20 fps 时每路 40 帧）**；在现有 117–177 s 内选择 5–10 s 候选采集窗保存过境上下文；实际几何拟合从其中一次清楚过境附近的有效帧开始 |
| 扩展原则 | 有效视角不足时按失败原因延长同一回放窗口；不预先要求全部 60 s，更不套用 GW184 的 320 s |
| 视频 | 三路独立 H.264 MP4、yuv420p，沿用现有编码器的无 B 帧、最长 1 s GOP 合同；其余实际编码参数留档，试片检查压缩后的轮廓和可匹配细节 |
| 正式算法输入 | 从交付 MP4 解码后的图像；无损源 PNG 保留为内部调试对照，不能代替正式视频结果 |
| 成像 | 首选现有三摄采集的 MATERIAL 视口材质成像、瞬时理想采样；冻结 studio light、显示变换和 PNG 输出设置 |

5–10 s 是候选采集窗，不自动成为近似刚性拟合窗，也不保证覆盖完整叶片。两秒试片先核对链路；正式重建短片再按 RGB 检查 B1 的清晰过境、各叶段画面、相邻取景关联和有效观察方向。试片未包含目标过境时，局部调整采样位置补看一次经过；不以空画面推定算法失败。检查不通过时记录具体原因，再调整窗口或成像设置，无需先完成全轨迹敏感性扫描。

既有单相机 CLI 的选项只有 **15/20/25 fps** 和 **1440p/4K**。`encode_video()` 本身、`frame_schedule()` 和旧 renderer 的帧中心函数也限制 15/20/25 fps。`validate_video()` 虽按传入帧率检查而无此白名单，整包 seal/verify 仍经 `frame_schedule()` 受限。因此需要其他帧率时，应同步适配实际使用的采样、编码和封包/校验入口，并核验 PTS、时间基和 GOP，不能只改方案数字。更高输出帧率也不增加 40 Hz 源数据的独立物理信息。若走旧 CLI，应使用其实际支持的分辨率或明确实现适配，并重算 K。

三摄采集采用视口材质环境，不使用场景灯光/world；与旧后台 EEVEE/Cycles 的场景照明、曝光积分链路不同。不得把旧单相机渲染器的 1 ms 快门或多次曝光采样声明移给本方案的瞬时采集。若最终选择后台成像，另记实际渲染器、灯光、曝光和色彩口径，所有三路采用同一约定。

### 3.2 唯一共享时间表

对冻结的 `[start_s,end_s)` 选取整数 `N=(end_s-start_s)×fps`。0 起始帧号 `n=0…N−1`，采用：

```text
video_pts_s[n] = n / fps
sim_time_s[n]  = start_s + (n + 0.5) / fps
```

`video_pts_s` 是解码播放时间；`sim_time_s` 是该图像对应的仿真状态时刻。三路共用同一个 `n → sim_time_s` 表，校准与图像在同次时间更新后读取。无丢帧替补、无端点额外帧、无把源数据重复拼成更长新工况。

现有三摄 UI 的 `sample_times` 按起点加步长并可能包含末点，不能直接替代这个中心采样表。需用小适配器把上述显式时刻交给采集流程。现有 Capture 支持 Blender `frame+subframe` 并以 `sim_time_s` 更新柔性场景，不需要把时刻舍入到 60 Hz 整数帧。后续仍须核验首帧、中间和末帧的实际状态，并保存实际采集记录；公式不替代运行记录。

本轮核对本地 T1 motion/telemetry 的 2401 个时刻，符合 `117+k/40`。若 `start_s=117`、20 fps，则中心时刻为 `117+(2n+1)/40`，恰好使用源网格奇数索引；两秒对应索引 1、3、…、79。一般从源索引 `k0` 开始时为 `k0+2n+1`。改变起点或帧率后重新检查，不能一概称中心采样必经插值，也不能因命中源网格就认定图像采样充足。

MP4 解码按呈现顺序和实际 PTS 对应时间表，不按编码包顺序、DTS 或网络到达时刻猜测。若选用不同采样约定，应建立新的运行版本并完整记录，不让编码和重建各自猜一套起点。

### 3.4 交付一验收

- 三份 MP4 完整解码、无损坏帧，实际帧数均为 N；尺寸、帧率、PTS 与共享时间表一致。
- 在首/中/末和目标过境帧检查三路状态同步，校准来自同刻相机；记录异常和无效帧，不补成正常值。
- 视频是 C1/C2/C3 各自完整画面，叶片轮廓/细节在压缩后仍可用，无 UI、检测框、错误裁切或调试几何覆盖。
- 数据说明写明目标身份、源片段、成像和插值假设、各相机取景、实际可用窗口和遮挡情况。

ffprobe 的 `-show_frames`、`-show_streams`、`-count_frames` 可用于帧/流检查；仍需运行完整解码检查。[官方文档](https://ffmpeg.org/ffprobe.html) 提供这些接口。未通过图像条件时交付状态记为 `VIDEO_VALID_RECONSTRUCTION_INPUT_INSUFFICIENT` 等明确状态，不能因文件可播放就宣布重建输入有效。

试片及第一次清楚过境后，只统计直接影响下步选择的量：按相机/叶段记录有效帧数、跨帧像素位移、可靠匹配数量与留存率，以及同一区域的有效观察方向差异。几何拟合后再报告去除声明刚体运动的图像残差；采集/优化过程中记录耗时及峰值内存。不可见点、跟踪器外推点和重复近似视角不计作新增有效观测。这些量目前未测，不要求试片前完成。

## 4. 算法输入和评分真值的简洁边界

算法从交付包独立运行，只读 MP4 解码图像和下列声明字段。字段白名单是待实现的新交接格式，不表示现有导出器已有同名文件。

| 文件 | 允许内容 |
| --- | --- |
| `dataset.json` | 目标 `T1/B1`、机型、米/秒/像素单位、视频和白名单文件内容签名、输出参考状态、允许输入政策 |
| `frame_map.csv` | `camera_id,frame_id,video_pts_s,sim_time_s,valid`；异常原因独立记录；必要时记录实际解码 PTS 与采集记录的对应 |
| `camera_calibration.jsonl` | 对应帧的 width/height、K、`T_camera_cv_from_world`、相机坐标和像素中心约定；理想针孔/无畸变等假设 |
| `motion_observations.csv`（可选） | 明确允许的方位角、B1 桨距和叶根刚体位姿等运行观测；每项记录单位、来源、时间及是否为仿真理想观测 |
| `template/`（可选） | 独立近似模板及来源、参数和签名；不能含测试场景的精确参考或逐帧表面 |

相机标定与已声明的刚体运行观测可以辅助重建，不要求首轮同时完成自标定和全部运动估计。[COLMAP 的已知相机姿态重建流程](https://colmap.github.io/faq.html#reconstruct-sparse-dense-model-from-known-camera-poses)说明这是常见的输入方式；这不意味着把动态 NREL 场景直接交给静态重建工具就能成立。

现有视频数据包不得直接整包交接：`frames.csv` 含 `clearance_b1_m` 至 B3 等净空字段，`frame_geometry.npz` 含 `tip_reference_world_m`、`nearest_tower_world_m`；完整源回放还包含精确几何与变形。`data.json` 的运动观测与测量真值混存，`data_manifest.json` 也包含净空定义和统计，不能作为整份算法输入。精确表面、结构截面真值、真值分割/对应和隐藏表面标签留在 `evaluation-only/` 或生成端，普通重建进程不能读。采用白名单复制并核验键名，未知新增字段不自动放行。

相机/刚体运动的精确信息应注明为“仿真理想标定/运行观测”。精确柔性变形若用于单独诊断，结果记为 `GT_DEFORMATION_ASSISTED`，不计作本轮正式的普通算法重建结果。评分真值仅参与结果评分；不依据测试真值反复选择窗口、优化参数或初始化。

## 5. 交付二：一片叶片的三维恢复

### 5.1 输出身份、尺度和参考时刻

正式结果为 **T1/B1 在声明时刻 `t_ref` 的受载三维表面**，采用米及声明的叶根局部坐标。`t_ref` 从 B1 有良好观测的实际解码帧中选择，依据 RGB 清晰度、可见叶段和已声明的运动信息；不机械取视频中间帧，也不使用评分真值挑时刻。将参考帧、绝对 `sim_time_s`、选择依据及拟合/留出帧清单冻结后再优化。

输出不是未受载外形，也不是完整时变表面序列。若使用相对形变模型，以 `u(t_ref)=0` 或等价锚定约束把形状固定在这一参考时刻；不要任由“参考形状＋形变偏移”相互抵消而改变输出含义。

### 5.2 首个重建方法和处理顺序

沿用原 v1.1 B，将首个方法具体化为 **低维叶片表面＋可微轮廓/可靠对应约束优化**。用少量展向控制站表示中心线、弦长、主体厚度和截面方向，模板独立于本测试精确网格，记录来源和参数。首轮仅优化这一片叶片的形状参数，不从头训练分割或重建基础模型。

```text
C1/C2/C3.mp4 完整解码并记录来源
→ 按实际 PTS 和 frame_map 对齐
→ 从 RGB 分割、跨帧关联 T1/B1，记录人工提示与遮挡不确定区
→ 使用标定及声明的运行观测处理相机/叶轮刚体运动
→ 在一次清楚过境的有效拟合帧上分阶段优化低维表面
→ 导出 T1_B1.ply、图像证据和缺口标签
→ 独立评分，与初始模板及无图像正则化对照比较
```

**分割与关联。** 允许操作者在实际 MP4 的 RGB 帧上点击/框选 B1，再使用预训练分割器传播并修正；[SAM 2 官方接口](https://github.com/facebookresearch/sam2)可作为候选。保存提示帧、坐标、修正及次数，结果标为半自动验证。重新入镜后结合 RGB 和声明的相位/时间关联身份；不读取 Blender 真值掩膜。点跟踪和跨视图匹配只用于实际可见且通过一致性检查的点，不把被遮挡点的预测坐标当测量证据，也不要求首轮同时部署多个匹配模型。

**遮挡下的轮廓损失。** 每帧区分以下三类；分类来自 RGB/允许输入并留档，不能用真值深度生成。

| 像素类别 | 约束方式 |
| --- | --- |
| F：确定可见的 B1 前景 | 对候选软轮廓施加前景约束 |
| B：确认无遮挡、且没有 B1 的背景 | 对候选软轮廓施加背景约束 |
| U：机舱/其他叶片等遮挡，或判断不确定的区域 | 不施加“这里必须没有叶片”的负约束；画幅外也无此约束 |

F、B 的损失分别按有效像素数归一化，缺少某类时略过其项并记录；U 不计入二值轮廓比较。轮廓边界项只使用确认的真实叶片轮廓，排除裁剪/画幅边界和 F–U 遮挡边界。不能把完整单叶片投影与可见掩膜直接做全图差值或 IoU，从而逼模型缩短被挡住的叶根。被遮挡部分继续标记先验依赖或未知，这一规则不要求重建整个场景。

**参数与求解。** 核对米制坐标后固定已声明的标定和刚体位姿，先拟合中心线与弦长，再释放有图像证据的扭转/厚度自由度；不同时释放全部顶点、全局缩放和逐帧自由位姿来吸收误差。拟采用可微光栅化及 Adam 优化形状参数；学习率、阶段顺序、迭代预算和停止规则在开发帧上固定并留档。正则限制相对初始边长/参数的变化、展向平滑和截面合理性，保持正弦长、正主体厚度并防止翻转/穿插；前后缘可正常闭合，不能照抄令全部边长趋零的损失。[PyTorch3D 轮廓拟合教程](https://pytorch3d.org/tutorials/fit_textured_mesh)可作实现入口，需适配本项目 CV 相机和低维参数，不能照搬其自由顶点与超参。

图像项使用上述遮挡掩膜及可靠对应点的稳健重投影误差；按相机、分辨率和有效观测分别报告残差，不能把相同像素误差解释为相同空间误差。对应点稀少时保留轮廓基线，但厚度/背面等仍依赖先验的区域必须注明。

正式视频保留真实 NREL 柔性回放。**采集窗与拟合窗单独登记**：5–10 s 可保存目标经过和上下文，首个拟合窗只纳入一次清楚过境附近的有效帧，其他帧用于身份关联或留出检查。检验近似刚性的图像残差及时间一致性后，再逐步纳入更远时刻；若有系统偏差，先定位标定、时间、关联或形变原因，需要时才增加低维补偿并保留 `u(t_ref)=0`。不能把整段视频默认视为静态表面，或悄悄换成刚性动画。

不必等近似模型完美才导出第一个结果。保留第一次模型、输入窗口和失败区域，根据具体问题改进；每次变化建立新结果版本。选择/调参使用开发帧，另保留未参与拟合的帧检查重投影，不用测试真值回选最好结果。

### 5.3 最少几何评分

评分端需补一个很小的表面导出接口：在同一视频场景、同一 `t_ref` 读取 **T1/B1 的实际 evaluated mesh**，保存单位、对象变换及表面范围。当前 `frame_geometry.npz` 只有叶尖/塔壁点和姿态等数据，没有整片叶片网格；原 solver 截面表面也不自动等于视频中 SourceLoft 生成的实际表面。不能拿净空侧车或截面点代替本次图像几何的评分真值。

真值与重建必须是同一 T1/B1、同一 `t_ref`、同一表面范围和坐标。输出物理尺度的结果不得通过评分端自由缩放来掩盖尺寸误差；若仅为坐标校核进行额外刚体配准，应同时报告配准前后值和变换。空模型或无法同态比较时距离记 `null` 并说明原因，不填零。

| 评价项 | 首轮必须报告 |
| --- | --- |
| 双向表面距离 | 重建→真值、真值→重建分别按各自源表面积加权，报告均值和 P95；单位 m，可另显示 mm |
| 分区和缺失 | 至少叶根/中段/叶尖分区；报告两侧/边缘的恢复、缺失及先验补全部位和有效范围 |
| 图像带来的改善 | 用同一坐标、范围和评分方法比较初始模板、无图像正则化结果及视频优化模型，列出改善与退化区域 |
| 少量固定截面 | 在评分前固定几个展向位置，比较弦长、主体厚度和截面翻转/穿插情况，发现整体距离掩盖的局部压扁；不展开缺陷计量 |
| 图像证据 | 网格区域与来源相机/帧的对应；分别标出图像约束、仅外观证据、先验补全、未知/缺失 |

真值→重建统计以预定义叶片表面为分母，不能只取成功区域。最近边界的有限距离不表示缺失区域已恢复；缺失面积和位置单独报告。网格闭合不证明全部表面被视频观测。第一次评分不要求先完成全面敏感性或毫米级工程门槛研究。

无图像对照从同一个未作图像优化的初始模板出发，采用相同参数化、约束、阶段释放顺序、正则权重、优化器和预算，**只把轮廓、对应点等全部图像损失权重置零**；共同标定、运行观测和参考状态保留。因此结论是这些辅助输入条件下的图像贡献。无图像结果与初始模板相同也如实报告，不为制造差异改变正则。三组仅在完成后由独立真值评分，不用真值调整初始模板或权重。

### 5.4 两种验收结论分别给出

**流程跑通**：三路有效视频已交付，正式算法确实读取 MP4 解码帧，完成目标关联和图像优化，输出可独立查看的单叶片网格、输入记录和独立评分。得到部分表面时标为 `PIPELINE_COMPLETE_PARTIAL_GEOMETRY`，同时给出缺口。

**算法几何有效**：视频优化相对初始模板和无图像正则化结果均提供实际几何改善证据，同时报告均值/P95、截面、分区退化及覆盖，并保留复现条件。若仅优于初始模板而不优于无图像对照，写“流程已跑通，视频的额外几何贡献尚未证实”。结论限于当前片段和辅助输入；工程允许误差与完整覆盖目标仍待后续约定。

## 6. 实施清单、拟目录与失败处理

以下均为待执行任务；本轮不创建下列实验目录或填入通过结果。

**存储与缓存约定：** 原始 PNG 原则上只保留一套，编码适配不无条件复制全部源帧；正式重建仍使用 MP4 解码图像。解码图像与特征优先按需读取或仅缓存关键帧，不将全视频浮点张量和全部中间特征持久化。保留初始模型、无图像对照、最终模型及少量必要检查点，不逐迭代保存整套高分辨率图像。两秒试片后统计各目录实际字节数，重新估算正式短片与缓存预算，再扩大运行。

1080p 成片保留，计算采用分段/流式解码、关键帧和小批次，缓存必要特征而非把整段浮点视频放入 GPU。优化可从 480×270 到 960×540，再以原分辨率核查；这些是起点建议，须由小运行的时间、峰值主存/显存决定。使用半像素中心缩放时 `fx'=sx·fx`、`cx'=sx·(cx+0.5)−0.5`，y 同理，并核验实际 resize 的像素映射；不能只缩图而沿用原 K。

在开始优化前做一次小规模导入、投影、可微渲染和反向传播检查，确认设备/库组合及内存；它不阻塞视频链路试片。PyTorch3D 是拟验证的实现入口，Mac 上可采集 Blender 图像不代表优化后端已可用。[nvdiffrast](https://nvlabs.github.io/nvdiffrast/)的 CUDA 依赖也不能默认在同一 Mac 环境满足；无需为首轮同时安装多套渲染器。

| 顺序 | 任务 | 可观察的完成条件 |
| --- | --- | --- |
| 1 | 锁定实际 NREL 运行源和三摄配置 | 记录版本、模块路径、必要依赖/回放/布局签名；身份与同刻投影小检查正确 |
| 2 | 接共享采样表、三摄采集及每路编码适配 | 中心时间表、PNG/元数据和编码帧逐项对应；仅允许字段进入算法输入 |
